# A first checked-method causal-use assay

Prospective design only, 7 September 2026. No implementation, task generation,
experiment, restart or new qualification was executed for this design.
Machine-readable details: [corrected contract](2026-09-07-unary-method-contract.json).

## Decision and exact missing seam

Implement one acquired **certificate rule**: typed premise/conclusion patterns plus
an executable, data-only recipe rebinding an existing witness-cover certificate.
Learn its particular pattern from checked mathematical episodes. The rule miner,
grammar, predicate mapping, certificate semantics and recipe interpreter are supplied.
This is ordinary learned inference-rule reuse; it is not a new theorem prover.

The missing seam is `checked episode → generalized checked rule data → durable KSO
admission → fresh-process retrieval/matching → actual certificate construction`.
Expose consistency preparation separately from query completion in the unary parent.
The shared parent must reuse compiled masks, the universal allowed-region aggregate
and existential obligations across query branches; do not retain avoidable rescans
as a weak baseline. Do not call complete `solve` before the learned route and then
claim that route solved the task. No second logic, FLT build or general architecture is required.

## Smallest learnable content and soundness

Training supplies set-notation unary ASTs and actual exact-parent results. First
independently verify every result. From a query-polarity unsat certificate whose
existential obligation is the negation of a universal conclusion, enumerate proper
2–3-premise subcovers of its universal support. No existential fact becomes universal.
Record every attempted subset, duplicate, invalid schema and rejected candidate.

Replace predicate leaves by typed Boolean-predicate parameters using exhaustive
alpha canonicalization. Preserve Boolean operators, quantifier polarity and repeated
parameter identity. Keep a rule only if it has at least two different **semantic**
training-task supports after alpha-normalization; renamings and copied traces count once.
A rule may not be a stored training answer or the complete training context.

Independently validate the generalized universal implication on all Boolean
assignments to its at most three parameters. Preserve the checked coverage table.
This pointwise universal proof justifies substituting well-formed Boolean expressions;
finite examples or two supports alone do not justify generalization. Reject unsafe
witness merging, missing side conditions and anything outside this universal-rule arm.
No task IDs, predicate names, raw Python, imports or callbacks occur in rule dispatch.

Recipe semantics are fixed: match signed statement patterns, bind parameters,
map the validated cover to actual premise indices, and construct the unsat branch.
Check premise consistency first. The base model serves the other query branch only
when the full independent result verifier validates it. Unknown, inapplicable or
inconsistent cases use the unchanged exact fallback/consistency outcome, with costs.

## Frozen workload and equally adaptive comparison

Use four deterministic seed episodes; each has 32 mathematical training tasks,
16 development tasks and 32 fresh controlled-language tasks. This is a bounded
apparatus sample, not a powered claim about a population or wall-time superiority.
All use exactly three predicates. Training has 2–3 atomic-premise contexts;
development/final use 4–6-premise contexts and a Boolean group. Query kinds rotate
through every/no/some/not-every without selecting by semantic outcome.

Freeze generator, seed derivation and finite draw bound before any outcomes. Split
on both alpha-normalized syntax and an independently computed finite-model semantic
fingerprint (all255 nonempty worlds over three predicates, minimizing over six
renamings). Include premise-order equivalence. Keep the complete draw/rejection map.
The fingerprint stays evaluator-only. Do not filter by learned applicability or answer.
No fitting on final tasks; an unfilled registered slot or failed task remains visible.

Each final AST has paired direct-formal and canonical-text presentations. Every arm
gets the same grammar, lexical mapping, facts, tasks, exact checker and initial caches.
Fresh labels are a surface control; the main split also differs semantically and in
composition/context. These pairs measure presentation cost, not two independent tasks.

Compare four arms: exact cached parent; conventional adaptive rule learner with a
plain indexed data store; OCM with those same learned rules enabled; OCM with the same
stored data but executable rule use disabled. The adaptive parent runs the identical
miner, schema validation, development selection, persistence, cold restore and revision.
Its simpler store is an honest conventional advantage, not omitted work. All arms
retain identical mathematical information. Never charge only OCM for shared checking.

Select at most eight rules by a frozen development criterion; preserve all candidates
and development failures. Give the conventional parent identical candidates/resources.
No-method and no-development-benefit results are valid outcomes, never seed-retry prompts.

## Actual persistence, causal use and revision

Acquire/admit/persist in process A; reap it. Process B starts from the frozen Python
executable with fresh PID, empty in-memory caches and only sealed data/source inputs.
Replay the actual OCM ledger and explicitly bind only the registered generic backend
and verifier. Reloaded Python callbacks or code-bearing method data are forbidden.
The conventional parent also cold-reloads its checksummed method/data journal.

Route current task atoms and live rule objects through actual `OCMRuntime.solve`.
Record selected IDs, lookup probes, postings/candidates examined, bindings attempted,
match outcomes, recipe steps, actual branch replaced and verifier outcome. A listed
method ID or a correct fallback answer is not use. No hidden full solve before matching.
The verifier PASS authenticates semantics, not telemetry; execution records supply that.

Use matched isolated ledger copies for enabled/disabled arms. The latter retains
all rules and mathematical content but cannot invoke them. A data-only rule mutation
must refuse; removing the chosen applicability premise must stop that match. Restore
the premise and require fresh matching/checking, not automatic answer resurrection.
Register these interventional streams before observing final outcomes.

Keep correctness, discovery and utility warrants separate. Independent schema proof
supports rule correctness; training receipts establish acquisition provenance;
development observations justify selection utility. Revoking a discovery/utility
record must not pretend that a separately proved rule became mathematically false.
Revoking its checker/semantic-contract assumption disables reuse; reinstatement
restores eligibility only. Test both routes and retain independent support when valid.
Do not inherit the polynomial parent's combined warrant as unary correctness authority.

## Costs, decisions and engineering boundary

Count full parse/validation/key construction, compile/consistency, proposal mining,
schema verification, admission, serialization/fsync, restore, index build/probes,
matching, recipe expansion, fallback, independent verification, revision and storage.
Keep every failure and all branches. Record outer wall and waited-child CPU, raw
processes and storage growth; nested spans are attribution, never summed twice.
Logical counters alone exclude hashing/allocation and cannot establish lifetime savings.
Report cold acquisition+use totals at the fixed horizon and any observed break-even;
never amortize over an invented future workload or silently subtract setup costs.

Primary apparatus success requires checked data admission/restart, actual acquired
rule use on at least two fresh semantic tasks, and a registered knockout that removes
those invocations while all answers remain independently checked. Report economic
benefit separately. If the equally adaptive parent matches the effect, record
`PARENT_SUFFICIENT`; causal reuse may still be a useful apparatus result.

Grammar/meaning mappings are shared and authored. The claim is **limited compositional
reuse through controlled-language presentation**, not learned grammar, broad language
understanding, empirical premise truth, FLT progress or a novelty result.

Qualify the complete actual launch/import/operator/data closure before execution:
CPU only, no neural dependencies, model calls, network or code-bearing restored data.
Existing OCM callbacks and a four-module scan do not establish whole-host isolation.
Unknown closure, unavailable checker or interrupted work returns CANNOT_CHECK; never
convert an unexecuted row into a semantic result. No resource/corpus clock is changed.

Implementation belongs in new `ocm-unary-learning` worktree, not the released unary
checkout. A small rule contract/miner, matcher, checked KSO store and episode entry
plus the parent's prepare/complete seam suffice; names/API are proposed in CONTRACT.

Tranche clarification: compute semantic support identity only from permitted training
inputs; evaluator development/final fingerprints remain withheld. A registered
used-support removal invalidates that exact binding, while valid alternate matches
remain permitted. Original external proposal bytes are preserved as history.

First-tranche normalization clarification: every acquired premise must be essential under
the independent schema checker. Deleting each premise must admit a counterassignment;
tautologies, one-premise primitives and padded composites do not count as methods.
The first-tranche API is specified separately in research/math-language-learning-v1/CONTRACT.md.
