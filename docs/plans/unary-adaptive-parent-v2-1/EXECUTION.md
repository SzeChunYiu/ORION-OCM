# Prospective execution, interventions and analysis

## Registration and scheduling

No scientific task generation until a final seal binds generator, selection, adapters,
analysis, all actual source/import/operator/data/binary inputs, and qualified containment.
Use the resolved Python3.11.14 binary and explicit hash profile with -I -S -B;
no packages from site-packages, restored code, neural components or outbound network.
The scope is the actual registered process tree, not an unsupported whole-host claim.

One unused run ID; a durable STARTED record precedes the first generated draw.
The 1,200-second monotonic scientific dispatch deadline includes generation, deduplication,
all four episodes, physical acquisition runs, every phase, revision, validation,
and write/fsync before dispatch closes. On expiry, dispatch stops and mandatory
termination/reaping/retention follows; measure and charge its actual overrun separately.
Do not claim cleanup completed within 1,200 seconds without such an observation.
Source/enforcement engineering qualification
occurs before STARTED and is reported separately; it cannot contain generated study rows.
Use one allowed CPU (lowest ID at start), one computational thread, and a 1-GiB
aggregate memory limit for the registered process group including coordinator/children.
Qualify actual enforcement first. If unavailable, do not launch an unbounded substitute.
Deadline or memory failure stops descendants, waits/reaps, records reached work and
unreached slots. Never restart the same study clock or silently resume a partial episode.
FAILURES.md fixes zero retries and exact continuation by phase; it is normative.

Episodes execute 0..3. Generate train/development/final partitions in that order,
retaining evaluator keys outside learner inputs. Complete generation of one episode
before its acquisition. Any unfilled partition prevents that episode's scientific solve
phases; later episodes may proceed only within the original deadline, retaining failures.
Final answers/reference results are not precomputed for training or selection.

Arms in base order: EXACT_PARENT, ADAPTIVE_PARENT, OCM_ENABLED, OCM_KNOCKOUT.
For each episode rotate this list left by episode index for each solve phase.
Arm A acquisition order is conventional then OCM for even episodes, reverse for odd.
Each A physically solves/checks training, mines, evaluates development, selects, persists
and exits. Assert identical candidate/ranking/library identities; retain both actual costs.
OCM enabled/knockout start from separate byte-identical copies of the same sealed A
store. Copy work/bytes belong to experimental setup, not invented independent acquisition.
Exact parent gets the same permissible input information without being forced to learn;
it need not pay an algorithmic acquisition cost it did not incur.

B is one new process per arm, empty caches, sealed library/data, fixed callback rebind.
Row order 0..31. Formal then text if (episode+row)%2==0, reverse otherwise.
Both presentations use identical renamed task bytes after text parsing. Maintain the
SELECTION.md cache policy for the entire B process. Persist actual reached records,
then exit/reap. A method-list/status inspection cannot stand in for a recipe invocation.
Arm-local B states and first-use bindings are retained before constructing interventions.

## Task-support interventions

C is a fresh process per arm starting from its A snapshot and empty caches.
Its formal-only stream uses every original final row, in row order; always preserve
original premise indices and a mapping to derived positions. For each row execute:
1. Remove its lowest original index whose kind is every/no; then restore exact original AST.
2. Remove the lowest index in the actual OCM_ENABLED B formal recipe's selected cover;
   then restore exact original AST. The reference is fixed, even if another arm's cover differs.
Both changed ASTs are shared by all arms. If no applicable premise/use exists, record
NOT_APPLICABLE for that removal and still execute the original restoration call.
Keep duplicate variants when the two removals choose the same premise.
After removal recompute the exact-used predicate registry from remaining premises AND
query, sort it, validate, and freshly prepare; never manufacture a metadata-only refusal.
Do not carry an old binding or certificate to the changed task. Alternative live matches
are permitted. Restorations require fresh matching/checking, not answer resurrection.

The reference method/binding must be present in an accepted full result with an actual
recipe event. Missing/failed B observations yield INTERVENTION_REFERENCE_UNAVAILABLE,
not NOT_APPLICABLE or replacement rows. C failure does not erase its base B row.

## Evidence-role interventions and restart

For each episode use the lowest original final row with actual checked OCM formal use
as one fixed role-control task. If none exists, retain all role slots as NO_USE_REFERENCE.
For each role, start a separate copy of the original A state, never chain role withdrawals.
Roles/order: schema_environment, discovery, utility. Change the reference method's
associated record (schema_environment is shared, so its actual broader cone is allowed).
Persist the withdrawal and terminate the mutation process; a fresh process solves the
same task with the changed state. Then reinstate that record, persist/terminate, and
another fresh process performs new matching and answer checking. Record actual PIDs,
state heads, eligibility/correctness transitions, use events and full costs.

schema_environment withdrawal disables schema-backed recipes while the independent
answer checker remains available for exact fallback. Discovery withdrawal preserves
independently proved correctness and utility eligibility. Utility withdrawal preserves
correctness but disables the affected selection eligibility; alternate selected methods
may still execute. Reinstatement never auto-promotes a cached answer.
Adaptive parent and OCM receive matching role operations/tasks. Knockout remains
disabled throughout; exact parent has no learned-role record and reports NOT_APPLICABLE
for that mutation while solving the same task under its unchanged semantic checker.
Malformed rule/cover/version and answer-environment controls belong to authored
qualification; do not secretly inject extra scientific rows under those names.

## Retention, costs and terminal precedence

Every process records command/profile/source identities, PID, exit/reap, input/output
digests, start/end, own and waited-child CPU, reached stages and retained failures.
Each solve records preparation, index build/probes/candidates, matching, actual recipe
and branch, fallback, full independent verification, durable write, and final outcome.
Count source hashing, input binding/validation, canonicalization, acquisition rejects,
schema proofs, development, copy, restore, indexing, parse, revision and storage bytes.
Scope timing before/after persisted journal spans explicitly; use encompassing totals.
Nested spans explain totals and must not be added twice. Missing measurements stay
UNAVAILABLE; a logical-work improvement cannot establish lower total cost.

Per episode terminal precedence: SEMANTIC_CONTROL_FAILED for any invalid accepted
answer or violated soundness/restart/withdrawal control; else CANNOT_CHECK for any
required unavailable/incomplete slot; else NO_METHOD_ACQUIRED for empty mined pool;
else NO_DEVELOPMENT_BENEFIT for empty selected library; else NO_CAUSAL_USE unless
one same acquired rule actually constructs accepted results on at least TWO distinct
original final base rows with distinct semantic keys, with knockout invocation zero;
else CHECKED_CAUSAL_REUSE_APPARATUS. Formal/text and interventions never increase
that two-row count. UNKNOWN/INCONSISTENT accepted payloads are valid semantics.
No-use-reference role slots are expected structural N/A under no-use/no-method
terminals, not an environmental CANNOT_CHECK; actual missing observations are unavailable.

Programme success requires all four complete episodes pass the apparatus gate.
Otherwise report every episode terminal and the strongest applicable non-success
precedence above, plus counts; never turn one successful seed into overall success.
Report paired outcomes/costs per original row and per episode, plus sums across the
four episodes; no IID significance claim, post-hoc subgroup win, or seed replacement.

Primary economic table includes actual A costs, B64 solves and required C/role work
per episode/arm, with experimental shared generation/copy/orchestration shown once in
the overall physical total and allocated equally to comparative arm views where shared.
The knockout amortization view reuses the same logical A cost but is explicitly a
counterfactual cost allocation; the physical experiment paid that OCM acquisition once.
Also show A+B cumulative cost at the fixed 64-presentation service horizon, without
charging C/role work to fictitious future queries. Report observed break-even only if
actually crossed; otherwise NOT_REACHED_WITHIN_REGISTERED_HORIZON. Missing cost

If the equally adaptive parent reproduces checked reuse, report PARENT_SUFFICIENT
for that mechanism even if OCM also passes. Economic differences remain their own
observations. No apparatus verdict entails novelty, general scalability, broad language,
