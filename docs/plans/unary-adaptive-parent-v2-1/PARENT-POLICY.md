# Conventional matched adapter: frozen policy

Use one ordinary checked rule store backed by the existing generic LedgerStore,
canonical content-addressed immutable payload files, an explicit dependency-state map,
conclusion-kind postings and direct dispatch. Do not emulate KSO/navigation/operators,
general warrant antichains, or a second ledger in order to burden the conventional arm.
Actual source implementation and serialization versions must be sealed before the assay.

## Persisted content and admission

Persist exact source/routing/selection-contract identities, checked inner rules,
schema certificates, training discovery and real development receipts, selected
membership and separate semantics/schema_environment/answer_environment roles.
Discovery and utility refer to those actual receipts; no authored-selected alias.
Restore requires existing valid initialization, never auto-creates missing history.

Use one journal admission intent for the complete selected batch before durable payload
writes, then one completion binding that intent and all payload hashes. Each payload
is written create-only/atomic and fsynced; parent-directory durability is included.
Existing equal content may be reused after byte/hash validation. No mutable payload
overwrite. A pending admission/use is an explicit cold-restore refusal. Unreferenced
owned payload files are reported/refused, never silently promoted to admitted rules.
An empty selected batch is valid and recorded; no method is invented to fill it.
These are conventional one-log WAL semantics, not cross-ledger KSO atomicity.

Cold restore reads/validates the complete bounded journal chain and CAS head, all
referenced immutable bodies, exact schemas/hashes, selected membership, independent
schema proofs and dependency roles. Validate historical use records and separate
their historical checker state from current eligibility. No mining, selection or
hidden task solve occurs on restore; all replay/revalidation cost is measured.

## Public operation and cache boundaries

At restore and at entry to acquire, solve, revise and persist, recompute/check the
declared source identity. Source checking is once per public operation, not once per
candidate; retain its actual cost. Observe source closure again at process exit.
The process owns immutable detached decoded payloads. Before a public operation,
validate current journal head and hashes of all referenced on-disk payloads against
the restored/admitted identities. A changed head requires explicit replay or refusal;
do not apply a stale in-memory state. Matching never trusts unvalidated replacement bytes.
Successful durable appends update the expected head; CAS failures retain intent/refusal.

USE_PREPARE binds the exact request/library/source/dependency revision before lookup,
then USE or USE_REFUSED durably records actual reached work and checker/result identity.
On partial failure, retain observed work and label unavailable counters explicitly.
Data cannot select a callback/import/entrypoint; the fixed direct implementation is
bound by the launcher and compared with the generic OCM dispatcher computation.

Cache checked immutable decoded rule bodies and pure posting contents by library
identity plus source/routing/dependency revision. Use-log growth alone does not change
eligibility or rebuild postings. Any role revision invalidates the corresponding
eligibility/posting cache; rebuilding and validation are charged. No final-answer cache.
Both adaptive arms use this posting-content and service-engine cache policy, with
their own current-state checks. Extra OCM custody work remains visible, not copied
into the conventional path to manufacture comparable latency.

## Fixed conjunctive revision semantics

Correctness is the checked schema certificate under live semantics and
schema_environment. Checked answers also require live semantics and
answer_environment. Selected execution additionally requires live utility evidence.
Discovery is attribution only. UNKNOWN is never LIVE. Record each withdrawal and
reinstatement with role/record identity and monotonically advancing revision.
No general Boolean warrant algebra is required for this fixed conjunction fragment.
Reinstatement revalidates the relevant proof/selection bindings and restores eligibility;
only a subsequent fresh recipe/match/result check can produce a new accepted answer.
Apply identical role effects in OCM and the parent; permit legitimate alternate rules.

This fixes a strong equally adaptive parent within the registered fragment. It is
not a claim to have surveyed or outperformed every conventional prover/database.
Any implementation change to this policy after outcomes needs a new registered comparison.
