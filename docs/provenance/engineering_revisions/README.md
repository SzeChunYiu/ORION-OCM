# Current engineering receipts — start here

Owner: #72 / #38 / #49. Classification: INFRASTRUCTURE.
This is the generic successor to V4 current-engineering selection. It establishes no scientific claim.

[Executed result](EXECUTED_V1.md) → [verification record](EXECUTED_VERIFICATION_V1.json) → immutable raw runs.

## Contract

Every current source state is identified by the SHA256 of its exact source inventory.
The inventory is unchanged from V4: all src files/resources, Python files under tests and tools,
and pyproject.toml. Generated bytecode and the specifically permitted editable-install metadata
remain excluded. Research prototypes and workflow files are outside this engineering inventory.

A new run executes the fixed focused and full pytest gate recipes inherited from the pinned V4
config, with only the JUnit output paths redirected into the new run directory.
Passing engineering gates neither reexecute protected studies nor promote historical conclusions.
Each run records exact commands, exit codes, JUnit and log hashes, source bytes, environment and
measured execution costs. The final source inventory must equal the initial inventory.
All required tests must pass, with no skipped, failed or errored cases.

Runs live under runs/<source-inventory-digest>/<unique-run-id>/ and are created exclusively.
A small source-only ZIP under sources/<source-inventory-digest>.zip is shared by runs of the same
source. It never includes docs, results or nested archives. Earlier run and source bytes stay intact.
CURRENT_ENGINEERING.json is the only replaceable selection pointer. Selection verifies the run,
all bindings and all named test gates first; pointer replacement is atomic.
A source change refuses the selected receipt until another real run succeeds. There is no no-run
rehash option and no fallback to an earlier scientific or engineering terminal.

All twelve milestone wrappers verify this single shared engineering run. They no longer create
or overwrite V4 successors. They accept --verify only. The separately named protected-study
wrappers remain independent; this protocol does not grant authority to run or rewrite them.

## Immutable predecessor custody

Git commit/tree/blob proofs bind them to that exact baseline. Existing V4 parent archive checks,
gate-replay validation and successor dependency checks are reused without historical recipe execution.
Every existing V4 provenance artifact remains byte-bound. V1–V3 history continues through the
existing V4 parent snapshots and their original verifier.

The protected V5 receipt and its bound non-source records also remain byte-bound; its original
source bytes are in the source-only predecessor archive. Verification checks custody only.
Current scientific promotion is NOT_ESTABLISHED, protected reevaluation is NOT_RUN, and legacy
recipe execution is NOT_EXECUTED. A historical label inside a frozen record does not become a
current claim. No M12 protected evaluator is invoked by the recorder.

## Operate on the compute laptop

Use an environment satisfying pyproject.toml and pytest, with its Python executable selected:

    PYTHONPATH=src /path/to/python tools/record_engineering_revision.py
    PYTHONPATH=src /path/to/python tools/m1_receipt.py --verify
    PYTHONPATH=src /path/to/python tools/m10_receipt.py --verify

The recorder selects the same Python executable for subprocesses and binds runtime imports to
this checkout's src directory. It removes ambient PYTEST_ADDOPTS, executes both exact gate
commands and writes logs into the new run. Failed attempts are retained with FAILED.json and
leave the current pointer unchanged. A source change during execution retains a SOURCE_DRIFT.json
diagnostic instead of selecting a receipt.

The pytest suite includes ordinary temporary-state M12 unit tests inherited from V4. It does
not launch m12_paired_eval.py --v5 or generate a protected-study receipt.

## Limits

These records attest an authored engineering execution, not cryptographic proof of CPU execution,
independent replication or validation of paper claims. XML timing is nondeterministic and the
whole receipt is immutable rather than regenerated to force byte equality.
Measured child CPU/wall costs are recorded; energy, setup and development costs remain unmeasured.
Historical evidence is interpreted under its scientific acceptance ledger, independently of this gate.
