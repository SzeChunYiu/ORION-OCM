# Integration map: GMI developmental theory ↔ RSI

## Existing G6 theory

The existing evolvability theory already supplies:

- persistent machine `M_t=(F_t,O_t,Π_t,C)`;
- self-model / causal factorization;
- locality `κ`, identifiability `Ω`, repair searchability `χ`;
- propose → challenge → shadow evaluate → assure → externally adopt/reject → migrate/rollback lifecycle;
- explicit external constitution `C`;
- a trajectory criterion: become easier to learn, diagnose, modify and extend.

**Bridge addition:** identify the lifecycle-generating machinery as `D_t` and make `D_t` itself an admissible, receipted intervention target.  Apply the same evolvability triad recursively to `D`.

## Existing G6 empirical lane

`g6-evolvability-v1` remains a negative/incomplete empirical terminal.  The bridge consumes its missing evidence as prerequisites.  It does not upgrade `DEVELOPMENTAL_EVOLVABILITY_SUPPORTED`.

## Existing G7 lineage

G7 provides the correct vessel for R4 because it binds persistent state across restarts and distinguishes continued lineage from reset/reacquisition.  The bridge adds one future obligation: an earned `D` change must be included in the persisted bundle/transition receipt and observed in a later descendant.

Current G7 governed self-evolution is still unrun, so this is an interface contract, not a completed transition.

## Grand GMI / prior-free developmental reachability

Grand GMI already separates static morphology frontier claims from developmental reachability and warns that a syntax-level development kernel can reintroduce architecture priors.

The RSI bridge sharpens the open developmental object:

\[
D_t \longrightarrow D_{t+1}
\]

must itself obey the declared operational quotient/resource boundary.  A claim that one syntax is easier for the updater to rewrite is not automatically architecture-neutral.  Comparisons should therefore be made at the registered operational resolution, with matched development budgets.

## Proposed future propagation, only after empirical evidence exists

Do **not** change upstream terminals merely because this bridge exists.  When evidence arrives:

1. G6 may add measured `(κ_D,Ω_D,χ_D)` and a genuine earned change to `D`.
2. G7 may add a governed self-evolution transition that persists `D` and its receipts.
3. Grand GMI may add a theorem/phase result about mutable development kernels if architecture-neutral conditions can be proved.
4. Only then may ORION-specific R3/R4 claims be promoted.
