# Registered modification surfaces

RSI disputes often collapse because “self” changes between examples.  This bridge makes it an assay parameter.

## Surface registry

A study must declare a set `Σ_mutable` and a protected set `Σ_protected` before outcomes are inspected.

Candidate mutable surfaces include:

- persistent epistemic field / memory;
- learned methods, macros and representations;
- executive/controller policy;
- prompts or policies stored as data;
- program/source code and tool wiring;
- model weights/adapters;
- curriculum/data generator;
- self-model and causal factorization;
- candidate-generation/search algorithm;
- parent/child selection policy;
- evaluator **proxy** used internally;
- migration/rollback strategy;
- the composite development operator `D`.

Protected by default in this bridge:

- external constitution/admission authority `C`;
- frozen/shadow evaluator used for the claim;
- resource meter and lineage/provenance receipt channel;
- assay definition and held-out evaluation set after registration.

## Classification consequences

- Memory/weight/tool/code change can support R1/R2.
- R3 additionally requires a persistent, executed change to a component that generates or selects **future improvements** (`D`).
- A candidate that merely edits the task solver while the improvement generator is fixed remains R2 under this taxonomy, even if task quality improves substantially.
- If an internal evaluator is in `Σ_mutable`, the protected shadow evaluator must remain outside it.
- If a study wishes to make `C` mutable, that is a different claim family requiring a separately externalized governance/revision authority; it is not silently permitted here.

## Receipt minimum

Every earned R3/R4 transition should bind at least:

```text
root machine digest
parent descendant identity
generation / lineage id
pre-change D digest
post-change D digest
changed surface ids
origin of proposal
resource vector
training/development ecology id
held-out ecology id
internal evaluator receipt (if any)
shadow evaluator receipt
adoption authority receipt
rollback/migration result
```

Without these, causal heredity is `CANNOT_CHECK`, not inferred from a final code snapshot.
