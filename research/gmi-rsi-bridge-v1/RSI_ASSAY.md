# GMI Recursive Evolvability Assay v1

## Registered question

Does allowing a persistent machine to change its **development operator `D`** causally improve its ability to generate validated future descendants, beyond what the same root can achieve with `D` frozen under matched resources?

## Required arms

### A — `FROZEN_D`

`M` may adapt on the registered non-`D` self surface. `D` is frozen.  This is the primary R2 counterfactual.

### B — `MUTABLE_D`

Same root, ecology and resource vector.  The machine may propose verified changes to `D`.  Descendants must execute the changed `D`, not merely store a dead patch.

### C — resource-confound control

Provide extra compute/data/evaluator/human engineering without granting a valid matched comparison.  This arm demonstrates that stronger descendants under more resources do not identify recursive evolvability.

### D — evaluator-reflexivity control

Permit an internal evaluator proxy to change.  A frozen/shadow evaluator outside the mutable surface decides the claim.  If only the mutable proxy improves, R3 is refused.

## Admission criteria for R3

All must hold:

1. registered `D` component changed persistently;
2. change was machine-originated under the frozen protocol and independently admitted by `C`;
3. descendants actually executed the changed `D`;
4. same root and held-out developmental ecology as frozen-D comparator;
5. matched compute/data/evaluator/human resource vector;
6. frozen/shadow evaluation boundary intact;
7. positive preregistered descendant meta-gain versus frozen `D`;
8. no hidden human patch/root-cause label/selection intervention.

R4 additionally requires the earned `D` change to persist into a later registered descendant.

## Fail-closed results

- fixed `D` + repeated self-edits → **R2 max**;
- mutable `D` + no frozen comparator → **R2 max**;
- mutable `D` + unmatched resources → **R2 max for causal bridge claim**;
- mutable judge + no frozen shadow reference → **R2 max**;
- positive current score but no positive descendant meta-gain → **R2 max**;
- earned D change but no later inheritance → **R3 max**;
- any finite cross-domain/generation count → **R4 max** in this classifier; R5 requires another programme.

## Upstream ORION prerequisites

A real ORION run must not bypass existing G6 negatives.  It needs source-bound intervention transcripts, disjoint incidents, matched parents, a third+ earned change where required by the G6 programme, and registered κ/Ω/χ observations.  For R4 it additionally needs a G7 lineage stage that actually earns governed self-evolution rather than a document-only stage label.
