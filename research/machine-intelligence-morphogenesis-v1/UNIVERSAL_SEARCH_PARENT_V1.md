# Universal search / Kt parent analysis v1

Status: **high-level parent subtraction for a supposed universal developmental complexity measure.**

## Parent result

Levin-style universal search provides a general search principle over programs/procedures weighted by prior/description complexity and runtime. A canonical resource-aware description measure is Levin's time-bounded complexity

\[
Kt(x)=\min_{p:U(p)=x}\{|p|+\log t(p)\},
\]

combining program length with execution time.

Universal/bias-optimal search results show that, relative to a reference language/prior and verifiable solution class, one can allocate search effort across candidate procedures with strong asymptotic/constant-factor optimality properties, albeit often with impractical constants/additive overhead.

Speed-prior work likewise penalizes hypotheses that are expensive to compute, not only long to describe.

## Track-B claim killed

Track B cannot claim novelty for:

> one universal framework can encode neural, symbolic, programmatic and other solution methods and trade description length against computation while searching among them.

Universal program search already supplies that idea at a very general level.

Nor can ORION claim that combining

```text
simplicity
+ runtime
+ verification
```

is itself a new general machine-intelligence principle.

## Why this does not solve practical developmental intelligence

Universal search is deliberately representation/reference-language dependent up to compiler constants and can carry enormous practical overhead.

It also does not by itself explain:

```text
why one structured morphology is learnable from realistic experience;
why a particular factorization gives local credit assignment;
why development preserves old competence;
why one morphology transfers better under drift/revision;
why a learned library/representation reshapes later search geometry;
which morphology phase appears under a real hardware/resource regime.
```

Those properties concern the **structure of the search/developmental bias**, not merely the existence of a universal meta-search over all computable procedures.

## Connection to developmental geometry

Levin-style search suggests a useful parent interpretation:

```text
morphology = structured bias/prior over candidate computations
experience = update of that bias / reusable program vocabulary / proposal mechanism
future burden = target complexity under the updated bias + verification/execution cost
```

OCM's measured history-induced proposal-rank shift can be read as a practical learned change in such bias at one restricted grammar.

But OOPS/PowerPlay/library-learning parents already study incremental search-bias reuse, so even this interpretation is not sufficient for novelty.

## Stronger residual

A Track-B contribution would have to show something universal search does not cheaply give:

1. **structure-derived practical predictor:** measurable morphology structure predicts useful search/developmental geometry without executing universal search;
2. **experience-induced geometry law:** verified experience changes that predictor in a quantitatively forecast way;
3. **cross-paradigm transfer:** the relation works across materially different realization families;
4. **phase prediction:** under changed ecology/resource constraints the theory predicts which structured bias/factorization becomes Pareto-admissible;
5. **endogenous structure discovery:** search recovers the predicted factorization without it being named in the candidate vocabulary.

## Implication for the ultimate question

At the most abstract computability level, a "general machine-intelligence substrate" can always be a universal machine plus universal search. That answer is mathematically general but scientifically too weak for ORION's goal.

Therefore the desired theory must explain **why particular structured, learnable, revisable factorizations are far better than generic universality in specific developmental regimes**.
