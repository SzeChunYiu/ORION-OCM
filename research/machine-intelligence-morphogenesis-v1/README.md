Refs #377, #233, #373, #165. Donors: #145, #214, #221/#220, #151, #149, #144.

**Base:** `main@67d791f8a4b80c2e76cb1c464a3ad5c6dba7ce57` (2026-09-11).

## Scientific question

Can a small resource-bounded adaptive generating basis, or an equivalence class of bases, generate qualitatively different machine-intelligence morphologies and predict which morphology should be favored by a task ecology, resource regime and verification contract?

The target is not another OCM core and not an LLM replacement. Current OCM is treated as one candidate morphology, not as the assumed universal form.

## Four foundational questions

Track B is explicitly organized around:

1. **Basis:** what is the minimal/equivalent generating basis of machine intelligence?
2. **Morphogenesis:** what law maps basis + ecology + resources + verification + history into different intelligence morphologies?
3. **Developmental frontier:** what limits each morphology and why does one dominate a regime?
4. **Unknown forms:** can theory predict a non-parent-equivalent morphology before search?

Higher rung: can the morphology generator/update law themselves develop?

Canonical details: `FOUNDATIONAL_QUESTIONS_V2.md` and `ROADMAP_V2.md`.

- DreamCoder / Stitch / GP own programmatic abstraction and learned libraries;

- novelty/QD/open-ended-evolution research already owns much of divergent morphology search and novelty measurement;
- Boolean functional completeness/minimal connective bases are mature Post/clone-theory territory.

Therefore the surviving candidate residual is deliberately higher:


No novelty is claimed for any individual line until stronger parent subtraction and evidence exist.

## Hard nulls

`UNIVERSAL_COMPUTATION_ONLY` is the central hostile. If the proposed basis reduces to arbitrary mutable state + arbitrary program + universal interpreter and yields no nontrivial learnability/resource/morphology prediction, Track B has rediscovered generic computation.

`PARENT_FORMALISM_SUFFICIENT` is equally important. If a candidate basis is simply a coalgebra/state machine, compositional learner, program interpreter or stochastic kernel with no new developmental/resource law, absorb the parent and move upward.

## Four levels of derivation

1. `D0 REPRESENTABILITY`: basis can simulate a morphology. Weak; universal computation can trivialize it.
2. `D1 BOUNDED_COMPILATION`: semantics and developmental update behavior are preserved within registered resource inflation.
3. `D2 DEVELOPMENTAL_ACQUISITION`: architecture-specific structure is not supplied; experience/search acquires it.
4. `D3 PROSPECTIVE_MORPHOGENESIS`: before search, theory predicts which morphology family should occupy the frontier under a new ecology/resource/verifier regime.

Only D3 is close to the intended field-level claim.

### Stage C-v0 — adaptive Boolean basis census: DONE / PARENT-DOMINATED

One-bit adaptive transducers with

```text
f(state,input) -> output
g(state,input,label) -> next_state
```

were exactly enumerated under all 63 subsets of `{NOT,AND,OR,XOR,NAND,NOR}`.

Key results:

```text
full adaptive morphology universe             4096
current behavior classes at initial state        4
developmental classes (histories <=2)          2884
complete primitive subsets                       54
```

The same inclusion-minimal functionally complete bases reappear, but a richer basis has lower mean compilation depth than the minimal-cardinality bases. Thus:

```text
current behavior identity != developmental identity
minimal primitive count != minimum resource cost
```

The functional-completeness part is nevertheless mature Boolean clone/Post mathematics. The correct terminal is therefore:

```text
ADAPTIVE_BOOLEAN_BASIS_CENSUS_EXACT__PARENT_MATHEMATICS_DOMINATES
```

This is useful because it kills a too-low-level route and forces Stage C-v1 upward toward **structured adaptive bases** whose scientific content is not exhausted by arbitrary Boolean maps.
