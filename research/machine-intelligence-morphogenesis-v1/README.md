## Scientific question

Can a small resource-bounded adaptive generating basis, or an equivalence class of bases, generate qualitatively different machine-intelligence morphologies and predict which morphology should be favored by a task ecology, resource regime and verification contract?

The target is not another OCM core and not an LLM replacement. Current OCM is treated as one candidate morphology, not as the assumed universal form.

## Four foundational questions

Track B is explicitly organized around:

1. **Basis:** what is the minimal/equivalent generating basis of machine intelligence?
2. **Morphogenesis:** what law maps basis + ecology + resources + verification + history into different intelligence morphologies?
3. **Developmental frontier:** what limits each morphology and why does one dominate a regime?
4. **Unknown forms:** can theory predict a non-parent-equivalent morphology before search?

Higher rung: can the morphology generator/update law themselves develop?

Canonical details: `FOUNDATIONAL_QUESTIONS_V2.md` and `ROADMAP_V2.md`.

## Important conceptual correction: the primitive need not itself be intelligent

A transistor is not a computer. Likewise, a fundamental adaptive primitive need not itself contain theorem proving, warrant, language, planning or OCM semantics.

Intelligence may be an emergent system-level property of:

```text
primitive/basis
+ composition/topology
+ control
+ learning/update law
+ memory/state
+ ecology/feedback
+ resource regime
```

This is why current OCM `u2` remains a higher-level **Cognitive Asset Contract** candidate rather than the assumed atom.

The strongest existing parent threat to the low-level-unit idea is now explicit: compositional learners/lenses/categorical cybernetics already formalize objects extremely close to `state/parameters + forward behavior + update + backward/request + composition`. See `LEARNER_OPTIC_PARENT_ANALYSIS_V1.md`.

## Hard nulls

`UNIVERSAL_COMPUTATION_ONLY` is the central hostile. If the proposed basis reduces to arbitrary mutable state + arbitrary program + universal interpreter and yields no nontrivial learnability/resource/morphology prediction, Track B has rediscovered generic computation.

`PARENT_FORMALISM_SUFFICIENT` is equally important. If a candidate basis is simply a coalgebra/state machine, compositional learner/lens, program interpreter or stochastic kernel with no new developmental/resource law, absorb the parent and move upward.

## Four levels of derivation

1. `D0 REPRESENTABILITY`: basis can simulate a morphology. Weak; universal computation can trivialize it.
2. `D1 BOUNDED_COMPILATION`: semantics and developmental update behavior are preserved within registered resource inflation.
3. `D2 DEVELOPMENTAL_ACQUISITION`: architecture-specific structure is not supplied; experience/search acquires it.
4. `D3 PROSPECTIVE_MORPHOGENESIS`: before search, theory predicts which morphology family should occupy the frontier under a new ecology/resource/verifier regime.

Only D3 is close to the intended field-level claim.

## Developmental frontier / phase-law status

The user-level intuition `d(development)/d(cost)` is retained only after freezing a capability utility and resource price vector. The primary object is the raw multi-resource Pareto developmental frontier.

A toy lifecycle calibration already derives the ordinary amortization boundary for a high-build/cheap-use morphology versus a low-build/expensive-use morphology. This is treated as parent-owned lifecycle economics, not GMI novelty.

`CREDIT_ASSIGNMENT_PHASE_AXIS_V1.md` additionally registers credit bandwidth/locality/delay/decomposability/identifiability as candidate phase coordinates. Credit assignment itself is parent-owned; the only Track-B question is whether those coordinates prospectively improve morphology-frontier prediction.
