# GMI-CP E1 parent-frontier protocol v1

Status date: 2026-09-11.

Status: **FROZEN DESIGN SKELETON. DEVELOPMENT-ONLY PILOT MAY CALIBRATE SCALE/TOLERANCES; THE CP PROPERTY PREDICTION AND NEGATIVE-TWIN DIRECTIONS MAY NOT CHANGE.**

Target: establish or kill a parent-frontier hole for `GMI-CP-V1` before neutral morphology search.

---

# 1. Two-stage causal design

E1 deliberately separates realization economics from acquisition.

## E1-A — oracle semantic-state realization assay

Every arm receives the identical finite authoritative semantic object. This stage asks only:

> given the same knowledge, does the predicted source/phenotype organization have the predicted lifecycle resource phase?

No learning claim is allowed from E1-A.

## E1-B — acquired developmental-state assay

Every arm receives the same observation/development stream and must acquire/update its usable state without direct access to the latent authoritative object.

This stage asks:

> does the organization still obtain the predicted cross-regime developmental advantage when the shared state itself must be learned and revised?

A new-morphology claim requires both A and B. If A fails, stop. If A passes but B fails, CP is an engineering compilation pattern, not a demonstrated developmental intelligence morphology.

# 2. Finite shared-semantic world family

Each world is generated from a hidden typed relational transition object with four externally checkable views.

The generator produces:

```text
entities                  16..32
Boolean/finite-valued state variables  12..24
deterministic local rules 8..24
stochastic local rules     4..12
reusable transformations   4..10
registered dependency edges
revision/revocation events
```

The same latent rules/transformations define all four regimes.

## STAT regime

Noisy partial observations -> prediction of selected future/output variables.

Metrics:

```text
log loss / Brier score
accuracy at registered coverage
serve compute and bytes
```

## EXACT regime

Exact entailment / reachability / consistency queries over the deterministic fragment.

Metrics:

```text
verified correct / abstain / false-positive counts
search/execution work
verification work
```

Any admitted false positive is a hard failure for exact-admissibility points.

## PROB regime

Posterior/probability queries over the stochastic fragment with a finite exact evaluator available for protected scoring.

Metrics:

```text
log score
calibration error
selective-decision regret
inference work
```

## EXEC regime

Construct an executable transformation for a requested reusable operator/composition. Protected tests are generated from the latent world after the candidate is frozen.

Metrics:

```text
hidden-test pass fraction
candidate-generation work
execution work
verification calls/failures
```

# 3. Developmental interventions

Every world contains a sequence of prospectively generated interventions:

```text
ADD_RULE
REVOKE_RULE
CHANGE_LOCAL_PARAMETER
ADD_REUSABLE_TRANSFORMATION
REVOKE_TRANSFORMATION
LOCAL_DEPENDENCY_REWIRE
```

The intervention generator records the true dependency closure but does not expose protected future queries.

A revision-locality metric is

\[
L_{collateral}=\frac{\text{changed behavior outside registered semantic dependency closure}}
{\text{all tested behavior outside closure}}.
\]

The primary analysis reports this as a coordinate; no architecture is rewarded for merely refusing all outputs.

# 4. Ecology cells

## P+ — predicted CP region

```text
effective regimes          4
semantic overlap           high: one latent world shared by all regimes
revision probability       development-calibrated medium/high
active regime per episode  1
compile/build cost          finite and amortizable
reuse horizon              long
```

## N1 — low diversity twin

```text
effective regimes          1 or 2
other variables            matched as closely as possible
prediction                 eager/fixed parent closes or reverses CP advantage
```

## N2 — low overlap twin

Each regime receives an independently generated latent world with matched marginal task difficulty/resource scale.

Prediction: cross-regime developmental sharing collapses; CP advantage closes/reverses.

## N3 — expensive-compilation / short-horizon twin

Increase compilation/materialization price or shorten reuse horizon while keeping task semantics fixed.

Prediction: eager maintained or broad fixed realization closes/reverses CP advantage.

If a stronger parent is found during development-only work, it must be added before protected execution.

# 6. Fairness constraints

All arms receive identical legal information and protected query timing.

Required accounting:

```text
pretraining/development examples
human-written architecture/compilers supplied to each arm
candidate generation
training/update compute
phenotype compile/build work
serve compute
memory/storage
verification calls
failed/rejected work
revision/maintenance work
human intervention
```

A hand-written compiler counts as supplied developmental capital. The CP arm may not hide architecture-specific manual engineering outside its ledger.

For E1-A, direct semantic-state access is supplied equally and explicitly excluded from intelligence/acquisition claims.

For E1-B, no arm may inspect the hidden latent object.

# 7. Development / protected split

The exact numerical scale may be chosen after a development-only runtime/power pilot, but the data-custody pattern is fixed:

```text
pilot seeds       implementation/runtime only; never counted
calibration seeds development-only metric scale / power estimation
protected seeds   generated and escrowed after code + thresholds + parent set freeze
```

Minimum protected design:

```text
>= 20 independent worlds per ecology cell
>= 3 independent implementation/random seeds per stochastic arm per world
all attempted worlds retained
```

If compute makes this impossible, reduce world complexity before opening protected outcomes; do not reduce the number of protected worlds after looking.

# 8. Primary E1 decisions

There is no single aggregate intelligence score.

## D1 — semantic adequacy

A system must produce admissible points in every P+ regime. Exact/EXEC admitted outputs require zero verifier-detected false positives in the protected batch; coverage is reported separately.

## D2 — phase direction

Relative to the best eligible non-CP parent frontier:

```text
P+    CP predicted to gain or join the nondominated lifecycle frontier
N1    advantage shrinks/reverses
N2    advantage shrinks/reverses
N3    advantage shrinks/reverses
```

At least two of N1-N3 must show the registered shrink/reversal direction for a positive phase result.

## D3 — developmental sharing

In E1-B, matched history from one regime must improve pre-solution proposal/surprisal/first-hit burden in at least two other regimes relative to RESET and shuffled-lineage controls.

## D4 — locality

Revision burden and collateral semantic change are reported jointly. CP must not obtain low update cost by silently serving stale invalidated phenotypes.

## D5 — parent frontier

A hole is supported only if no registered parent simultaneously matches CP's protected P+ semantic-developmental/resource vector within the prospectively frozen equivalence tolerances.

# 9. Statistics

Primary inference is paired by world wherever possible.

Before protected execution, development-only data must freeze:

```text
which resource coordinates are primary vs diagnostic
semantic adequacy tolerances
family-equivalence tolerances
confidence interval method
multiple-comparison correction for the small primary contrast set
minimum practically important differences
```

Required reporting regardless of significance:

```text
all per-world results
medians and means
paired differences
bootstrap or exact confidence intervals
failure/refusal rates
resource vectors
negative-twin direction counts
```

Conditional-on-success resource reporting is forbidden unless success probability is shown beside it.
