# Morphology phase-law parent atlas v1

Status: **parent subtraction**. This document exists to prevent Track B from renaming algorithm selection / resource rationality / AutoML as a new morphology law.

## 1. Rice / automated algorithm selection

The classical algorithm-selection problem asks, in abstract form, for a mapping from problem/instance features to an algorithm from a portfolio so as to optimize a declared performance criterion.

Modern per-instance algorithm-selection work operationalizes this with:

```text
instance/task features
+ portfolio of candidate algorithms
+ performance/cost metric
-> selector / expected best algorithm
```

Therefore Track B receives **no novelty credit** for the weak statement:

> different task regimes favor different algorithms and we can learn/predict which one wins.

That is mature parent territory.

## 2. Resource-rational analysis

Resource-rational work asks how task/environment structure and computational costs should determine algorithms/representations/strategies, rather than evaluating cognition against an unconstrained ideal.

A standard resource-rational recipe already includes:

1. formalize the task/function;
2. posit an algorithm/architecture family and operation costs;
3. optimize the tradeoff between quality and resource use;
4. compare predicted strategy/mechanism against behavior.

Therefore Track B also receives no novelty credit for the weak statement:

> architecture should be judged by capability under explicit resource prices.

## 3. AutoML / NAS / meta-learning

AutoML, neural architecture search and meta-learning already search/configure architectures/hyperparameters/learning algorithms from task experience. AutoML-Zero is especially damaging to any weak claim that basic operations can search their way into neural learning algorithms.

Again, the weak form

```text
search across architectures and find which performs best
```

is parent-owned.

## 4. What survives upward

Track B's phase-law residual must therefore require **all** of the following:

### P1 — endogenous candidate generation

The relevant morphology families are not merely a human-supplied portfolio. They arise from a common frozen low-level basis / morphology grammar or from a theory-derived expansion rule.

### P2 — developmental cost included

The objective includes not just current execution quality but:

```text
acquisition/search cost
learning/update cost
maintenance/revision
retention/plasticity
future reuse horizon
```

### P3 — morphology equivalence, not architecture names

Candidates are quotiented against known families under bounded developmental compilation. A different source graph does not count as a different form.

### P4 — prospective boundary prediction

Before protected architecture search / new ecology outcomes, derive a statement such as:

```text
for regime E_left, class A is on the nondominated frontier;
for regime E_right, class B is on the nondominated frontier;
boundary occurs in registered interval/condition R.
```

### P5 — blind recovery

Neutral/frozen search from the shared basis recovers the predicted forms or frontier change without being told their architecture labels.

### P6 — parent-favoring and no-difference regions

The phase model must predict regions where:

- an ordinary parent dominates;
- two morphologies are equivalent within tolerance;
- development cost prevents a high-capability morphology from paying;
- a morphology transition should *not* occur.

## 5. Strongest current Track-B residual

The candidate field-level claim is therefore not algorithm selection. It is closer to:

> A resource-bounded developmental theory predicts which equivalence classes of machine-intelligence morphology become Pareto-admissible as ecology/resource/verification variables change, while the candidate morphologies themselves are generated from a shared basis and their acquisition/development cost is charged.

This remains an **open hypothesis**.

## 7. Parent anchors

Mandatory parent families for the next phase-law pass:

- John R. Rice, *The Algorithm Selection Problem* (1976);
- modern automated/per-instance algorithm-selection surveys and systems;
- SATzilla/algorithm-portfolio descendants where relevant;
- resource-rational analysis (Griffiths, Lieder and related work);
- rational metareasoning / value-of-computation;
- AutoML / NAS / meta-learning / algorithm configuration;
- multi-objective/Pareto algorithm selection where resource vectors matter.

The next prospective phase-law experiment must state exactly why it is not merely one of these parents.
