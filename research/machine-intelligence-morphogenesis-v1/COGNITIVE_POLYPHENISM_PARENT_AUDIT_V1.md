# 1. Audit question

Does an established parent already implement the entire predicted CP organization:

```text
one authoritative persistent developmental state
+ materially different regime-conditioned executable realizations
+ semantic equivalence / round-trip obligation across those realizations
+ lazy invalidation or reconstruction after shared updates
+ cross-realization developmental transfer
+ open, developable realization family rather than a frozen labelled portfolio
+ complete lifecycle resource advantage in the predicted heterogeneous regime
```

A partial match is not novelty, but it is also not sufficient by itself to reduce CP. The burden is whether a parent product bounded-compiles the whole registered developmental/resource behavior.

# 2. Strong parents

## P1 — knowledge compilation

Knowledge-compilation theory explicitly studies translating a source knowledge representation into target representations chosen for tractable downstream queries/transformations. This is a very strong parent for the **source -> target realization** component.

Threat:

```text
CP may simply be dynamic multi-target knowledge compilation.
```

Residual required of CP:

```text
experience-driven shared developmental update
+ heterogeneous cognitive execution families
+ prospective regime/resource phase law
+ cross-phenotype transfer
+ open morphology development
```

If ordinary multi-target knowledge compilation plus incremental maintenance realizes these within the registered bounds, CP is parent-owned.

## P2 — ACT-R / production compilation

Cognitive architectures such as ACT-R have long used knowledge compilation/proceduralization: declarative knowledge is transformed into faster procedural productions as skill is acquired.

Threat:

```text
persistent declarative knowledge -> compiled procedural phenotype
```

is not new.

Residual required of CP: multiple materially different regime-conditioned realization families plus lazy invalidation and common developmental authority, not merely compilation into productions.

## P3 — multiple-representation cognitive architectures

Polyscheme and related cognitive architectures explicitly combine multiple representations/inference systems and can exploit representation diversity without a single universal internal formalism.

Threat:

```text
multiple cognitive realizations sharing an integrated agent
```

is parent-owned.

Residual required of CP: derived/disposable realization phenotypes tied to one developmental authority, prospectively regenerated as resource/verifier regimes change, with a measurable heterogeneity/revision phase transition.

## P4 — self-adjusting / incremental computation

Self-adjusting computation tracks dynamic dependencies and updates only affected computation after data changes, often using memoization/change propagation.

Threat:

```text
lazy invalidation + dependency-local recomputation
```

is strongly parent-owned.

Residual required of CP: the dynamically maintained objects must be **different cognitive realization families** whose developmental transfer and verifier semantics remain coupled through a common semantic state.

## P5 — materialized views / incremental view maintenance

Databases choose and maintain derived/materialized representations according to query workload and maintenance cost.

Threat:

```text
workload-conditioned materialized phenotype + maintenance economics
```

has a mature systems analogue.

Residual required of CP: ongoing cognition/learning changes the source state; views can be different learning/reasoning morphologies rather than query indexes; experience through one realization alters future cognition through another.

## P6 — model switching / algorithm selection

Multi-model control and algorithm-selection work choose among a portfolio using problem/regime information and performance models.

Threat:

```text
regime -> best executable model
```

is parent-owned.

Residual required of CP: phenotype construction and developmental sharing, not frozen portfolio selection.

## P7 — MoE / modular continual learning

Mixtures of experts, dynamically expandable modules and parameter-isolation continual learning create specialized persistent modules and route tasks to them.

Threat:

```text
sparse active specialist subset + local updates
```

is parent-owned.

Residual required of CP: inactive phenotypes may be absent/discarded and regenerated from shared developmental authority; the realization family is open and can cross representation paradigms.

## P8 — neuro-symbolic / MRKL / tool-agent hybrids

Hybrid architectures combine neural, symbolic, retrieval, planner and tool components under routing/control.

Threat:

```text
heterogeneous morphology inside one system
```

is parent-owned.

Residual required of CP: the predicted object is not static coexistence but **developmental re-realization** from a common persistent semantic source, with phase-conditioned materialization and invalidation.

## P9 — hypernetworks / conditional computation

A generator can produce parameters or subnetworks conditioned on context/task.

Threat:

```text
one state/generator -> many execution phenotypes
```

is parent-owned inside neural families.

Residual required of CP: cross-paradigm realizations and shared semantic developmental equivalence, not merely weight generation.

## P10 — program/library learning and multi-representation evolution

DreamCoder-style library learning and newer multi-representation symbolic-evolution systems build reusable abstractions and transfer them across tasks/representations.

Threat:

```text
learned developmental source -> reusable derived procedures across tasks
```

is parent-owned.

Residual required of CP: explicit phase-predicted realization switching/materialization under verifier/resource regimes and lazy multi-phenotype scaling.

## P11 — memory-based model editing / unlearning

Explicit edit memories, modular adapters and unlearning techniques can localize changes without retraining an entire model.

Threat:

```text
local revision / bounded collateral change
```

is parent-owned.

Residual required of CP: the local update must propagate through a common developmental source to multiple distinct future realization phenotypes.

# 3. Audit result

The parent audit significantly reduces the novelty surface. No individual ingredient of CP is new:

```text
compilation                  parent-owned
multiple representations     parent-owned
lazy dependency updates      parent-owned
workload-conditioned views   parent-owned
model selection              parent-owned
modularity                   parent-owned
local editing/unlearning     parent-owned
morphology generation        parent-owned
```

The only surviving candidate residual is their **developmental organization plus a prospective phase law**:

> a persistent intelligence with one future-relevant developmental authority should, under high semantic overlap + high regime heterogeneity + ongoing revision + sparse active-realization demand, move toward a regime where executable cognition is repeatedly materialized as different disposable realizations rather than maintained as one fixed morphology or an eagerly synchronized portfolio.

This residual is sufficiently specific to fail experimentally, but it is not yet proven non-parent-equivalent.
