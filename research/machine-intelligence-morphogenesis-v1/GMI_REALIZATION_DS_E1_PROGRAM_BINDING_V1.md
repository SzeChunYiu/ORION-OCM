# 2. What the real program-family evidence establishes

## 2.1 History changes program proposal/search geometry on genuinely new targets

In M2-P1, protected target normal forms are disjoint from developmental history. `LIBRARY_ONLY` equals `RESET` on the new targets, while a history-mined structural library changes the guided proposal stream.

This excludes exact solved-object retrieval as the explanation at that registered scope.

The important native program-search object is not “memory present.” It is:

```text
history
-> mined fragments / library
-> changed token ordering / composition search
-> changed proposal burden before verified target success
```

This is GMI K1/search-capital behavior at the authored program-family scope.

## 2.2 Structural content matters, not history volume

The shuffled-history control preserves a matched library size/length profile while destroying the true structural motifs and can perform worse than no library.

Thus the treatment is a search-bias/content effect, not generic extra context volume.

## 2.3 Program-native rank/coverage quantities predict the gate

The admission law on the E5/E7/E8 programme is:

```text
recovered == all motifs  <=>  admitted
```

with the learned motifs also appearing early in the token ordering under the support-count/length ranking rule.

The original uniform `T^k` position approximation was falsified. The corrected predictor is native to the actual enumerator:

```text
motif presence / coverage
+ motif rank in the frozen token order
-> guided composition position
-> whether interleaving can remain non-inferior
```

This is exactly the kind of family-native predictor DS-E1 requires first.

## 2.4 Development depth is a non-monotone response curve

At one fixed held-out set, the recorded M2-P1 depth sweep is:

```text
depth 8   -> 21.9% work reduction
depth 16  -> 37.7%
depth 32  -> 72.2%
depth 64  -> 66.9%
depth 128 -> 62.3%
```

The decline after the peak is attributed to the fixed top-16 fragment capacity filling with generic high-support fragments, diluting the useful motifs and expanding the guided branch set.

Therefore:

```text
more history != monotonically better search prior
```

at this scope.

This is a morphology/search-response property, not an obligation-side universal law.

## 2.5 Applicability is a separate native response layer

M1B's top-rung scored results:


A simple dev-data decision list recovers nearly the entire applicability effect.

This means the native realization response contains at least two separable pieces:

```text

```

and retrieval timing alone is insufficient in the scored M1B regime.

M2-P1 independently exhibits horizon/accounting phase behavior. Under its E8 ledgers, different legitimate cost-attribution conventions produce materially different break-even horizons; the raw ledgers are therefore more fundamental than one scalar headline.
