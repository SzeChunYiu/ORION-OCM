# GMI realization DS-E1 parent/predictor atlas v1

Status: **FIRST-REFUSAL PARENT ATLAS FOR FAMILY-NATIVE REALIZATION PREDICTION**

Refs: `GMI_REALIZATION_DEMAND_SIGNATURE_V1.md`, `GMI_REALIZATION_SIGNATURE_LIMITS_V1.md`, #377, #233.

## Purpose

Before testing a cross-paradigm realization law, each morphology family gets its strongest practical/native pre-outcome predictors.

The shared GMI demand signature matters only if it predicts held-out realization-frontier movement beyond trivial identifiers and beyond what the native family already predicts.

Do not compare a cross-family predictor against a deliberately weak baseline.

---

# 1. Common protocol

For family `f`, define:

```text
Omega_f          registered obligation/ecology
M_f              frozen candidate realization set
P_f              strongest native pre-outcome predictor family
Xi               shared GMI obligation-side coordinates
R_M              morphology response profile
Y_f              protected realization ranking/frontier outcome
```

DS-E1 first asks within family:

```text
How well does P_f predict Y_f?
Does Xi add anything beyond P_f?
Are the proposed Xi coordinates actually measurable before Y_f?
```

DS-E2 later asks whether any coordinate meaning transfers to a held-out morphology family.

Architecture/family identity may be used in the **native parent** model, but not as an input to the claimed cross-paradigm law.

# 2. Program / library / synthesis family

## Mature parents

### Levin-style / bias-optimal programme search

Native quantities include:

```text
program prior probability
code/description length
execution time
verification time
search allocation induced by prior/bias
```

Under standard bias-optimal constructions, shorter/higher-prior candidates receive more search allocation. Exact guarantees are conditional on the search formalism.

### OOPS

OOPS explicitly reuses previously frozen solution-computing programs and measures bias through problem-solving/search time under the current program distribution.

### DreamCoder

DreamCoder jointly learns symbolic library abstractions and a neural search model, changing the language/prior used for future synthesis.

### Stitch

Stitch directly optimizes library compression objectives over program corpora and is a strong parent for abstraction/library construction economics.

## Native predictor candidates

Before a new target is solved, record where legal:

```text
target/candidate description length under frozen grammar/library
prior/proposal mass under frozen search distribution
branching / enumerator depth
estimated execution + verification cost
library lookup / matching cost
compression gain of admitted abstractions
build cost of the library
expected/effective reuse horizon
scope/applicability uncertainty
```

## First-refusal prediction

A program-family phase result is parent-owned if code length/search prior + lifecycle amortization predicts the frontier adequately.

Valid terminal:

```text
PROGRAM_NATIVE_SEARCH_BIAS_AND_LIBRARY_ECONOMICS_SUFFICIENT
```

## Key hostile

A GMI coordinate called `tau_L` cannot simply copy the program's native code length and then claim cross-paradigm unification. It must retain the same operational semantics in the held-out family or remain family-native.

# 3. Probabilistic / Bayesian family

Keep three objects distinct:

```text
Bayesian posterior inference
Bayesian experimental design / expected information gain
PAC-Bayesian generalization theory
```

They are related but not interchangeable.

## Native Bayesian quantities

Depending on the registered model:

```text
prior mass / prior density around truth or useful hypotheses
likelihood informativeness / identifiability
posterior entropy / contraction
Bayes factor / marginal likelihood
expected information gain of legal experiments
Fisher / local asymptotic information where assumptions permit
number/cost of observations
inference/sampling computation
```

## Expected information gain parent

For legal experiment `d`, the standard Bayesian-design criterion can be expressed as expected prior-to-posterior information gain, e.g. an expected KL / mutual-information quantity when the assumptions fit.

This already owns a large part of:

```text
which observation/probe is informative per unit cost?
```

## PAC-Bayes / meta-learning parent

PAC-Bayes bounds provide family-native complexity/generalization quantities involving posterior-vs-prior KL under explicit assumptions. Recent meta-learning work extends the framework to learned priors and even learned learning algorithms for future tasks.

This is a direct parent of K1/K2-style “history changes future learning” claims under its registered task-distribution assumptions.

## First-refusal prediction

For a Bayesian family, use its strongest applicable posterior-concentration, prior-mass/KL, information-gain and inference-cost predictors before introducing a GMI cross-family coordinate.

Valid terminals:

```text
BAYESIAN_NATIVE_INFORMATION_AND_PRIOR_GEOMETRY_SUFFICIENT
PAC_BAYES_META_PARENT_SUFFICIENT
```

## Key hostile

Do not call `KL(Q||P)` a universal GMI distance. In another morphology there may be no natural prior/posterior pair with the same semantics.

# 4. Neural / differentiable family

## Native parent landscape

Neural realization prediction is already a research field.

Parents include:

```text
full/partial training curves
parameter/FLOP/memory/hardware cost models
neural architecture search surrogates
zero-cost / training-free proxies
conditioning / curvature / gradient statistics
activation/representation geometry
NTK/Fisher-style local analyses where assumptions fit
```

## Zero-cost / training-free NAS

Recent reviews characterize a large family of proxies that attempt to rank architectures before full training using cheap forward/backward/statistical measurements.

Important empirical boundary:

```text
proxy ranking quality varies across tasks/search spaces/objectives
```

and robustness or broader objectives may require combinations of proxies rather than one metric.

Recent 2026 work such as InTrain explicitly combines:

```text
geometric capacity
optimization resilience / gradient health
```

into a trainability proxy.

This is strong parent evidence against claiming one hand-written GMI `gamma` coordinate as a new neural-performance law.

## Native predictor candidates

Where prospectively measurable:

```text
architecture size / FLOPs / memory / communication
activation covariance / effective rank
forward signal propagation
gradient magnitude/variance/health
conditioning / curvature proxies
zero-cost NAS proxy suite
hardware latency/throughput model
small-budget learning-curve extrapolation
interference/plasticity on declared prior tasks
```

## First-refusal prediction

Any GMI neural realization claim must compare against a current proxy ensemble / strong training-free predictor and, where feasible, a small-budget learning-curve predictor.

Valid terminal:

```text
NEURAL_NATIVE_TRAINABILITY_PREDICTORS_SUFFICIENT
```

## Key hostile

A proxy derived from untrained architecture internals is **morphology-side response**, not an obligation-side demand coordinate.

This directly motivates the v1 demand/response split.

# 6. Why the native atlas matters

The cross-paradigm theory should **not** aim to replace every native predictor with one scalar.

A successful GMI law could instead be a higher-order statement such as:

> a small set of obligation-side variables predicts how the value of family-native response properties changes across ecologies.

Example structure:

```text
long eta + low nu
-> build-heavy reusable structures receive more opportunity to amortize
```

This can apply across:

```text
program library
Bayesian cached/sufficient structure
neural training
symbolic materialization/indexing
```

while the family-native model still predicts the exact build/use curve.

That is a more plausible cross-paradigm residual than claiming code length, KL and gradient health are literally the same quantity.

# 7. DS-E1 evaluation order

## DS-E1-P — program/library

Use current #323 program/search-capital receipts where legal for calibration, plus fresh protected tasks only under their own authority.

Question:

```text
Does Xi add predictive information beyond native code-length/proposal-mass/library-economics quantities?
```

## DS-E1-B — Bayesian/probabilistic

Build a finite exact Bayesian microscope first so prior mass, information gain, posterior concentration and inference work are known exactly.

Question:

```text
Does an obligation-side coordinate transfer without simply renaming Bayesian native quantities?
```

## DS-E1-N — neural/differentiable

Start on a small controlled task/architecture family with a frozen current zero-cost proxy suite.

Question:

```text
Does Xi explain held-out task variation beyond native trainability/performance predictors?
```

No large training campaign before this protocol is frozen.

## DS-E1-S — symbolic/search

Use exact small search/CSP families where native complexity is enumerable.

This is useful as a collision/control family because strong native predictors may make the shared signature redundant.

# 8. Evidence required before DS-E2

Do not move to a cross-family claim merely because each family shows some correlation.

Require:

```text
native parent implemented or faithfully approximated
pre-outcome feature custody
held-out obligations within each family
resource-complete outcome
family-native residual quantified
same Xi coordinate semantics demonstrably available in >=2 families
architecture/family labels removed from claimed shared predictor
surface-remint hostile
```

If no coordinate survives:

```text
FAMILY_NATIVE_REALIZATION_THEORIES_SUFFICIENT
```

is the correct DS-E1 terminal.
