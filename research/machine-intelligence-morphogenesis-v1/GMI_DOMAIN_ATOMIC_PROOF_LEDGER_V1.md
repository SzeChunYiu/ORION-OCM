# GMI Domain Atomic Proof Ledger v1

Status: **FORMAL HARDENING / LIVE PROOF LEDGER**

Status date: 2026-09-12.

Purpose:

> Decompose every structural-domain claim into atomic theorem obligations. A domain is not accepted because its description is suggestive. Every atomic obligation is proved, reduced to a parent, experimentally registered, or left explicitly open.

Use plain technical labels. Legacy identifiers such as `N3` and `N8` may remain as stable cross-references, but coined architecture/species names are not evidence.

---

# 1. Atomic domain obligations

For a candidate carrier/operator family `D`, register all atoms below.

```text
A0  carrier definition
A1  native operator definition
A2  semantic sufficiency
A3  non-vacuity / bounded description and precision
A4  information or state lower bound
A5  constructive upper bound / executable realization
A6  natural complexity coordinate
A7  strongest-parent compiler upper bound
A8  lower bound against strongest parent under frozen overhead class
A9  capability/scaling law
A10 matched negative twin
A11 held-family prediction
A12 semantic and implementation remint invariance
A13 empirical protected evidence
A14 domain/kingdom/reduction verdict
```

Allowed atom statuses:

```text
PROVED-EXACT
PARENT-THEOREM
EXECUTED-SUPPORTED
REGISTERED
OPEN-BLOCKING
REDUCED-TO-PARENT
FALSIFIED
OUT-OF-SCOPE
```

A candidate cannot receive domain status while `A7` is missing or `A8` is `OPEN-BLOCKING`.

# 2. Overhead classes

Every reduction/separation statement must name its accepted overhead resolution.

```text
H0  representation remint / constant additive overhead
H1  constant-factor lifecycle overhead
H2  quasilinear or other explicitly frozen tight overhead
H3  polynomial overhead
H4  computability-only finite simulation
```

`GMI_CLASSICAL_DOMAIN_COLLAPSE_THEOREM_V1.md` proves that ordinary finitely described classical computable systems collapse to a universal program super-domain at H4. Therefore all ordinary classical novelty claims must be H0-H3 claims.

# 13. Recursive closure rule

For every `OPEN-BLOCKING` atom:

1. derive the smallest exact finite family exposing it;
2. prove a lower bound or construct a collision;
3. construct the strongest known parent compiler;
4. compare under a frozen overhead class;
5. derive a negative twin;
6. implement an exact microscope where finite enumeration is possible;
7. freeze a held-family prediction before broader experiments;
8. update this ledger with `PROVED`, `REDUCED`, or `FALSIFIED` rather than adding prose.

A candidate whose `A8` repeatedly reduces should be demoted quickly. Research effort should move toward candidates with unresolved parent-separation atoms, not toward defending names.
