# Architecture vs learned inductive bias — Track-B threat v1

Status: **parent-derived threat / theory correction**, not a Track-B empirical result.

## Why this matters

A morphology phase law can easily over-attribute developmental behavior to the visible architecture.

But a learner's effective inductive bias can live in multiple places:

```text
architecture/topology
initial parameters/state
pretraining/meta-training history
optimizer/update rule
external memory/library
proposal/search distribution
representation
```

Therefore:

```text
architecture label != complete developmental morphology
```

## Parent threat 1 — learning universal predictors

Recent work on `Learning Universal Predictors` trains neural networks by meta-learning on data generated by Universal Turing Machines, explicitly investigating whether neural learners can amortize very broad Solomonoff-like universal prediction strategies.

Scientific threat to Track B:

> a morphology normally called “neural” can acquire a much broader inductive/search strategy through developmental history than its bare architecture label suggests.

Thus a phase law that classifies only `Transformer` vs `program` vs `symbolic` can miss the learned geometry inside the architecture.

## Parent threat 2 — architecture vs initial weights

2025 work comparing MLP/CNN/LSTM/Transformer architectures under meta-learned initial weights reports that meta-learning can substantially reduce or eliminate performance differences among architectures on several controlled inductive-bias tasks, while generalization remains poor far from meta-training experience.

This should be treated as a strong active threat, not as a universal theorem.

Track-B consequence:

```text
some apparent architecture phase differences may actually be prior/history differences
```

and conversely:

```text
some architectures may differ mainly in how cheaply they can acquire a useful prior
```

rather than in final representational capability.

## Corrected morphology state

The existing morphology object already includes mutable configuration and learning law:

\[
M=(G,X,\Theta,\Pi,\mathcal L,\mathcal K_{io}).
\]

For phase work, distinguish at least:

```text
G      relatively persistent architecture/topology
Theta  learned parameters / weights / rules / library state
L      update law
H_dev  developmental/meta-training history that created Theta/L
```

The developmental geometry

\[
\mathcal G_M=(\mathcal H,\pi,K,c,V)
\]

should be measured **after the registered developmental history**, not inferred from architecture name.

## New required controls

Any future cross-morphology phase study should include, where feasible:

1. **unadapted architecture** comparison;
2. **equally meta-trained/adapted** comparison;
3. explicit cost of learning the prior/initial state;
4. transfer to tasks outside meta-training distribution;
5. reset-prior controls;
6. same architecture with different learned priors;
7. different architectures trained toward the same registered task ecology.

## Important possible result

A valid phase result may be:

```text
ARCHITECTURE_DIFFERENCE_VANISHES_AFTER_META_LEARNING_AT_SCOPE
```

This would not mean architectures are identical. It would mean the effective developmental geometry is more plastic than the architecture taxonomy implied.

Conversely:

```text
ARCHITECTURE_CONSTRAINS_ACQUIRABLE_GEOMETRY_AT_SCOPE
```

would require showing that matched training/history cannot erase the residual within the registered budget.

## Relationship to unknown-morphology discovery

A candidate “new form” must not be declared new merely because its static graph is unfamiliar. It may be a familiar universal architecture carrying a newly learned prior/update geometry.

The reduction test must ask whether the developmental geometry is reproducible by a known architecture under comparable meta-training/resource cost.
