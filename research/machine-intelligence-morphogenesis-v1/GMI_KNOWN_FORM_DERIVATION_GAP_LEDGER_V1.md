# 3. Major blocking response laws

## GKF-01 — shared-law compressibility

Need a pre-outcome descriptor predicting when a coefficient/basis model compresses future semantic distinctions better than explicit memory.

Required closure:

```text
exact synthetic families with known minimal description
held-family estimator of reusable regularity
coefficient vs exemplar crossover prediction
negative twin with independent volatile labels
```

## GKF-02 — neural reachability

Need a response law predicting whether actual gradient-based development reaches an adequate realization within budget, not merely whether the architecture can represent it.

Coordinates should include at least:

```text
feedback density/alignment
conditioning
width/redundancy
feature-learning pressure
optimization horizon
initialization scale
```

## GKF-03 — neural generalization

Need held-family prediction of protected risk from pre-outcome architecture/update/data descriptors. Competing parent mechanisms must include margin/norm, stability, PAC-Bayes, spectral/manifold and feature-learning descriptors rather than one universal mechanism.

## GKF-04 — approximate symmetry

Need quantitative law from degree of real symmetry/locality to burden advantage of parameter sharing/equivariance.

## GKF-05 — dependency geometry

Need a pre-outcome estimator of required dependency sets `E(x)`, their union, variability, density and discovery difficulty. This controls fixed routing vs attention vs sparse routing vs recurrent/state-space alternatives.

## GKF-06 — conditional specialization

Need a lower/upper-bound framework comparing best dense shared realization with routed heterogeneous experts, not merely execute-all portfolios.

Coordinates:

```text
mode heterogeneity
parameter/function overlap
activation sparsity
routing error
communication price
expert maintenance/search cost
```

## GKF-07 — recurrent/state dimension

Need practical approximation to the future-response quotient or predictive-state dimension from finite observations, including nonlinear and partially observable cases.

## GKF-08 — residual complexity

Need measurable prediction of:

```text
H(S_O|S_P)
within-predictive target multiplicity
effective target update rank/locality
```

for RAG/adapters/fine-tuning/full rewrite selection.

## GKF-09 — search value

Need quantitative prediction of heuristic information value, verifier power, branching reduction and candidate reuse to choose search/frontier depth and compute.

## GKF-10 — generative factorization

Need zero-prior selection among:

```text
autoregressive conditionals
diffusion/score dynamics
normalizing flows
latent-variable models
adversarial generators
retrieval/generative hybrids
```

from observable distribution/ecology/resource coordinates.

## GKF-11 — control factorization

Need zero-prior crossover among:

```text
model-free policy/value
world model + planning
search-only control
hybrid cached planning/policy
```

under model error, dynamics change, goal variation, exploration value and reuse.

## GKF-12 — continual-development architecture

Need law predicting replay vs regularization vs expansion vs local modular update vs external memory from update locality, task overlap, retention, lineage and plasticity loss.

## GKF-13 — test-time reasoning/search

Need response law for allocating inference-time branches/depth/verifier calls vs more train-time capacity.

## GKF-14 — heterogeneous tool composition

Need theory of when one tool suffices, when routing among tools suffices, and when multi-step tool composition is required by semantic dependency.

# 4. Recursive closure rule

For each gap `GKF-i`:

1. define the hidden causal variable;
2. construct exact finite worlds where it is known;
3. prove an information/resource bound if possible;
4. define an observable pre-outcome estimator;
5. freeze a directional/quantitative response law on D;
6. tune only on V;
7. predict fresh P family cells;
8. neutral-search the corresponding structural property;
9. attack with strongest alternatives;
10. if RED, preserve the failure and refine only the failed atom.

No protected failure may be patched by adding a world identifier or family name.
