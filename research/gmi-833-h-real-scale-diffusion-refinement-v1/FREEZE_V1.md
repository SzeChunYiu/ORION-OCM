### The ecology, registered before it is built

`F33` (`SIGMA_H33R`). The presentation unit is the descriptor closure: every
prefix of length ≥ 2 of every token, in source order, giving
`T_ctx = sum(len(w) - 1) = 671,860` positions over `168,834` distinct
descriptors. A **task** is a held position whose descriptor `q` is a context
with `len(q) >= 3`.

The stored table of a slice is built from the slice's own positions: for each
stored position with descriptor `q` of length ≥ 3, the pair `(q[:-1], q[-1])`
is a stored unit — the **one-step continuation of `q[:-1]` by the character
`q[-1]`**. For a context `q`,

```
S_store(q) = { c : the stored unit (q, c) exists }        the stored candidates
CARD(q)    = |S_store(q)|                                 the candidate cardinality
```

`S_full(q)` is the same set built from the whole source, and is a **registered
READ-ONLY labeller datum**: it is a full-source-only quantity that the fit
slice under-samples, and no readout of this package's language may read it.

### The registered refinement channel, and the label

The alphabet is put in the registered **target-independent Knuth order**

```
order(c) = sorted(A, key = lambda c: (ord(c) * 2654435761) mod 2**32)
sigma(c) = order[(index(c) + 1) mod C]
```

`order` is injective on this source (the key is injective over 69 distinct code
points), and `sigma` is the successor in that order — a fixed permutation of
the registered alphabet, carrying no free parameter and no family information.

The task presentation is a **noisy candidate**. For a context `q`:

```
c0(q) = min S_full(q)                        the canonical candidate
z(q)  = (occ(q) * 2654435761) mod C           the registered probe offset
c(q)  = sigma^z(q) ( c0(q) )

r(q) = min { r >= 0 : sigma^r( c(q) ) in S_full(q) }   capped at M = 256
```

`occ(q)` is the number of source positions whose descriptor is exactly `q`.
`r(q)` is the **refinement index**: the number of successive registered
perturbations of the presented candidate required before the candidate's
character re-enters the full-source support of `q`.

**The task presentation is the pair `(q, c(q))`.** The presented candidate
`c(q)` is an INPUT of the task, and every readout of section 5 may read it: it
is the noisy candidate the refinement procedure is given, exactly as the
sibling packages present the query. `z(q)` is target-free (it depends on the
context's occurrence count, not on the label). `S_full(q)` and the refinement
walk through it are **labeller-only**: they produce the label and no readout of
this package's language may read either — a readout may walk the registered
successor chain through the STORE's own candidate set, which is a strict
sub-table of the full set, and that is a different quantity.

The protected interface is the **refinement-index predicate**

```
y(q) = 1   iff   r(q) <= T*
y(q) = 0   otherwise
```

with `(probe key, corruption)` and `T*` fixed by the registered **configuring
rule** below, before any fit. A context with `|S_full(q)| < 2` is a **tie** and
is out of the registered query set: at a context with a single source candidate
a refinement step is not defined, and the label does not pretend otherwise.

### The registered rule that fixes the labelling configuration and `T*`

`T*` and the labelling configuration are fixed pre-outcome by one rule, applied
to source-derived data alone, with **no slice, no store and no readout
evaluated**:

> Over the four registered configurations {(probe key from `occ(q)`,
> corruption `0`), (probe key from `occ(q)`, corruption `1`), (probe key from
> `(ord(q[0]) * MULT + len(q)) mod C`, corruption `0`), (probe key from the
> descriptor key, corruption `1`)} — where "corruption `1`" adds one registered
> step to the probe offset, `c(q) = sigma^(z(q)+1)(c0(q))` — measure the
> distribution of `r(q)` over **all** source contexts, and select the
> configuration minimising `|P(y = 1) - 1/2|`; `T*` is the smallest threshold
> attaining that minimum.

Why a balance criterion and not a free floor: a threshold chosen to make the
label easy to predict (for example `T* = C/2`) pushes the base rate to 0.84 and
the constant arm then beats every real arm at the majority rule. The registered
rule instead fixes the label at the most even split attainable among the
registered configurations, so the majority rule is a genuine adversary. The
rule is a property of the bytes, is measured on the full source with no slice
and no store, and is applied once.

The rule is a criterion, not a named configuration: the configuration it
selects is a fact of the bound source, is measured by the executor on the full
source before any fit, and is recorded in `REAL_RUNS/scope_SIGMA_H33R.json`
under `label_config` together with the label's exact positive/negative integer
counts. The executor asserts that the chosen configuration's label is non-degenerate (both labels
occur) and fails the run otherwise. No configuration name is fixed in this
freeze, because fixing one here would be fixing a threshold from outside the
registered rule.

### Slices, fixed here before any fit

## 9. Falsifiers

Registered with numerical form, so they cannot be read after the fact:

1. the winning arm's held error count **strictly exceeds** the fit-majority
   rule's held error count;
2. the winning arm's F1 margin fails, i.e. its held error count exceeds **half**
   the fit-majority rule's;
3. the best arm of the registered **single-draw family** is **not worse** than
   the best arm of the registered **refinement-index family** — which would mean
   the recovered class is the sibling's single-draw source channel rather than
   this row's iterative refinement, and would falsify this row's claim at this
   scope;
4. the registered design null fails to fire on the refinement family (the
   refinement-index arm does not degrade by the registered factor) or a raw
   count arm moves under the reassignment, which would make the null an arming
   null rather than a clean one;
5. the source-order presentation control does not fire, or the store ladder is
   not monotone, or the crossover arithmetic does not hold;
6. any cross-scope gate composition, foreign `sigma`, or failed negative
   control falsifies the claim ceiling.

Falsifier 3 is the load-bearing one for this row: this row and
`Latent-variable generative systems.` share a registered target contract, and
the measurement must separate them by data rather than by name.

## 10. Controls

Matched negative control (`R05`): the **weight reassignment design null**
reassigns every stored unit's refinement participation globally — each stored
unit is given the refinement index of a unit drawn from a different context —
so no context's refinement index survives its own evidence, while the raw
cardinality aggregates `CARD(q)` are **bit-identical** by construction and the
executor asserts they are. A null that permutes a query's own multiset is
invalid and is not registered here. The **equal-weight control** runs the same
language on a store where every stored unit contributes weight 1. A
shuffled-label null on the winning arm's unchanged predictions is reported for
completeness. The screen asserts `CLEAN` only when the no-alarm case also fires.

## Appendix A — the pre-freeze configuration screen, and why the labelling rule has the shape it has

This appendix is part of the freeze and is committed with it. It records the
measurements that fixed the registered rule above. All of them are
**source-derived constants**: no store, no readout, no error count and no
family verdict was computed in producing them.

1. A first candidate labelling rule — the same refinement walk with the probe
   offset `z(q)` drawn uniformly from `[0, C)` and **no** corruption, i.e.
   `c(q) = c0(q)` so that `r(q) = 0` for every task — is degenerate: `P(r <= t)`
   is 1 for every `t >= 0`, the label is constant, and no threshold balances it.
   The registered rule therefore perturbs the candidate by a target-free offset
   before the walk, and the registered grid includes the corrupted variant.
2. A second candidate — the same walk with a corruption drawn from `[1, C)`
   and the probe key taken from the descriptor — was measured and rejected: it
   is also injective (the walk stops at the first character reached, which for a
   uniformly drawn corruption is essentially uniform over the alphabet, with a
   mode at the first hit) and it does not balance the label as evenly as the
   registered configuration. The registered rule's grid selects among these
   configurations by the balance criterion in section 4, so the rejection is
   mechanical rather than asserted.
3. The balance criterion is registered because the obvious alternative — fixing
   `T*` at `C // 2` — pushes the label base rate to `0.84` on the held slice,
   at which the constant arm beats every real arm at the majority rule and no
   readout can be distinguished. `0.84` was measured on the full source during
   this screen, on the source-derived distribution alone.
4. The registered grid's four configurations are each measured on the full
   source by the balance criterion, and the rule registered in section 4 is
   that argmin rather than a chosen name. During the screen, one of the four
   configurations attained a full-source label rate close to `1/2`; the
   executor re-measures all four and records the one it selects, because the
   screen's own arithmetic is staging code and is not evidence here. The
   registered criterion is what this freeze fixes; the configuration and `T*`
   it selects are a measured fact of the bound source, recorded in the receipt.

Nothing in this appendix asserts an outcome, a class, or a recovery. It exists
so that the registered rule's shape is auditable from the freeze and its
appendix alone.
