# Z2 freeze amendment 1 — the re-encoding group, the specification vocabulary

Committed **before** any executor, oracle, receipt or result file of this package
exists, and therefore before any number this package reports was computed. It
amends `FREEZE_V1.md` §4, §5 (`H7`, `H8`) and §2. `source_main` is unchanged
(`5e57d4292266bccf435136e1f7d72caa32e920a0`), the claim ceiling is unchanged, the
five reconcilable rows are unchanged, and no neighboring row is earned here.

## Why

`FREEZE_V1.md` §4 defined the re-encoding group `G` as generated by a state
relabeling and by index permutations, and `H7` asserted that the semantic-class
partition is invariant under **every** element of `G`. On paper that is wrong,
and the error is instructive rather than cosmetic:

the universe contract fixes the canonical initial state to `0`. A state
relabeling `s -> 1-s` is a genuine involution of the syntactic universe `U`, but
the candidate it produces, started at `0`, behaves exactly as the original
started at `1`. So the relabeling does **not** fix `beh` pointwise, and the
class *membership* of an individual candidate moves. What it does fix is the
multiset of behaviours, hence the class-size histogram.

Stating `H7` over an undifferentiated `G` would have hidden exactly the
distinction row 4 asks about: *which* quantities a P3/P4 derivation may lean on.
The amendment therefore splits `G` into named generators and asks the invariance
question once per generator, so the answer is a table rather than a verdict.

## Amended §4 — the re-encoding generators

Three maps on `U`, each required to be verified a bijection before use:

- `g_rename` — a pure permutation of candidate **indices**, drawn from a frozen
  seed. The mechanism is untouched; only its name moves.
- `g_state` — the state-bit relabeling: `nxt'(s,m,x) = 1 - nxt(1-s,m,x)`,
  `table'(s,m,x) = table(1-s,m,x)`, identity on the stateless block.
- `g_out` — the global output complement: `table' = ~table` on the candidate's
  output truth table, `nxt` untouched.

`g_rename` is a renaming. `g_state` is a re-encoding of the state carrier.
`g_out` is a re-encoding of the output alphabet **that does not preserve the
task targets**, and is included precisely so that the admissible subgroup has to
be identified rather than assumed.

## Amended `H7` — one row per (quantity, generator) pair

The executor reports an invariance table over the quantities

`K`, the class-size histogram, `D_TV`, the multiset of `(e_now, e_delay)`, the
minimum of `J` over the registered `5x4` `(p,eta)` grid, the winning property
class (`STATELESS` / `PERSISTENT_STATE`) on that grid, the per-candidate class
membership, and the canonical-order first-hit index of each class

against the three generators. `H7` is replaced by:

| id | statement | falsifier |
|---|---|---|
| `H7a` | `K`, the histogram and `D_TV` are invariant under all three generators | any one moves |
| `H7b` | the minimum of `J` and the winning property class on the registered grid are invariant under `g_rename` and `g_state` | either moves under either |
| `H7c` | at least one generator moves the minimum of `J` or the winning property class — identifying the non-admissible generator by computation rather than by assumption | all three leave both fixed |
| `H7d` | the canonical-order first-hit index of at least one class moves under `g_rename` | no class moves |
| `H7e` | per-candidate class membership moves under `g_state` | membership is fixed |

The **strongest defensible P3/P4 standard** (row 4) is then read off the table
rather than asserted: a claim is P3-defensible at this scope exactly when the
quantity it is about is invariant under the task-target-preserving generators,
and any claim resting on a quantity that `H7d`/`H7e` show to move is outside
what a P3 certificate licenses.

## Amended §2 / `H8` — the property-first specification language

`FREEZE_V1.md` §5 `H8` required "one fixed primitive set and one fixed
property-first specification language, containing no family-name token". The
language is now pinned exactly, before it is run.

Twelve generic primitive predicates, none of which names a family, form the
vocabulary `V12` (`c` is the current input, `s` the current state, `m` the mode):

```
p01 has_state                       the candidate carries a state bit
p02 out_depends_on_input            table differs for some (s,m) across c
p03 out_depends_on_state            table differs for some (m,c) across s
p04 out_depends_on_mode             table differs for some (s,c) across m
p05 out_constant                    table is constant
p06 next_depends_on_input           nxt differs for some (s,m) across c
p07 next_depends_on_state           nxt differs for some (m,c) across s
p08 next_depends_on_mode            nxt differs for some (s,c) across m
p09 next_constant                   nxt is constant
p10 next_equals_input               nxt(s,m,c) == c everywhere
p11 next_equals_state               nxt(s,m,c) == s everywhere
p12 out_equals_input                table(s,m,c) == c everywhere
```

A **specification** is a conjunction of literals over `V12`: each primitive
appears positively, negatively, or not at all, giving `3^12 = 531441`
specifications. One enumerator, one vocabulary, one grammar digest; the only
thing that differs between families is the literal assignment. `H8` is
unchanged in content and now has an exact search space, which is also the space
null `N3` draws from.

## Amended `N3`

`N3` draws `200` specifications uniformly from the `3^12` space using seeds
`4300..4499` and records how many select exactly the member set of a registered
family. The recovery claim in `H8` is reportable only alongside this count.
