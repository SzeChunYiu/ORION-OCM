### The ecology, registered before it is built

`F29` (`SIGMA_H29R`). Tokenise `D` into its 104,334 whitespace-separated
tokens. The descriptor closure is: for every token `w` and every length `L`
with `2 <= L <= len(w)`, the prefix `w[:L]`. The exact total is

```
T = sum(len(w) - 1 for w in words) = 776,142 descriptors
```

**The stored object is an expert partition with a registered router.** The
token list is split by a content-external, deterministic rule into four
disjoint expert populations: for a token `w` with first character `c`
lowercased, the expert is

```
k = 0 if 'a' <= c <= 'f'; 1 if 'g' <= c <= 'm'; 2 if 'n' <= c <= 's'; 3 otherwise
```

and every descriptor occurrence belongs to exactly one expert, so the four
stored relations are disjoint. The **router** is a registered, query-content
derived, target-independent function of the query descriptor alone:

```
r(q) = (sum(ord(ch) for ch in q) * 2654435761) mod 2**32   mod 4
```

For a query descriptor `q` the **expert-local evidence** is, per expert `k`,

```
ck(q) = the number of stored descriptor occurrences of q belonging to expert k
fk(q) = |Ak(q)|, the number of distinct letters that appear immediately after q
        across expert k's tokens (that expert's continuation fan-out; the trie
        child count of q inside expert k's token trie)
```

and there is **no marginalised table and no pre-computed joint**: the language
of section 5 contains expert-local readouts, READOUTS OF THE ROUTER-SELECTED
EXPERT, and readouts over ALL experts (unions and count-weighted sums), never a
pre-computed mixture distribution.

A task is a query descriptor. The family is **mixture-of-experts / routing
systems**: several stored sub-models exist, and a routing context — a function
of the query, computed before any target is consulted — SELECTS which of them
answers. The protected interface is the decision

```
y(q) = 1 iff f_{r(q)}(q) >= 1
```

**The label is RESPONSE DEPENDENCE ON THE REGISTERED ROUTING CONTEXT:** the
query is positive exactly when the expert the router selects attests a stored
continuation. It is not a readout over a fixed expert and not a union over all
experts: reading a fixed expert (say expert 0 for every query) and reading the
union of all experts are each a large share of the descriptors wrong, and the
router is what decides which stored sub-model is written down as the answer.

Slices, fixed here before any fit: the descriptor list is partitioned by a
deterministic 7:1 rule registered in `FREEZE_V1_SLICE_ADDENDUM.md`, giving

```
n_fit = (T * 7) // 8 = 679,124  >= 100k
n_held = T - n_fit = 97,018    >= 20k
```

which clears the R11 real-scale bar (n_fit >= 100k / n_held >= 20k on a
sha256-bound external REAL source, exact arithmetic, independent oracle).

**Registered design statistics.** The layout statistics of this ecology (the
per-expert token and occurrence counts, the slice sizes, the router's query
distribution, the label's positive fraction, the best arm of each family, and
the seeded constructions) are measured on the frozen constructions and folded
into `FREEZE_V1_SLICE_ADDENDUM.md` and `FREEZE_V1_SLICE_ADDENDUM_R2.md`, which
are committed **before the executor**. Any statistic that does not survive the

position stated and its error attributed to one stage — never silently
adjusted. The frozen prediction, the frozen readout language and the frozen

**One registered property of the design, stated before the outcome because it
constrains how the claim may be read.** The ordering of the routed count arm
against the routed fan arm is CONTEXT-DEPENDENT: in the excited arena
`SEL_CNT>=1` beats `SEL_FAN>=1` by a strictly positive margin at every stage,
and in the unexcited arena the ordering REVERSES. This is a consequence of the

## 5. Grammar

`G_MOE`: a family-blind grammar derived ONLY from the sha-bound bytes of `D`.
The descriptor closure over the token vocabulary (prefixes of length >= 2), the
four-expert first-letter partition of the token list, the expert-local evidence
tables (per-expert occurrence count and per-expert continuation fan-out), the
registered query-content router, and a charged-cost model over expert lookups
and scan cost. No family-level macro, no hand-encoded mixture-of-experts or
routing routine, no reference to any external implementation and no family name
in the generator. Section R03 asserts the grammar contains no
mixture-of-experts macro, and R04 recovers the family from the grammar alone.

**The readout language `R` is closed before any outcome** and registered in
`FREEZE_V1_SLICE_ADDENDUM.md` section 3. It contains, at minimum and stated
here so it cannot be read after the fact:

- the constant arms `C0`, `C1` and the length arms `LEN<=6..12`;
- the **router-selected (sparse) family**: `SEL_CNT>=1`, `SEL_CNT>=2`,
  `SEL_CNT>=3`, `SEL_FAN>=1`, `SEL_FAN>=2`, each reading ONLY the expert the
  router selects;
- the **fixed-expert family**: `E0_FAN>=1`, `E1_FAN>=1`, `E2_FAN>=1`,
  `E3_FAN>=1`, and the matched count readouts `E0_CNT>=1`, `E0_CNT>=2`,
  `E0_CNT>=3`, `E1_CNT>=1`, `E2_CNT>=1`, `E3_CNT>=1`;
- the **union / continuous-reweighting family**, reading ALL experts:
  `UNION_FAN>=1` (`f_k(q) >= 1` for some `k`), `UNION_FAN>=2`,
  `UNION_CNT>=1`, `UNION_CNT>=2`, `UNION_CNT>=3` (`sum_k c_k(q) >= t`),
  `TOPK2_FAN>=1` (fan-out at least 1 for one of the two experts with the
  largest stored occurrence count, ties by smaller index), and `WSUM_FAN>=1`
  (`sum_k c_k(q)*f_k(q) > 0`, a count-weighted reweighting over all experts);
- the admitted membership arm `MEM_FALLBACK`: **if** the query is present in
  the store (`sum_k c_k(q) >= 1`) it answers the store's own predicate for the
  query, which on the store's routed expert is `1 if f_{r(q)}(q) >= 1 else 0`;
  **else** it answers the fit-majority constant `M`, a two-valued constant read
  from the committed receipt and never hardcoded. The fallback branch is
  load-bearing and reachable: it is taken on every query the store does not
  contain, and the executor asserts that at least one registered query takes it.
  Without that branch this arm would be the same code path as `SEL_FAN>=1`
  under another name.

### The registered predicate identities, and the rules that govern them

Two distinct predicates can coincide on this ecology, and two registered arms
can even agree at every evaluated stage. Both cases are registered here with
their reason, because neither is an accident of the data that a reader could be
expected to re-derive.

**Rule 1 — the alias rule (new in this package).** Two committed arms whose
decision functions are identical at every registered stage and every query are
**one readout registered under two names**: the language counts the readout
once, the second name is recorded as an **alias**, and the alias is not a
competitor for either the winner slot or the runner-up slot. This rule is
registered as a NEW rule with its own justification — "two names for one
predicate are one readout" — and **not** as an inherited sibling practice.
No sibling package's freeze carries a rule of this shape; it is stated here
because a shipment whose "runner-up" is an alias of the winner's own predicate
misrepresents the language, and because error-count agreement between two names
is not evidence that they are two arms.

**Rule 2 — the neighbouring, different, merged precedent.** The sibling
`gmi-833-h-real-scale-decision-trees-v1` registers a *constant-branch exclusion
rule* in its `FREEZE_V1_SLICE_ADDENDUM.md`: a membership readout with a majority
fallback whose stored branch reads out a CONSTANT is excluded from the
enumeration, because on a held query its stored branch cannot separate. In that
package the rule eliminated nothing (its stored branch reads a two-valued stored
label, so it is admitted and the winner rule then rejects it by the data). It
is cited here for the CATEGORY only — arms are pruned from the language
enumeration before the winner rule runs — and it is a DIFFERENT rule with a
DIFFERENT trigger: H08's trigger is a degenerate stored branch; Rule 1's trigger
is identical decision functions across two named arms.

**Rule 3 — distinct predicates that coincide on this ecology.** A registered
arm may share a decision function with another arm on this data while remaining
a distinct predicate, and such an identity must be listed here with its reason,
not discovered after the outcome. Two such groups are registered:

- `TOPK2_FAN>=1`, `UNION_FAN>=1` and `WSUM_FAN>=1` are three DISTINCT
  predicates (a top-two routing choice, an any-expert union, and a
  count-weighted sum `sum_k c_k(q)*f_k(q)`) that coincide on this ecology
  because no query has a positive stored count with a zero stored fan-out:
  wherever `c_k(q) > 0` we have `f_k(q) >= 1`. They stay registered as separate
  arms; the coincidence is a measured property of this ecology, not an identity
  of the code.
- `MEM_FALLBACK` and `SEL_FAN>=1` are DISTINCT predicates — `MEM_FALLBACK` has
  a fallback branch that `SEL_FAN>=1` does not, so they are separable by a
  store whose majority constant is `1` on a query the store does not contain,
  and the test suite exhibits exactly such a row — but they coincide on all
  four registered stages, because every registered stage is majority-negative
  (the store's majority constant is `0` at every stage) and the fallback's
  branch therefore returns the same `0` that the routed fan-out returns on a
  descriptor the store does not contain. Under Rule 1 they are therefore ONE
  readout for the winner and runner-up ranking at these stages, and the alias
  is recorded rather than counted. The identity does not decide the winner:
  `SEL_CNT>=1` beats both by a strictly positive margin at every stage
  (section 9).

**The governing check.** A test asserts that no pair of registered arms whose
identity is NOT listed in this section resolves to identical decision sequences
at any registered stage, AND that the two listed groups are what this section
says they are: the union trio distinct as predicates, and `MEM_FALLBACK`
distinct from `SEL_FAN>=1` by a constructed counterexample row. The check is on
the decision sequences and on the predicate branches, never on the error
counts.

## 10. Controls

Matched negative control (`R05`): a shuffled-label null with equal sample size
on the identical slice rule must perform at chance; and a **global** design
null must exceed three times the winning arm's error count while leaving the
non-target arms bit-identical.

**The unexcited-context control — the registered control of this row.** It is
registered in two forms, and the PRIMARY form is `B'`: the readout language,
the winner rule, the expert partition, the store, the slices and the query sets
are held fixed, and the only registered coordinate that moves is the ROUTING
CONTEXT — the router `r(q)` is replaced by the constant context `r0(q) = 0`
while the protected label stays `y(q) = 1 iff f_{r(q)}(q) >= 1`. The
requirement is:

- every routing-free arm (the fixed-expert and the union families) must be
  **decision-identical between the two arenas** at every stage — the context
  change must move the routed arms and nothing else;
- each router-selected arm must COLLAPSE ONTO ITS MATCHED FIXED-EXPERT
  COUNTERPART: `SEL_CNT>=t` against `E0_CNT>=t` for `t = 1,2,3`, and
  `SEL_FAN>=t` against `E0_FAN>=t` for `t = 1,2`, with **zero decision
  mismatches** and therefore equal error counts;
- the routed arm's margin over the best routing-free arm must be strictly
  positive in the excited arena and must VANISH (be exactly zero) in the
  unexcited arena.

`B'` is the registered form because it is the one that isolates the context as
the single moving coordinate. The first specification of this control was
internally inconsistent and is recorded here as a correction rather than
silently replaced: it redefined the protected label in the unexcited arena
(`y0(q) = 1 iff f0(q) >= 1`) while simultaneously demanding that routing-free
arms stay bit-identical — and those two requirements cannot both hold, because
the label is itself a function of the context and the two labels disagree on
306,000 of the 776,142 descriptor positions. The primary form therefore holds
the label at `y`; the label-perturbed reading (`arena B`) is registered as a
SECONDARY reading only, with that label change named as its confound, and is
reported as such in `REAL_RUNS/`. Both forms are measured and both are
committed; neither is substituted for the other after the outcome.

A control that fails to collapse the advantage does not close this row: it
would mean the advantage is not attributable to the registered routing context.

The screen asserts `CLEAN` only when the no-alarm case also fires.
