# Goal-only cold-process lifecycle: prospective development v1

## Question and boundaries

Can the accepted ordinary prover, given only a goal, hypotheses, typed context and
fixed limits, consume the already qualified historical 22-method library in a
fresh native-checked proof? Does resident disabling remove a bounded proof-decision
benefit, and does restoring exactly the same eligibility restore the result?

This is the next **ordinary-parent development integration**, following
`research/programme/ORDINARY_GOAL_SEARCH_NEXT.md`. It is not a replacement OCM,
OCM-specific treatment, protected independent evaluation, or programme completion.
Real OCM evidence withdrawal is not simulated by renaming a local eligibility bit:
this caller makes only a conventional library-eligibility intervention.

The three review perspectives here are formal semantics, implementation/custody,
and experimental design, applied by one author. There is no claim of independent
expert review or independent replication. The reviewable PR is a draft.

## Prospective development allocation

`allocation.py` is outside the worker's permitted sources and inputs. It generates
all fully parenthesized three-operation terms over three class parameters A, B, C
using intersection, union and difference, requiring all three parameters in each
term. An independent eight-assignment membership table distinguishes equality from
inequality. The table is not a proof route and never enters the solver.

Positive pairs have equal membership tables. Whole statements already present as
unconditional three-class-parameter assertions, including simultaneous variable
renamings, are excluded from the frozen source index. This excludes direct statement
retrieval, **not** every ordinary one-step substitution or derivable shortcut. The
complete ordinary parent keeps those powers. Equivalent goals are canonicalized
under simultaneous variable renaming and equality reversal. A deterministic SHA-256
order with the fixed source salt selects at most eight positives, at most one per
ordered-operator/tree-shape family; two unequal-table controls are selected separately.
The ten-task maximum is an engineering budget, not a statistical sample-size claim.
All readiness counts are retained before solving. No unavailable member is backfilled.

This finite constructed set-algebra distribution is not natural-language competence,
a cross-domain result, or a held-out independent lifetime. Semantic equivalence of
terms is not evidence that their proof families are independent. No official proof,
target theorem label, expected route, solver outcome or acquired-cut-shaped template
participates in allocation. The original acquisition traces were not constructed
for this successor's goals. The inherited methods themselves are supplied prior
information to both ordinary-parent arms, with their acquisition costs still unpaid.

Source, salt, grammar, exclusions, limits and scoring must be committed before the
first search on this allocation. The only earlier new runs use the explicitly
synthetic authored fixture. Do not revise the allocation or limits to rescue an
exposed result. An integration failure is retained and gets a separate source
version; it does not become an independent scientific replicate.

## Execution and cost contract

Each arm starts a different Python interpreter with `-I -S -B`, no stdin, a minimal
environment, exact interpreter/stdlib bindings, a source-only loader, and explicit
permitted file reads. A Python audit hook rejects undeclared reads, writes outside
the output, network operations and child-process creation. It is a reviewed-Python
execution boundary, **not a security sandbox for arbitrary hostile native code**.
Operating-system address-space, CPU, file-size and parent-enforced process-group
wall limits are recorded. Source/input identities are rechecked after execution.

One immutable source/library/task population is staged. The controller persists
three linked, fsynced eligibility versions: enabled, resident-disabled, restored.
Each worker independently reconstructs the Library from disk. All three retain the
same resident C, syntax banks, grounding and syntax materialization. Only eligible
C actions differ. Every row is bound to the issued task and actual worker process;
all native requests, databases, receipts and logs are retained and reconciled.

Per task: maximum 3 abstract proof-tree decisions, 100,000 grounded instances,
2,000,000 token states, soft 8-second solver wall. Per arm: hard 150 seconds,
2,000,000,000-byte address-space bound; no checkpoint claim implies preemption of
an arbitrary inner operation. A worker timeout ends the sequence as incomplete.

Report all tasks, all three arms, proof decisions, attempted work, native calls,
CPU, wall, peak RSS, bytes staged and materialized, and failed attempts. Peak memory
is not additive. Nested phase timings must not be added to enclosing process wall.
The fixed enabled/disabled/restored ordering supports restoration engineering, not
an unbiased wall-time speed estimate. Historical acquisition, preparation and
engineering attempts are not declared recovered by any warm-query improvement.

## Outcome rules

A proof is a success only at `GENERATED_PROOF_NATIVE_VERIFIED`, after current native
request/result/trace/USED binding. Count selected-proof consumption, not merely a
cohort action attempted during grounding or failed search.

A bounded causal decision witness requires identical preparation and restored
result, actual cohort use in both native-verified enabled/restored proofs, and either
strictly higher verified disabled proof-decision cost or complete supported finite-
bank absence in the disabled arm. UNKNOWN, timeout, unsupported parent scope and
native-check failure are **not** evidence that removing the method reduced capability.
A finite-bank negative is not global unprovability. Native proof of a negative-table
control is an inconsistency requiring investigation, never a success metric.

No-use, parent-sufficient, harmful-transfer, bounded absence and incomplete execution
are all retained results. No positive architectural, lifetime-economic, generalized
learning, G4-G8 or full OCM claim is admitted by this development run.

## Conditional foundation and falsifiers

**Conservative extension.** Assume the unchanged native verifier is sound for the
issued Metamath scope and each cohort lemma has a verified proof in the base. Adding
those lemmas as ordinary actions cannot create a logically false theorem: expand
each lemma application by its proof and typed substitution; sound inference is
closed under composition. Actual native validation remains necessary, including
mandatory hypotheses and distinct-variable obligations. This interface deliberately
refuses unsupported DV/type cases; the proposition does not expand that scope.

**Finite decision-cost monotonicity.** With the same fully grounded bank and positive
unit action costs, enabling a set C of actions cannot increase the *minimum* proof-
tree decision cost: every disabled derivation is also enabled. Induction on tree
height gives inclusion of derivable trees and hence the minimum inequality. This
does not say enabled search takes less CPU or finds a proof before the same deadline;
additional actions can make search slower or exhaust a budget. Those failures stay
UNKNOWN. The witness checker therefore cannot treat missing verification as a win.

**Membership oracle.** For any element x, membership in A, B, C gives one of eight
Boolean assignments. Structural induction on the term grammar makes membership in
intersection/union/difference equal conjunction/disjunction/and-not respectively.
Equal tables therefore establish extensional equality for this grammar; unequal
tables give a one-element countermodel. This is a bounded semantic oracle, not a
Metamath proof and not a solver hint. The final machine claim still requires native
proof construction without access to that oracle.

**Intervention identification.** Exact source/input equality and recorded equal
preparation control these measured confounders; disabling C changes only logical
action eligibility in the inherited mechanism. Equal enabled/restored checked proofs
and strictly worse *verified or complete-bounded* disabled behavior support that
scoped intervention. They do not establish an OCM residual against the same ordinary
library or statistical causality over independent developmental lifetimes.

Falsifiers include source drift, changed banks, stale state/request identity, missing
rows, forged use, false native acceptance, unsupported negative inference, restored
behavior mismatch, and utility lost after all costs are charged.

## Intellectual parents

The mechanism reuses the repository's accepted finite ordinary prover, exact syntax
memoization, native proof checking and goal bridge rather than inventing a new core.
Classical Metamath typed substitution and distinct-variable conditions are described
in the official Metamath book and set.mm documentation. Library compression and
search utility remain separate, as the repository's Stitch and REFACTOR reviews
already require; the neural extraction machinery of REFACTOR is not used here.
