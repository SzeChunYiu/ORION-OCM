## Mechanisms and predictions

H1: retaining exact semantic search state reduces repeated synthesis work across
distinct polynomial tasks versus restarting current OCM search. The baseline
already learns fragments where available; both primitive and learned schedules
are measured. Falsifier: no cost improvement at identical verified coverage,
after construction, final checking, checkpoint and replay charges.

H2: collapsing equivalent polynomial prefixes preserves reach within the
registered primitive-length limit. Independent raw-word interpolation checks
the complete length 0..3 worlds. Falsifier: any missing reachable target, invalid
witness, incorrect shortest depth, or false bounded exhaustion.

H3: the incremental semantic algorithm is a conventional parent that OCM can
adopt. A parent using precisely the same kernel is equivalent by construction;
this is an explanation, not a fabricated head-to-head result. A separately
implemented inverse-search parent is also measured. No claim of superiority
over all synthesis algorithms, novel cognitive primitives, acquired abstraction
transfer, or general OCM superiority is admissible.

## Registered ecology and separation

Grammar: inc, dec, double, square; rational univariate polynomials, exactly the
existing OCM semantics. Maximum primitive program length 4 for evaluation.
The oracle alone enumerates all raw words through length 4 and deduplicates
exact coefficients. Arms receive only the current task, never the oracle table.
Training: first 12 distinct tasks of shortest length exactly 3, ordered by
mathematical fingerprint. Evaluation: every distinct task of shortest length
exactly 4, ordered then shuffled with seeds 4101..4108. Thus training and target
mathematical identities are disjoint. Development tests are confined to length
0..3; these are disclosed calibration, never promoted into held-out results.

No target outputs have been inspected before this protocol is committed.
Code repairs after first evaluation preserve raw runs and receive a corrigendum.

## Arms and lifetime

1. Current OCM primitive enumeration, fresh search for every problem.
2. Current OCM learned-fragment enumeration, acquired from the same training
   problems with the existing `learn_generator` routine.
3. Semantic BFS with reset before every target (compensation-aware persistence
   ablation; it retains within-query semantic deduplication).
4. Persistent semantic BFS, plus a durable checkpoint and fully charged replay
   halfway through evaluation. It always rechecks each returned witness.
5. Exact inverse synthesis, with its own memoization within each query.

All arms solve the 12 training tasks and pay their own acquisition work; only
arm 2 mines fragments. Every arm can use the full grammar, exact target
coefficients and the same exact answer checker. Primitive/guided slot caps are
2*(1+4+16+64+256)+2; semantic/inverse transition caps are 100000 per query.
These caps ensure feasibility; they are not claimed equal units of work.

The single-query negative twin starts each arm cold on one of the first eight
evaluation fingerprints, with no training and an empty guided library. This
tests persistence amortization, not absence of all within-query benefits.
Persistent and reset semantic kernels should have identical query work before
any checkpoint cost. Changed grammar/semantics and no shared structure are
NOT TESTED; snapshot namespace mismatch is a correctness test only.

## Measurement and gates

Primary: verified coverage, then the resource vector at matched coverage.
Record all candidate/transition work, exact coefficient additions,
multiplications, divisions/root calls where used, probes, final answer checks,
serialized bytes, read/write bytes, restart work, wall and process CPU time,
and process peak RSS. Fraction operations are algebraic counts, not unit bit
complexity. RSS is subprocess high-water memory, not live field size. No
arbitrary weighted aggregate or universal speedup is inferred.

Each arm runs in a fresh subprocess. Wall/CPU encompasses construction,
training, learning, queries, mandatory verification, checkpoint write/fsync,
read and restore. Benchmark oracle generation and reporting are outside the
solver measurement, identical and unavailable to arms. Source/import overhead
is reported through external subprocess elapsed time. Record per-query hits
and expansions: a distinct target can already be in an earlier search index.

Report all eight orderings, medians and ranges; these are order/timing
sensitivity runs on one finite ecology, not independent domain replications.
No statistical population or cross-domain inference. Any incorrect result
fails the improvement gate regardless of speed. Unreachable fractional target
and interruption, reset, tamper and restart checks belong to exact calibration.

## Runtime boundary and interpretation

The search index stores recomputable mathematical proposals, not permission to
reuse revoked learned-generator warrant. It uses no detached governed generator.
The authoritative OCM answer checker remains mandatory. A separate integration
receipt exercises `admit_solution`, persist/restart, support revocation and
replay. This demonstrates compatibility, not faster whole-runtime cognition.
An optional timed integration profile is reported separately with all custody
costs, never added selectively to a comparator.
