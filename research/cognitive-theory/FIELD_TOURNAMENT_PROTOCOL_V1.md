# First field tournament: prospective design V1

Status E0 / L0, NOT EXECUTED. This is a frozen design proposal, not an E3-ready protected protocol. No field winner is predicted. Owners: #145 GUO-D5; #143 CL-0/CL-6; #93. Question: do different physical representations preserve the same alternative-support lifecycle, and where do their complete cost vectors differ?

## First exact stage (V2)

Use m=1 and m=2 independent copies of W2. Each copy has support tokens a_i,b_i and q_i with alternative sufficient supports {a_i} or {b_i}. Register all 2^(2m) live-support assignments and each named revocation; all future sequences collapse to the finite set of withdrawn-token subsets. This first exact stage is deletion-only. **Restoration is PENDING a separately frozen finite identity/horizon contract:** repeated fresh token identities would make the claimed state universe unbounded. Any restoration extension must bind a finite token universe/horizon or justify an identity quotient under C, then check the full finite system rather than deletion subsets alone.

Three arms encode precisely the same logical information:

1. Relational tables for objects, supporting environments and environment membership, with forward and reverse indexes available.
2. Typed adjacency graph with explicit support-environment nodes, preserving AND-within / OR-between environments, with equivalent indexing permission.
3. Incidence hypergraph with explicit hyperedge/support identities and equivalent reverse-incidence indexing permission.

The strongest parent is the indexed relational support store with ATMS-style validity evaluation and identical external C. All arms use the same scheduler, event stream, query contract, cost definitions and allowed caches. A separate co-design study may vary controllers later; it must not be mixed into this representation intervention.

Decoded states and required output traces must match on **100%** of the finite states/events, with zero stale and collateral validity errors, before resource comparisons are interpretable. A support-specific certificate is not silently equated to conclusion validity. The selected-certificate replacement rule must match C in W2 or receive a versioned new contract.

## Negative/control families

- Query-only two-class quotient: retaining the full support distinction is unnecessary when no future revision is permitted.
- Alternative-support case: one withdrawal changes warrant availability without invalidating q.
- Conjunctive case q requires {a,b}: one withdrawal does invalidate q. This changes the logical rule explicitly and must be supplied to every arm.
- Shared global support: g is necessary for every q_i, so withdrawing it invalidates all conclusions. Locality is not universal.
- Scan/recompute parent: permit exact recovery by scanning retained support records and charge its work; do not call a missing index an impossibility.
- Rebuild-after-each-event mutant: same query touches, greater maintenance, retained as a cost-control example.
- Label permutation and serialization round trip: preserve decoded semantics and external identities.

## Measurements

Record logical state counts separately from serialized and resident bytes; object/edge/index reads and writes; comparisons; operator/search/checker calls; build, migration, query, revision, restoration, cache invalidation and maintenance work; peak memory; restart reconstruction; and cumulative lifetime resource vectors. Distinguish candidate dependency cone, touched cone, changed support labels and conclusions losing all support. All static code, rules, schemas, initial data and indexes are prior information. Dependencies are supplied here: the study does not test their discovery.

For a later exploratory scale pilot, proposed block counts are 1,3,10,30,100 with separate unrelated-block and globally coupled families. Derive per-coordinate crossover Q* from measured build/maintenance and per-query deltas only when the denominator has the appropriate sign; retain 'no crossover'. There is no weighted overall score or universal-winner rule.

## Compensation and falsifiers

After removing an index or field feature, permit reconstruction from all retained information within a registered compensation budget. Report certified optimum only in completely enumerated finite classes; otherwise report best-found compensation and CANNOT_CHECK for necessity. Give the parent the same caches, observations and authority wrappers.

Any decoded lifecycle mismatch kills equivalence for that implementation. Any advantage disappearing against the indexed relational parent is PARENT_SUFFICIENT at that coordinate. If gains trade storage/build cost for cheaper queries, report a Pareto tradeoff, not a free cognitive gain. If global support invalidates everything, report global revision as required by the semantics.

## Gates still missing for V3 / #144

The exact stage can be implemented in the isolated theory lane. A protected scaling/transfer study still needs independently authored families, frozen generator and split commitments, exact source/environment identities, complete comparator configurations and tuning budgets, independent-unit/statistical plan, power/precision and capability margins, exclusions/timeouts/multiplicity, human accountability and disjoint/fresh-host replication. This proposal freezes no protected seeds and grants no protected access.

Next decisive test: implement the three finite encoders plus an independently authored common semantics checker and verify complete trace parity. Only then freeze an outcome-unseen scaling protocol. Controlled language, coding and heterogeneous-domain holdouts remain unopened.
