## Overcomplete typed catalogue

All records are candidate contracts, not implemented primitives. Input and output types are logical specification types. Every candidate carries identity/version, preconditions, reads/writes, observable events, costs and external acceptance obligations before admission.

| Candidate | Typed input -> output | Effects and reduction hypothesis |
|---|---|---|
| FOCUS / RETRIEVE | field, query, scope -> candidate identity set, completeness status | Reads/index work; no warrant update. Split retrieval, ranking and executive selection. Soar/index parent. |
| DECOMPOSE | goal contract, method candidates -> subcontracts, sufficiency obligation | Proposal only until checked. Scheduling belongs to Pi; subgoal formation may be this plus FOCUS/CHECK. |
| EXPAND / GENERATE / SEARCH | frontier, grammar, budget -> candidate terms and search receipt | Enumerates proposals; cannot infer absence without completeness. Distinguish generator from search policy. |
| COMPOSE | typed programs, interface obligations -> candidate composite | Program construction differs from executing a sequence. Admission is external; ordinary composition/compiler parent first. |
| DISTINGUISH / PROBE | live alternatives, allowed information channels, decision -> probe proposal or unresolved terminal | Probe selection and probe execution are different effects. Observation access is additional information, not a renamed transform. |
| RE-REPRESENT | encoding, task contexts -> new encoding, decoder/correspondence, proof obligations | Preserve required trace semantics; migration and code costs count. Refinement and lossy abstraction are not synonyms by default. |
| CHECK / VERIFY | candidate, specification, evidence, checker identity -> verdict plus scoped receipt | Verdict types include accepted/rejected/unknown/unavailable; checker cannot silently become proposer or adoption authority. |
| REVISE / REOPEN | authorized event, support structure -> revised supports, changed warrants, pending obligations | Split support withdrawal, validity recomputation and reopening schedule. ATMS/TMS + external C first. |
| CONSOLIDATE / GENERALIZE_METHOD | scoped episodes/programs -> candidate macro/schema and applicability obligation | Split compilation, scope generalization, evidence aggregation and forgetting. A compact token is not an irreducible semantic primitive. |

The split effects improve measurement; they do not introduce additional primitives. No two labels are declared exact synonyms without semantics and lifecycle equality. SEARCH_MORE, JUMP, FAILURE_LEARNING, ANALOGIZE and GENERALIZE remain composition hypotheses with unspecified pieces, not identities established by naming a sequence.

## What can be removed from claims now

- Remove novelty from states-plus-operators, one shared executable graph, chunking, library learning, probe selection, indexed retrieval and reason maintenance alone.
- Merge expanded macro tokens into the existing semantic closure when their expansion is faithful; retain any measured search/native-runtime advantage separately.
- Replace fixed-threshold 'basis equivalence' with costed compilation compatibility until the overhead class is closed under composition.
- Replace deletion-only 'minimum basis' claims with inclusion-minimality unless all registered compensations/subsets were checked.
- Preserve epistemic irreducibility as a comparison of answer and lifecycle contracts; strike a claim that it is an independent absolute mathematical category.
- Separate donor/literature saturation, bounded search completeness and finite primitive-pressure zeros. None implies either of the others.

These are changes to this packet's vocabulary and claim scope. No production concepts or existing programme terminals have been deleted or reopened.
