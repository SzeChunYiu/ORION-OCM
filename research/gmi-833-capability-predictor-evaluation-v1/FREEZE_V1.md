## 2. What is frozen

### 2.1 The predictor is not modified

`F` is the parent module `research/gmi-833-capability-predictor-v1/capability_predictor_v1.py`
at blob `7f1bb6808901be2291bf575ee3178247d14d01d4`. This package never edits it.
The held-out populations are installed by rebinding exactly the enumerated
`REGISTRATION_SURFACE` (23 names: the universe, its search order, the capability
tables, the registered grids and the cut masks). Two independent proofs that
`F`'s code is untouched are recorded in `FROZEN_PREDICTIONS_V1.json`:

1. the git blob sha of the parent file, and
2. a sha256 over the `co_code` of every function and method in the parent module
   (138 code objects), captured before and after every installation.

`BETA`/`BETA_SUM` are deliberately *outside* the registration surface: they are
the U-2B composition premises that `TypedUncertainty.__init__` validates, and
they are the contract the calibration row is measured against.

### 2.2 Three held-out registered universes

| universe | realizations | mechanism | disjointness separator |
|---|---:|---|---|
| `SIGMA_SYN` | 64 | modular head machines (state = ones mod m, m ∈ {1,2,3,6}) | `rho[3] ∈ {1,2}` |
| `SIGMA_ARCH` | 128 | four named architecture families: `FF` window, `REC` recurrent accumulator, `CTR` saturating counter, `STK` bounded stack | `rho[3] ∈ {3,4}` |
| `SIGMA_REAL` | 32 | real trained torch systems: `MLP`/`GRU` × width {2,8} × register {0,1} × trained-head set {1,3,5,7} | `rho[3] ∈ {5,6}` |

The parent universe `SIGMA_1` has `rho[3] = 0` on all 32 realizations, so the
four populations are pairwise disjoint by a single separating coordinate. The
exhaustive pairwise descriptor comparison (64×32, 128×32, 128×64, 32×32,
32×64, 32×128) is recorded as the independent second route, with
`descriptor_collisions = 0` in every pair.

### 2.3 The registered grids and the complete prediction stream

Each universe carries a registered input grid of exactly **51,840** inputs
(8 expressivity sets × 6 resource pairs × 3 development budgets × 5 search
budgets × 3 observations × 3 typed uncertainty inputs × 2 contracts × 4
thresholds). Every prediction is generated by
`freeze_predictions_v1.py`, which imports the parent and cannot observe any
outcome. The complete stream is bound by sha256 in `FROZEN_PREDICTIONS_V1.json`
(`predictions_sha256` per universe); `FROZEN_PREDICTION_SAMPLE_V1.tsv` carries
every 101st row for human inspection. The scorer regenerates the stream and
refuses to proceed unless the sha256 matches.

### 2.4 The per-case order class is frozen NOW, not after the confusion matrix

For every one of the 3 × 51,840 inputs the freeze records whether the ladder
label is `ORDER_FREE` (all 120 cut orders agree), `CONJUNCTIVE` (they do not, so
no order-free attribution exists — the KP-2D regime) or `NO_CROSSING`. The
qualitative-failure confusion matrix is reported separately on each stratum.
Deciding this partition after seeing the matrix would be an excuse mechanism;
it is decided here.

### 2.5 The quantitative curves

`FROZEN_PREDICTIONS_V1.json` carries 8 registered curve cases × 4 thresholds ×
3 universes, each sweeping the resource coordinate `R.budget` across all three
registered budgets, with the predicted disposition, point and identified set at
every swept point.

### 2.6 The real-system protocol

Frozen here in full, before any training run exists:

- source: `/usr/lib/python3.8/argparse.py`, 96,311 bytes,
  sha256 `cc1e3c3a7cb538c32270a77b6f62ac7e91ff5b5a9261607ccbb3e6afe57c44f7`;
- protected battery: length-12 binary words, bit = `byte & 1`, windows
  `[0,6000)` for training and `[6000,8000)` for the protected split — disjoint
  by position;
- 32 systems, seeds by the rule `8317 + 101*mech_index + 17*size + 3*w + task_index`,
  torch CPU, one thread, Adam, lr 1/1000, 400 epochs, batch 256;
- a task counts as solved only at **exact** accuracy `Fraction(correct,total) == 1`
  on the protected split;
- the registered solved-set law `real_solved_law` is a falsifiable *prediction*
  about real training outcomes and is recorded per system in
  `real_system_protocol.registered_solved_bits`.

Registration truthfulness (measured solved-set == registered solved-set) and
`F`-soundness are reported as **two separate numbers**. Per the parent boundary
KP-1D, a registration failure is attributed to the bridge, not to `F`, and `F`
is scored on the truthfully-registered subset with the failure count stated in
the open.

## 4. Falsifiers registered in advance

- any point emission on a held-out universe whose value differs from the
  externally evaluated capability of a consistent realization (a **soundness
  violation**; this would be the headline result of the tranche);
- disagreement between the closed-form registered capability law and
  brute-force simulation of the protected battery on any machine;
- an empirical coverage below the U-2B lower bound `1 - alpha - sum(beta)` on
  any stratum of the registered fault law;
- a curve point whose externally evaluated capability contradicts the frozen
  predicted point;
- a prediction stream whose sha256 differs from the one pinned here.
