## Serving mechanism (root-cause change)

Underlying tokens remain exactly:

```text
inc
dec
double
square
```

Search generates each 4-primitive word of length ≤ bound **once**. A learned
fragment `f` is a rewrite rule: greedy leftmost non-overlapping occurrences of
`f` collapse to one operator. Operator-cost is the rewritten length. Programs
are then visited in

```text
(operator-cost, rewritten-first, original 4-ary index)
```

so a sequence matching `f` is replaced by one operator step instead of being
re-encoded as an extra token in a 5-ary product.

The primitive parent (`K_0`) is the same algorithm with no rewrite, which
reduces to ordinary 4-ary BFS and matches `M.solve` attempt/program order.

Because every complete word is a 4-primitive program and is generated once:

```text
enumeration_attempts == unique_candidates_checked
```

Duplicate 5-ary tokenizations cannot inflate compute. Grammar width stays 4.

This is conventional library/rewrite serving (Stitch / DreamCoder / #192
operator replacement), not an OCM architecture novelty claim.

## Arms

1. `K_0` — primitive 4-ary grammar (reset).
2. `ORDINARY_PERSISTENT` — admitted fragment stored/reloaded from ordinary atomic JSON; same rewrite serving.
3. `OCM_LIVE` — same fragment as a procedure object; persist/restart before later tasks.
4. `OCM_REVOKED` — training evidence revoked; later search must equal `K_0`.

Ordinary parent receives the identical fragment and exact rewrite search.
Later-task savings against reset, if any, are therefore `PARENT_SUFFICIENT`
versus a persistent program-library rewrite.

## Lifetime capital

`C_acquire(T_j | K_t)` is later-task search given an already-earned library.
Library capital (training search + every candidate's validation search + persist
bytes + training demonstrations) is reported separately.

A first-class negative is recorded, and salts/counts are **not** retuned, when:

- later-task compute is not strictly cheaper than reset (`NO_AMORTIZED_ACQUISITION_LATER_NOT_CHEAPER`);
- or library capital exceeds later-task savings (`LIBRARY_ACQUISITION_EXCEEDS_LATER_SAVINGS`).

H1 boxes are earned per charged coordinate, not by pooling unlike units. The
vector inequality is false unless every charged later-task coordinate strictly
improves.
