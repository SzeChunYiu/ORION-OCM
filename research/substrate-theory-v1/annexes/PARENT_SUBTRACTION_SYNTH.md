# Parent-Subtraction Research Brief — Program Synthesis, Library Learning, and Economic Machinery for OCM

Scope: 9 fields x parent-subtraction. Every idea answers the six canonical questions. OCM findings bound below as F1–F5; u-fields = <Z, I, φ, β, Ψ, V, W, C, L, P>.

**OCM binding key (live findings):**
- **F1** Fragment LIBRARY helps only when SERVED through applicability (which-fragment-helps-where); retrieval timing null.
- **F2** History induces a genuine SEARCH PRIOR on authored ecologies; stored answers worth zero; shuffled history worse than none. Admission law: a learned generator is admitted iff its library recovers ALL ground-truth motifs.
- **F3** Library mining ranks by (support desc, length desc); fails when motifs share substrings; learnability condition = pairwise substring-disjointness derived.
- **F4** Learned structural APPLICABILITY (field I) is the standing gap.
- **F5** Cost ledger: capital vs marginal accounting; amortisation crossing tests in flight.

## §1 Program Synthesis & CEGIS

### 1.1 CEGIS (counterexample-guided inductive synthesis)

1. **OCM gap addressed:** F2 (history-as-search-prior) and P (causal support). CEGIS is the canonical mechanism by which a *verifier's counterexamples* — not stored answers — compress the hypothesis space. It explains F2's "stored answers worth zero": answers are only useful through the constraint they place on future search (discriminating counterexamples), never as artifacts. Also feeds β (termination/fallback = verification success) and W (each candidate's warrant = the counterexample set it survives).
2. **Strongest parent:** Solar-Lezama, *Program Synthesis by Sketching* (PhD thesis, Berkeley 2008); Jha, Gulwani, Seshia, Tiwari, "Oracle-Guided Component-Based Program Synthesis" (ICSE 2010) — the CEGIS loop as oracle-guided narrowing.
3. **Mathematical object to assimilate:** The CEGIS fixed point: alternation of SYNTH(φ, cons) → candidate c, and VERIFY(c, spec) → counterexample x violating c; cons grows monotonically; termination when VERIFY returns valid. Formally a two-player reachability game solved by iterative under-/over-approximation of the solution space. The valuable residue is the *counterexample as constraint*, i.e., value flows only through the discriminator set D ⊆ inputs, not through solutions.
4. **Novel after subtraction:** Almost none of the loop. CEGIS already: uses failures as search constraints, terminates on verification, treats examples as tests not artifacts. Residue: OCM's insight that the *constraint stream is the unit of P (causal support)* and that counterexample *selection* has marginal cost C and expected value V — CEGIS picks arbitrary distinguishing inputs; OCM could charge C and rank by V (this collapses into §8 Bayesian experimental design — see 8.1; "CEGIS with optimal counterexample selection" is the same object as active learning of discriminators).
5. **Minimal implementation in OCM terms:** Replace "store solution fragments of solved tasks" in the history with "store the counterexample/discriminator stream per unit"; W of a unit carries its surviving-constraint set; P becomes the count/provenance of constraints that actually narrowed a later search (measurable: search-nodes-pruned attributed to each constraint).
6. **Falsification:** Knockout: replace CEGIS-constraint history with answer history (F2 already shows answers ≈ 0); transplant: run identical φ with (a) random counterexamples, (b) maximally-discriminating counterexamples (8.1), on authored ecologies with known motifs; terminal readout = search-nodes-to-solve distribution. If (a)≈(b), the "constraints not answers" mechanism adds nothing over mere iterated sampling — the P-as-constraints framing is costume.

### 1.2 Bottom-up enumeration + observational equivalence (enumerative synthesis with memoized terms)

1. **Gap addressed:** F3 (mining collisions on shared substrings) and the dedup/normal-form machinery underlying F2's admission law. Bottom-up synthesis prunes by *observational equivalence classes* (two terms equivalent if equal on all test inputs), which is exactly the collision structure support-rank mining ignores.
2. **Strongest parent:** Udupa et al., "Translating Imperative Programs to Equations" (PLDI 2013, test-place deep-syntactic dedup); Alur et al., "Scaling Enumerative Program Synthesis via Divide-and-Conquer" (TACAS 2015) — observational-equivalence pruning + grammar splitting; FlashFill lineage (Gulwani, "Automating String Processing in Spreadsheets using Examples," PLDI 2011).
3. **Object to assimilate:** OBSERVATIONAL EQUIVALENCE relation ≈_D over candidate terms given discriminator set D: t1 ≈_D t2 iff ∀x∈D: t1(x)=t2(x). Build terms bottom-up, keep one representative per class. Key theorem: pruning is sound for the *current* D and grows monotonically with D. This is a finite, constructive cousin of e-graphs (§3).
4. **Novel after subtraction:** Parent already solves the *collision* half of F3 (shared substrings = shared equivalence/overlap structure; classes are disjoint by construction). Residue: OCM's ranking question — which representative to keep is a *cost/valorization* question (C of re-use vs V of generality), which enumerative synthesis decides arbitrarily (first-found). The learnability condition (pairwise substring-disjointness) becomes unnecessary machinery if classes are used: disjointness is enforced, not assumed.
5. **Minimal implementation:** During library mining, group candidate fragments by ≈ over the corpus contexts where they occur; rank classes (not raw fragments) by class-level support; admit one representative per class chosen by C/V. This directly patches F3.
6. **Falsification:** Head-to-head on motif-sharing ecologies: (support,length)-rank mining vs equivalence-class mining vs Stitch compression (§2.2). Terminal metric = fraction of ground-truth motifs recovered (F2's admission law is the terminal predicate). If class-mining ≤ support-rank on ALL shared-substring ecologies, the equivalence-class transplant is dominated and F3's disjointness condition remains the right scoping.

### 1.3 Version-space algebras & behavioral cloning from examples (PBD)

1. **Gap addressed:** I (applicability): in programming-by-demonstration, *when to offer* a learned macro is learned jointly with the macro — closest classical treatment of "served through applicability" (F1/F4).
2. **Strongest parent:** Lau, Wolfman, Domingos, Weld, "Programming by Demonstration Using Version Space Algebra" (Machine Learning 2003); capsule-critic macro induction: "SmartEdit" (Lau et al. UIST 2001).
3. **Object to assimilate:** Version space VS(hypotheses consistent with examples) as a *set-valued applicability function*: macro applies at state s iff the VS, intersected with s's features, is non-empty and the macro's trigger (feature conjunction) covers s. Trigger learning = feature-conjunction specialization over positive/negative application events.
4. **Novel after subtraction:** Trigger learning already exists (SmartEdit learns preconditions for macros; cost/benefit of application guides admission). Residue: OCM's V (conditional future value of applying — not immediate correctness) and C (charge the trigger evaluation itself), plus sleeping structure (macro inapplicable in most states).
5. **Minimal implementation:** Each library fragment gets a feature-conjunction trigger over Z; application events (helped/hurt/neutral on downstream success) update the trigger by specialization/generalization.
6. **Falsification:** Serve the SAME library through (a) learned conjunction trigger, (b) contextual bandit (§7.1), (c) always-all, on identical ecologies. If (a)≈(b) with less machinery, bandit machinery is overkill; if (a)≈(c), triggers learned nothing — F1's mechanism falsified for this trigger class.

## §2 DreamCoder / Stitch / wake-sleep library induction

### 2.1 DreamCoder wake-sleep (recognition model = neural applicability)

1. **Gap addressed:** F4 directly — DreamCoder's *recognition model* is the field's flagship instance of learned structural applicability: a conditioned policy Q(program | task features) that decides which library pieces to try where. Also F1: DreamCoder's wake phase uses the library *through* the recognition net, never raw.
2. **Strongest parent:** Ellis et al., "DreamCoder: Bootstrapping Inductive Program Synthesis with Wake-Sleep Library Learning" (PLDI 2021); journal version "DreamCoder: growing generalizable, interpretable knowledge with wake-sleep Bayesian program learning" (Phil. Trans. R. Soc. A 2023).
3. **Object to assimilate:** Wake-sleep factorization: wake = infer programs conditioned on tasks with recognition model q(z|x); abstraction sleep = compress corpus into library; dream sleep = train q on imagined tasks sampled from the generative model. The recognition model q(z|x) IS a learned I: its support defines applicability, its confidence defines initiation strength.
4. **Novel after subtraction:** Brutal: DreamCoder *already demonstrates* that a library without learned serving is useless (their ablations show compression-only libraries don't accelerate search — the recognition net is what converts library to speedup). Residue for OCM: (i) q is trained on *imagined* tasks — OCM's admission law (F2: recover ALL motifs) is a stronger, verifiable gate DreamCoder lacks (nothing certifies the library covers the true motif set); (ii) OCM's Ψ/V/C fields — DreamCoder's q has no effect model, no cost ledger, no warrant; it is a black probability, not a registered unit. The residue is the ledger + admission veto, not the mechanism.
5. **Minimal implementation:** Wrap each OCM fragment family in q(fragment-class | Z-context) trained on (context, helped/hurt) events from live ecologies (not imagined ones — that difference is testable); I = support(q) above threshold; Ψ logged as q's calibration curve.
6. **Falsification:** Transplant: recognition-model serving vs always-serve vs never-serve of the same mined library on the same ecologies (this is F1's design — replicate with q trained on imagined vs live contexts). If imagined-trained q ≈ live-trained q, dream-sleep's core loop is irrelevant to OCM ecologies; if neither beats always-serve, learned I adds nothing at this ecology scale.

### 2.2 Stitch compression objective (SPECIAL ATTENTION (a): vs OCM support-rank mining)

1. **Gap addressed:** F3 head-on — ranking fragments by (support desc, length desc) fails on shared substrings because support is counted pre-application; Stitch's objective is computed *post-application*.
2. **Strongest parent:** Bowers & Solar-Lezama, "Top-Down Synthesis for Library Learning" (POPL 2023, arXiv:2211.16605) — corpus-guided top-down invention of abstractions; also Cao et al., "Learning Better Abstractions with E-Graphs and Anti-unification" (Babble/LLMT, POPL 2023).
3. **Object to assimilate:** COMPRESSION OBJECTIVE: for candidate abstraction f with body size |b| and call size |c|, utility(f) = Σ_occurrences (|b| − |c|) − |definition|, computed on the corpus *after rewriting* — overlaps are automatically resolved because the second application of the same subterm is consumed by the first abstraction (Stitch's top-down call-site search finds best (abstraction, call-sites) jointly, so a fragment's utility is exactly the bytes it saves, not its raw frequency). Babble refines: candidates via anti-unification over e-graphs, selection via extraction, plus an equational theory input.
4. **Novel after subtraction — is support-rank strictly dominated?** **Yes, on the ranking failure.** Post-application utility subsumes (support, length) whenever motifs share substrings: shared substrings are counted once, not twice; utility is exactly Δcorpus-size. Support-rank is the special case utility ≈ support × length when fragments are pairwise disjoint — i.e., F3's derived learnability condition is precisely the regime in which the parent's machinery degenerates to OCM's cheap ranking. OCM re-derivation credit: the disjointness condition *characterizes when cheap ranking is admissible*. What the parent does NOT give: (i) F2's admission law — Stitch maximizes compression, will happily stop at a high-compression library that misses low-support motifs; "recover ALL ground-truth motifs" is an exhaustive-recovery condition alien to MDL-style objectives; (ii) support as causal P (usage provenance) vs Stitch's syntactic frequency; (iii) C — Stitch's cost is DSL-token size, not capital/marginal compute (§6). Residue: admission veto + economic cost, genuinely not in the parent.
5. **Minimal implementation:** Swap miner ranking to utility-after-application: for each candidate, compute rewritten-corpus savings with greedy call-site assignment; keep (support,length) as the disjoint-regime fast path. ~A rewrite of the miner's score function, not the miner.
6. **Falsification:** Head-to-head on motif-sharing ecologies: support-rank vs utility-rank vs Babble-AU, terminal = motif-recovery fraction (F2 law) + downstream search speedup served through fixed I. Prediction: utility-rank ≥ support-rank everywhere, equal on disjoint ecologies; if support-rank ever strictly wins a shared-substring ecology, the post-application-utility claim is falsified for OCM's corpus regime.

### 2.3 Dream phase / imagined data as regularizer (and its failure mode)

1. **Gap addressed:** F2 (history as prior) — DreamCoder's dream phase is the canonical claim that *self-generated data* beats real history; OCM found shuffled history worse than none, so the parent's assumption is contested at the unit level.
2. **Strongest parent:** Same DreamCoder papers (dream sleep); also Schmidhuber's "powerplay"/formal curiosity line (Srivastava, Schmidhuber 2012) as the "generate your own curriculum" pole.
3. **Object to assimilate:** Generative-model-as-task-distribution: tasks ~ p̂(task|library), recognition trained to convergence on p̂ — a closed loop whose fixed point is (library, q) self-consistency. The formal object is the bootstrapping operator B(library) → library' and its fixed-point/absorption behavior.
4. **Novel after subtraction:** Parent already claims self-generated data > stored data; OCM's shuffled-history negative is evidence *against* naive versions. Residue: OCM can state the *condition* under which imagined data helps — consistency of p̂ with the admission law (imagined tasks must exercise all motifs) — a non-parent refinement. If p̂ is shuffled/incoherent, dream phase degrades — exactly OCM's finding.
5. **Minimal implementation:** Sample synthetic tasks from the current generator; feed only tasks whose solutions pass the admission gate (touch every admitted motif); log whether these accelerate live search vs. neutral.
6. **Falsification:** Three-arm: no-dream / gated-dream (admission-consistent) / ungated-dream, on ecologies with known motifs; terminal = search-nodes-to-solve. If ungated-dream < no-dream (replicating "shuffled worse than none") and gated-dream > no-dream, the admission law generalizes from history to imagination; if gated ≈ no-dream, dreaming adds nothing here.

## §3 E-graphs & equality saturation

### 3.1 Equality saturation (egg) (SPECIAL ATTENTION (d): parent of OCM normal-form gates)

1. **Gap addressed:** The normal-form gate in F2 (targets' normal form disjoint from history ⇒ novelty) and the collision failure F3. E-graphs are the canonical machinery for equivalence classes with a bounded rewrite budget — a saturation-budgeted, congruence-closed representation.
2. **Strongest parent:** Willsey et al., "egg: Fast and Extensible Equality Saturation" (POPL 2021); original equality saturation: Tate, Stepp, Tatlock, Lerner (PLDI 2009).
3. **Object to assimilate:** E-graph = union-find over terms + hashconsed e-classes, congruence closure invariant, saturating rewrite application under a node/match budget, then EXTRACTION: pick minimal-cost representative per class. Complexity facts that matter for OCM: tree extraction is poly (bottom-up DP); DAG extraction is NP-hard (see "Fast and Optimal Extraction for Sparse Equality Saturation," OOPSLA 2024; egglog, Yang et al. POPL 2023). The normal-form gate = e-class identity: "target ≡_history some stored term" is decidable by saturating history+target with the shared rewrite system and testing class membership.
4. **Novel after subtraction — does the parent already solve the normal-form gate?** **Yes, given the rewrite system.** Congruence-closed equivalence detection IS the gate, with a principled budget (saturation limit). What the parent does NOT solve: (i) it supplies no rewrite system — OCM must author or mine rules (Ruler, Nandi et al., OOPSLA 2021, infers rules by saturation; Enumo, PLDI 2023 follow-up); (ii) extraction cost is AST/token size — no V/C/W: extraction does not value *downstream utility* (which representative helps future search) nor charge marginal cost; (iii) no admission law — saturation never asks whether ALL motifs are represented. Residue: economic extraction (cost function over C/V instead of node size) is a genuine, small delta.
5. **Minimal implementation:** Represent history terms + new targets in one egg workspace with the ecology's equivalence rules; gate = same-e-class-as-history predicate (replaces string/normal-form heuristic); mining (F3) can run over e-classes directly (Babble-style candidate generation, 2.2).
6. **Falsification:** Knockout: drop the e-graph gate, use syntactic-equality gate; measure false-novelty (targets judged novel that are provably equivalent) and false-redundancy rates on motif-sharing ecologies. Terminal: correlation of gate verdict with ground-truth motif identity. If syntactic ≈ e-graph on all ecologies, the shared-substring structure is too shallow for congruence to matter and F3's disjointness condition suffices.

### 3.2 Rewrite-rule inference / ruleset quality (Ruler, Enumo)

1. **Gap addressed:** W (warrant) for transformations φ: Ruler's derivability check — is rule r derivable from the existing ruleset? — is a formal warrant notion for "this transformation adds no new expressivity."
2. **Strongest parent:** Nandi et al., "Rewrite Rule Inference Using Equality Saturation" (OOPSLA 2021); "Equality Saturation Theory Exploration à la Carte" (Enumo, OOPSLA 2023); derivability metric: Dao et al., "What is a 'Good' Ruleset?" (2024).
3. **Object to assimilate:** DERIVABILITY: rule r is derivable from R if saturation with R proves r. Ruler's selection loop: enumerate candidate rules via saturation on sampled terms, filter by derivability + canonicity, keep a small orthogonal set. Orthogonal ruleset = the parent's version of a non-redundant library — precisely the structure F3 wants at the fragment level.
4. **Novel after subtraction:** Parent solves redundancy-elimination for *equational rules*; OCM needs it for *imperative fragments* (not declared equal, only behaviorally similar). Residue: behavioral (input/output) derivability vs equational derivability — OCM's fragments warrant via P (did it causally help), not via proof. Small but real.
5. **Minimal implementation:** For each mined fragment, test whether its effect is derivable from existing library composition (a saturation-based redundancy test on effect classes); admit only non-derivable fragments (this generalizes F3's disjointness from substrings to effects).
6. **Falsification:** On shared-substring ecologies, compare admission by (a) substring-disjointness (F3 condition), (b) effect-derivability. Terminal: motif-recovery + library size. If (b) admits strictly smaller libraries at equal recovery, substring-disjointness is a syntactic proxy of the effect-level condition — refinement, not replacement; if (b) loses motifs, syntactic condition is the correct one.

### 3.3 Guided / backtracking saturation (saturation as a resource-bounded search)

1. **Gap addressed:** F2 (search prior) and C — equality saturation is the cleanest existing "search with a rewrite budget and graceful degradation" mechanism; OCM's claim "history induces a genuine search prior" needs exactly a budgeted saturation to instantiate.
2. **Strongest parent:** Koehler et al., "Guided Equality Saturation" (POPL 2024); backtracking saturation (Koehler et al., "Backtracking for Equality Saturation," OOPSLA 2023).
3. **Object to assimilate:** TERM-ORDER POLLING / guided rewriting: instead of saturating blindly, spend the budget in the order a learned/heuristic term-order prescribes; backtracking restores prior states when the chosen route is dominated. Formal object: a scheduler over rewrite applications with provable completeness preservation under a fixed budget.
4. **Novel after subtraction:** Parent already does "prior over rewrites under budget." Residue: OCM's prior comes from P (causal history of which rewrites helped), and the budget is denominated in C (capital/marginal ledger), not node counts. Again ledger-shaped residue.
5. **Minimal implementation:** Priority queue over rewrite firings ordered by fragment P-scores; budget = C units; β = budget-exhaustion fallback to unguided enumeration.
6. **Falsification:** Guided-by-P vs guided-by-arbitrary-heuristic vs unguided, same budget, terminal = best-found-term cost within budget across ecologies. If P-guidance ≈ heuristic-guidance, F2's "genuine search prior" claim is weakened to "any prior helps" (shuffled-history negative already shows a bad prior hurts; this tests whether the *learned* prior beats cheap heuristics).

## §4 Abstract interpretation & type systems (applicability/warrant machinery)

### 4.1 Abstract interpretation (Cousot) — applicability as an abstract domain question

1. **Gap addressed:** I (learned applicability) and Ψ (predictive effect model): abstract interpretation gives the *sound over-approximation* of where a transformation applies and what it does — applicability proofs, not applicability guesses.
2. **Strongest parent:** Cousot & Cousot, "Abstract Interpretation: A Unified Lattice Model for Static Analysis of Programs" (POPL 1977); Cousot & Halbwachs, "Automatic Discovery of Linear Restraints Among Variables of a Program" (POPL 1978) for effect shapes.
3. **Object to assimilate:** GALOIS CONNECTION (Concrete ⊑ Abstract, α/γ pair): applicability I(f) = γ(abstract-precondition(f)) — the set of concrete contexts where f applies is exactly the concretization of a computed abstract precondition. Effect model Ψ(f) = transfer function on the abstract lattice. Soundness: never says "applies" when it doesn't (no false-positive applicability) at the price of false negatives.
4. **Novel after subtraction:** Parent solves *sound* applicability for programs over a chosen abstraction. OCM's I must be *learned and cheap* (abstract interpretation is compile-time expensive and domain-authoring-heavy) and OCM tolerates unsoundness in exchange for C savings. Residue: a learnable soundness/coverage dial — OCM can rank candidate I-functions by (precision, cost), i.e., an abstraction-lattice traversal with C-pricing. Parents have lattices but never price lattice refinement by marginal cost.
5. **Minimal implementation:** Give each fragment family a small abstract domain (types + a few predicate abstractions); I = γ(pre); Ψ = abstract transfer; learn *which domain refinement to buy* with the ledger (a refinement costs C, buys precision).
6. **Falsification:** Compare learned-neural I vs abstract-interpretation I on the same library: false-application rate, missed-application rate, and total C (including analysis cost), terminal = end-task success per unit cost. If neural-I matches abstract-I's false-positive rate at equal total cost, the lattice machinery is costume; if abstract-I wins only when domains are hand-authored, that authoring cost must appear in C or the comparison is rigged.

### 4.2 Refinement / liquid types — applicability as a decidable precondition

1. **Gap addressed:** I and W together: refinement types are *machine-checked applicability contracts* — "f applies to {x | φ(x)}" with an SMT-checkable proof. Warrant field W as an object.
2. **Strongest parent:** Rondon, Kawaguchi, Jhala, "Liquid Types" (PLDI 2008); Polikarpova, Kuraj, Solar-Lezama, "Program Synthesis from Polymorphic Refinement Types" (Synquid, PLDI 2016) — type-directed synthesis where applicability *prunes search*.
3. **Object to assimilate:** REFINEMENT TYPE {ν:B | φ(ν)} with SMT-decidable φ; applicability test = type-checking (decidable for the liquid fragment); Synquid's contribution: types as a search-space divisor — the type of the goal restricts which components can appear at each position.
4. **Novel after subtraction:** Type-directed applicability already prunes search with formal soundness (Synquid literally demonstrates it). Residue for OCM: type systems are static and total (apply everywhere typeable); OCM needs *economic* applicability — applies-and-helps-where, with V/C. A fragment can be typeable-applicable yet value-negative; no type system encodes that. Residue = conditional value on top of sound applicability.
5. **Minimal implementation:** Annotate fragments with lightweight liquid-style preconditions over Z-features; use SMT filter as the I-soundness backbone; layer the bandit (§7) only over SMT-passing candidates. This makes F4's learning problem strictly easier (learn V, not (applicable ∧ V)).
6. **Falsification:** Ablate the SMT backbone: bandit over raw fragments vs bandit over SMT-filtered fragments, same exploration budget. Terminal: regret-to-good-serving. If raw ≈ filtered at practical fragment counts, the type machinery is premature (search space too small for soundness to pay); the implementation should be deferred, and that is a real finding either way.

### 4.3 Gradual/bidirectional typing & blame — partial warrants with provenance

1. **Gap addressed:** W and β: how to serve a fragment whose applicability is only partially known without losing provenance, and how to fall back (β) when the contract fails at runtime.
2. **Strongest parent:** Siek & Taha, "Gradual Typing for Functional Languages" (SFP 2006); Wadler & Findler, "Well-Typed Programs Can't Be Blamed" (ESOP 2009); Tobin-Hochstadt & Felleisen, "Interlanguage Migration" (ICFP 2006).
3. **Object to assimilate:** GRADUAL GUARANTEE + BLAME: contracts with unknown parts (?); a runtime contract failure blames exactly the component whose contract was violated — a provenance-preserving fallback. Blame assignment = the formal object for "which unit's Ψ was wrong."
4. **Novel after subtraction:** Blame tracking exists wholesale. Residue: OCM's blame feeds P (causal support updates) and L (plasticity: demote/specialize the blamed unit) — a closed learning loop on blame, which gradual typing never closes (it reports, doesn't learn).
5. **Minimal implementation:** Serve fragments with gradual contracts; on failure, record blame to the unit, decrement its P, trigger β; blame log is the P update stream.
6. **Falsification:** Compare P-updates from blame (precise) vs from task-level success signal (diffuse credit). Terminal: rate at which the library's serving policy converges to helped-only. If diffuse ≈ blame-precise at ecology scale, blame machinery is unnecessary — the ecology is too small to localize credit.

## §5 MDL / compression / information theory

### 5.1 Two-part MDL for libraries (and its admission-law mismatch)

1. **Gap addressed:** F2's admission law and F3's mining objective — two-part MDL is the parent formalism for "code the library, then the corpus given the library": L(lib) + L(corpus|lib).
2. **Strongest parent:** Rissanen, "Modeling by Shortest Data Description" (Automatica 1978); Grünwald, *The Minimum Description Length Principle* (MIT Press 2007); program-library instance: the Stitch objective (§2.2) IS two-part MDL with DSL token costs.
3. **Object to assimilate:** TWO-PART CODE: argmin_L |lib| + |corpus given lib|; refinement complexity (corpus|lib) is the formal measure of "the library explains the corpus." Babble/Stitch = computable approximations with search instead of exact minimization.
4. **Novel after subtraction:** Parent gives the mining objective and explains compression-benefit curves, but MDL *does not imply* F2's law: minimizing L(corpus|lib) can terminate at a library that compresses well yet misses motifs (undersampling low-frequency motifs costs few bits). "Library must recover ALL motifs" is a recall-complete, non-MDL condition — OCM's admission veto is genuinely extra (it is closer to a *coverage grammar* requirement than a code-length requirement). Residue: the veto, plus cost-in-C (compute), not code length.
5. **Minimal implementation:** Report both quantities at admission: two-part length AND motif-recall fraction; admit iff recall = 1, size-optimize subject to that constraint (constrained MDL — recall-constrained minimization is a nonstandard, publishable twist).
6. **Falsification:** Compare admission by (a) pure MDL threshold, (b) recall-constrained MDL, on ecologies with rare motifs. Terminal: downstream search speedup + false-admission rate (generators admitted whose libraries miss motifs). Prediction: (a) misses rare motifs systematically; if (a) ≈ (b), rare motifs carry no downstream value and the "ALL motifs" law is stricter than necessary (would itself CORRECT F2 — a first-class outcome).

### 5.2 Levin complexity / universal search — the idealized prior (and the complexity barrier)

1. **Gap addressed:** F2 (search prior) in its idealized form: Levin search is the optimal-in-constant search under the program prior; any learned prior can be benchmarked against it.
2. **Strongest parent:** Levin (1973; see Scholarpedia "Universal Search"); Schmidhuber, "Optimal Ordered Problem Solver" (Machine Learning 2003) — incremental/self-referential variant; Hutter speed prior line.
3. **Object to assimilate:** LEVIN COMPLEXITY Kt(p) = |p| + log(time(p)); universal search runs all programs in Kt order; optimal up to multiplicative constant: solves any problem in time ≤ 2^(Kt+O(1)). The mathematical role: the *absolute scale* any OCM search prior is measured against — a library/ prior is worth exactly the Kt reduction it induces on the ecology's tasks.
4. **Novel after subtraction:** Parent is idealized (incomputable constants, no memory between problems — Schmidhuber's OOPS addresses incrementality). Residue: OCM's P is a *per-ecology learned* Kt bias with capital/marginal costs; also OCM's admission law has no Levin analogue. Essentially nil machinery transfer; this is a measuring stick, not a mechanism.
5. **Minimal implementation:** Compute per-ecology "effective Kt" (search effort to solve) with/without library-prior; the prior's value = log-ratio; report it in C/V terms.
6. **Falsification:** If learned-prior search effort is not monotone in admitted-library quality (motif recall), the Kt-reduction model of library value is wrong; run across ecologies and read out the correlation. Terminal, cheap, decisive.

### 5.3 MAP-Elites / quality-diversity for programs (QD-of-programs)

1. **Gap addressed:** F3 and library diversity: ranking by a single scalar (support, or utility) collapses diverse behavior niches; QD explicitly maintains an archive over behavior descriptors.
2. **Strongest parent:** Mouret & Clune, "Illuminating Search Spaces by Mapping elites" (arXiv 2015); program-space instances: phenotype-behavior descriptors for GP (e.g., Lehman & Stanley, novelty search, 2011).
3. **Object to assimilate:** ARCHIVE over (behavior-descriptor cell → best individual): each e-class/effect-class (1.2) is a cell; selection pressure is per-cell, so no niche is outcompeted — directly prevents the F3 failure where a dominant high-support fragment starves overlapping smaller motifs of admission.
4. **Novel after subtraction:** QD solves diversity-preservation for search; what it lacks is (i) F2's admission criterion (cells ≠ verified motifs; coverage is behavioral, not ground-truth), (ii) any cost ledger (QD archives are free to keep). Residue: QD-cells priced by C and validated by admission = a QD library with an economic veto. Modest but real.
5. **Minimal implementation:** Replace the single ranked list in the miner with a descriptor-indexed archive (descriptor = effect class from 1.2); admit per-cell by utility; budget cells by C.
6. **Falsification:** On shared-substring ecologies with rare motifs: ranked-miner vs QD-archive miner, terminal = rare-motif recovery. If QD recovers rare motifs at equal total cost, single-scalar ranking is the defect (confirms F3 diagnosis, adds the fix).

## §6 Database query optimization — materialized views, index economics, adaptive indexing

### 6.1 Materialized-view selection economics (SPECIAL ATTENTION (c): parent of OCM capital-vs-marginal)

1. **Gap addressed:** F5 head-on — the capital-vs-marginal ledger and the amortisation crossing test. View selection is the field that has *literally already written* the crossing equation: build once (capital), save per query (marginal), pay maintenance on updates (invalidation).
2. **Strongest parent:** Chaudhuri & Narasayya, "An Efficient Cost-Driven Index Selection Tool for Microsoft SQL Server" (SIGMOD 1997, AutoAdmin); Agrawal et al., "Automating Physical Database Design in a Parallel Database" (SIGMOD 2004); Baralis, Paraboschi, Teniente, "Materialized View Selection in a Multidimensional Database" (VLDB 1997) — cost models with query AND maintenance cost; Zilio et al., DB2 Design Advisor (SIGMOD 2004).
3. **Object to assimilate:** VIEW-BENEFIT FORMULA: benefit(v) = Σ_queries freq(q)·[cost(q) − cost(q|v)] − Σ_updates freq(u)·maint(u,v) − amortized_build(v,W) , selection = knapsack/ILP over candidates under a storage/budget constraint, solved by what-if costing against a workload W. The "invalidation cone" = the update-triggered maintenance cost, the piece naive amortisation forgets. Crossing time = build cost / per-query savings, adjusted by workload drift.
4. **Novel after subtraction — does the parent already solve F5?** **Yes for the economics: the crossing equation, the budget knapsack, and the maintenance-cost correction are all standard.** What is NOT in the parent: (i) OCM's C is *cognitive compute + attention*, not storage — the constraint object differs (their budget is bytes; OCM's is runtime/effort, fungible across all units); (ii) workload drift in DBs is handled by re-tuning periodically, whereas OCM's L (plasticity/lifecycle) demands online demotion — closer to §6.2 cracking; (iii) the F2 admission veto (views pick top-k under budget; OCM demands exhaustive motif recovery — an unusual, stronger constraint). Residue: lifecycle-gated online re-solving + admission veto.
5. **Minimal implementation:** Write OCM's amortisation crossing test directly in the view-benefit form: per fragment, freq(context)·[search-cost-without − search-cost-with] vs compile/index cost + invalidation on ecology drift; the in-flight amortisation crossing tests (F5) should be validated against this closed form — if they differ, OCM's ledger has a defect, since the parent's form is the audited one.
6. **Falsification:** Transplant: instantiate the parent formula with measured OCM quantities and compare its admission decisions against OCM's current ledger decisions on logged traces; also knockout the maintenance term (set =0) to test whether invalidation matters (ecology drift). Terminal: cumulative utility under fixed total C. If parent-formula ≈ OCM-ledger without maintenance term, OCM is in a static-workload regime and L/invalidation is dead machinery for now.

### 6.2 Adaptive indexing / database cracking — pay-as-you-go marginal builds

1. **Gap addressed:** F5's *marginal* accounting: cracking is the canonical "don't pay capital upfront; pay per use, incrementally" mechanism — the exact antithesis of build-then-amortise, and OCM's ledger needs both regimes and the switching law.
2. **Strongest parent:** Idreos, Kersten, Manegold, "Database Cracking: Cute or Evil?" / CIDR 2007 "Database Cracking" line; "Adaptive Indexing in Main-Memory Column-Stores" (PVLDB 4(4), 2011); Graefe et al., adaptive merging (2006? follow-on).
3. **Object to assimilate:** CRACKING OPERATOR: each query reorganizes only the piece it touches; total work converges to a full index but is paid in O(log n)-ish installments at first touch. Formal object: amortized incremental structure S_0 → S_1 → … where each step is triggered by observed demand and is useful immediately (no stranded capital). Complementarity result (cracking vs adaptive merging): high init cost + fast convergence vs low init + slow — a two-axis frontier OCM's ledger should reproduce for libraries (eager-compile vs lazy-crack a fragment).
4. **Novel after subtraction:** Parent already owns pay-as-you-go. Residue: OCM fragments crack on *contexts* (Z) rather than keys, and the demand signal is V (conditional future value), not query frequency — a thin mapping. The genuinely novel bit is the *switching law* between eager and lazy given a drift forecast (Ψ extended to workload drift), which the cracking literature treats empirically, not as a derived decision rule.
5. **Minimal implementation:** Serve fragments in uncompiled form; compile/specialize on k-th reuse (k = 1 is cracking; k = ∞ is eager); log crossing behavior per fragment; choose k per fragment class by measured drift.
6. **Falsification:** Two-arm serving — eager-compile vs crack-on-demand — across drift regimes (static ecology vs drifting ecology). Terminal: total cost to fixed cumulative utility. Prediction: eager wins static, cracking wins drifting; if cracking never wins even under drift, the L/plasticity field is currently vestigial (also a valid CORRECTED-type finding).

### 6.3 Learned query steering (Bao/Neo) — bandit over physical designs

1. **Gap addressed:** F4/F1 jointly, in the *systems* realization: Bao learns per-query which hint-set (≈ which fragment/configuration) to apply — learned applicability in production, with the exact reward = query latency.
2. **Strongest parent:** Marcus, Negi, Mao, Tatbul, Papaemmanouil, "Bao: Making Learned Query Optimization Practical" (SIGMOD 2022) — tree-CNN + Thompson sampling over hint sets; Neo (SIGMOD 2019) for full learned plans; Kraska et al., "The Case for Learned Index Structures" (SIGMOD 2018).
3. **Object to assimilate:** CONTEXTUAL BANDIT STEERING: context = query structure (tree), arms = configurations, reward = negative latency, Thompson sampling posterior over reward; adapts within ~1 hour of workload; explicitly chooses to *steer* a trusted optimizer rather than replace it.
4. **Novel after subtraction:** Bao is strong evidence the (context → configuration) routing problem is solved machinery (see §7 verdict). Residue for OCM: reward = immediate measurable cost in DBs; OCM's V is *conditional future value* (delayed, ecological), and arms have admission gates (F2). The steering-not-replacing lesson is worth importing verbatim: serve fragments through φ, don't rewrite φ.
5. **Minimal implementation:** Posterior per (fragment-class, context-feature) with Thompson sampling; exploration budget drawn from C; per-ecology adaptation curve logged (Bao's "1 hour" is the comparison bar).
6. **Falsification:** Replicate Bao's protocol on OCM ecologies: adaptation speed vs a fixed oracle-serving upper bound. If Thompson serving reaches oracle-serving on static ecologies, F4's remaining gap is only the ecological/V-reward extension, not routing itself.

## §7 Sleeping experts / contextual bandits / regret theory

### 7.1 Contextual bandits (SPECIAL ATTENTION (b): exact parent of learned applicability I)

1. **Gap addressed:** F4 verbatim — I(u) is a map from context Z to "apply/don't apply" (or a ranking over units). That is a contextual bandit: at each context, choose an arm (fragment), observe reward (helped/hurt), minimize regret to the best context→fragment policy.
2. **Strongest parent:** Auer, Cesa-Bianchi, Freund, Schapire, "The Nonstochastic Multiarmed Bandit Problem" (SIAM J. Comput. 2002) — EXP4, regret O(√(TK ln N)) against the best expert/policy in hindsight, adversarial rewards; Langford & Zhang, "The Epoch-Greedy Algorithm" (ICML 2008) for stochastic contextual bandits; Bao (§6.3) as the deployed instance.
3. **Object to assimilate:** EXP4 POLICY CLASS + REGRET GUARANTEE: experts = candidate applicability functions (features of Z → fragment); partial information (only the served fragment's outcome is observed); regret bound O(√(T·K·ln N)) means: with T serve events, the learned I approaches the best applicability function in the class with a *certified rate* — an auditable convergence statement OCM's F4 currently lacks.
4. **Novel after subtraction — does the parent already solve F4?** **Yes, the routing/learning problem itself: given (a) a context feature map, (b) a reward signal, and (c) a policy class, contextual bandits learn I with regret guarantees. DreamCoder's recognition net does it too (§2.1) but without guarantees.** What the parent does NOT give: (i) the *feature map Z* — someone must define the context representation (this is OCM's Z field; bandits are silent on it, and F1's "which-fragment-helps-where" lives or dies on feature quality); (ii) the reward definition — immediate vs conditional-future V (delayed ecological reward breaks standard bandit assumptions; needs off-policy correction or a surrogate); (iii) cost-aware arms — pulling/evaluating I has a price in C (regret is denominated in reward, not net-of-cost); (iv) admission gates — bandits never decide which arms should exist (F2 law). Residue: Z engineering + delayed V + cost-charged regret + admission veto.
5. **Minimal implementation:** Linear/Thompson contextual bandit over Z-features per fragment; reward = measured downstream Δ (search-nodes saved), charged with marginal C; log regret vs oracle-I on replayed traces (offline policy evaluation gives the oracle for free).
6. **Falsification:** Knockout/transplant: oracle-I (computed by exhaustive replay) vs bandit-I vs never-serve vs always-serve, identical library, identical ecologies; terminal = cumulative utility and regret trajectory. If bandit-I fails to separate from always-serve at current ecology scale, F4's gap is not a learning gap but a *scale/features* gap (i.e., contexts don't yet discriminate) — diagnosis changes the roadmap.

### 7.2 Sleeping experts/bandits — applicability as arm availability

1. **Gap addressed:** F1/F4 with the crucial structural twist OCM actually has: a fragment is *unavailable* (inapplicable) in most contexts — not merely low-reward. Vanilla bandits model all arms as always-pullable; OCM's "which-fragment-helps-where" has hard availability structure.
2. **Strongest parent:** Kleinberg, Niculescu-Mizil, Sharma, "Regret Bounds for Sleeping Experts and Bandits" (MLJ 2010; COLT 2008); full-info predecessor: Freund, Schapire, Singer, Warmuth, "Using and Combining Predictors that Specialize" (STOC 1997); Blum, "Empirical Support for Winnow and Weighted-Majority" (1997).
3. **Object to assimilate:** SLEEPING REGRET: awake set A_t varies; per-action regret Σ_t [r_t(best awake action) − r_t(a_t)]; KNS show ordering/oracle-regret formulations and bounds (e.g., per-action regret O(√(n_i) polylog) where n_i = times action i awake), adversarial-available-set settings with impossibility results (no external-regret algorithm is simultaneously no-internal-regret and no-regret against all orderings — a *structural* limit worth importing: some OCM serving desiderata are provably incompatible).
4. **Novel after subtraction:** Parent already models "arm exists only in some contexts" with guarantees. Residue: (i) awake-set A_t is *itself learned/uncertain* in OCM (sleeping experts assume the availability signal is observed pre-choice) — OCM must infer awakeness from Z, merging 7.1 and 7.2 (learned awake-set + learned value within awake set: two coupled learning problems, not one); (ii) cost-charged pulls again. The two-coupled-problems structure is the honest novelty.
5. **Minimal implementation:** Per fragment: awakeness classifier (from Z features, §4 contracts can bound it soundly) + value estimator within awake contexts; serve argmax E[value·awake] − marginal C.
6. **Falsification:** Compare coupled (awakeness ∧ value) model vs flat bandit over all fragments. Terminal: false-awake serve rate and utility. If flat ≈ coupled, the sleeping structure is not yet load-bearing (contexts too permissive); the impossibility results of KNS give the terminal theoretical readout for what serving policy class OCM can even aspire to.

### 7.3 Online learning with switching/adaptive costs — regret theory as budget grammar

1. **Gap addressed:** C and L — regret theory supplies the *denomination* for OCM's ledger: what does "cost" mean when the environment shifts (ecology drift) and units must be added/demoted.
2. **Strongest parent:** Cesa-Bianchi & Lugosi, *Prediction, Learning, and Games* (CUP 2006) — external/internal/swap regret taxonomy; Herbster & Warmuth, "Tracking the Best Expert" (Machine Learning 1998) — switching regret for drifting comparators; adaptive regret (Hazan & Seshadhri 2007).
3. **Object to assimilate:** SWITCHING/ADAPTIVE REGRET: guarantee vs the best *sequence* of policies with S switches, cost ∝ √(T(S ln N + ln T)) — the formal price of plasticity: L's demotion/promotion policy should be judged against this bound; "cheap plasticity" = low switch-count regret overhead. Also internal/swap regret as the right target for library *composition* (the right mixture of fragments, not the single best).
4. **Novel after subtraction:** The bounds exist; nobody prices the *switch itself* in capital terms (Herbster-Warmuth counts switches in regret but each switch is free). OCM's L charges capital per lifecycle transition (compile, index, demote, resurrect). Regret-with-priced-switching is a genuinely open, small, formal delta.
5. **Minimal implementation:** Charge each admission/demotion event its ledger cost; report cumulative net utility vs the switch-free oracle; express F5's amortisation crossing as the switch-count/price frontier.
6. **Falsification:** Ablate switch pricing (free switches vs priced switches) under drifting ecologies; terminal = net utility. If free-switch policies win even though the ledger says they shouldn't, the ledger's capital entries are mispriced — an F5-internal audit with a clean null.

## §8 Bayesian experimental design & active learning

### 8.1 Expected information gain for counterexample/probe selection (EIG/BALD)

1. **Gap addressed:** P and Ψ — which *experiment* (probe input, counterexample, ecology sample) maximally reduces uncertainty about the true model; this is the principled version of CEGIS counterexample selection (§1.1) and of F2's admission tests (a unit is admitted on evidence; EIG picks the cheapest evidence).
2. **Strongest parent:** MacKay, "Information-Based Objective Functions for Active Data Selection" (Neural Computation 1992) — expected information gain; Houlsby et al., "Bayesian Active Learning by Disagreement" (ICML 2011) — BALD, MI between predictions and parameters via predictive entropies; decision-oriented refinements: "Targeted Active Learning for Bayesian Decision-Making" (AISTATS 2022), EPIG (Bickford Smith et al., AISTATS 2023).
3. **Object to assimilate:** EIG(x) = I(θ; y_x) = H[θ] − E_y H[θ | y]; for OCM: θ = the motif/library hypothesis set (or the admission-relevant parameter); x = a candidate probe task; the decision-oriented variant replaces "information about θ" with "information about the *decision* (admit/deny)" — strictly better aligned with F2, since only decision-relevant information has value.
4. **Novel after subtraction:** Parent already solves optimal experiment selection given a model class and a decision. Residue: (i) OCM's hypothesis space is a *library with admission law* — designing experiments to certify exhaustive recall (ALL motifs) is a coverage-design problem, not a parameter-precision problem; EIG-for-coverage (maximize probability of *finding any unseen motif*) is closer to species-discovery/sequential testing than BALD; (ii) cost-charged probes again (C). Modest, real residue.
5. **Minimal implementation:** Maintain posterior over motif sets (Dirichlet-style on motif occurrence); probe = next ecology sample/task; selection by max P(discover new motif)/cost (decision-EIG surrogate); Ψ logs predicted-vs-observed discovery rate.
6. **Falsification:** Compare probe orders: EIG-selected vs random vs adversarial (hardest first), fixed probe budget, terminal = motifs discovered per probe and admission-decision accuracy at fixed budget. If random ≈ EIG on authored ecologies, motif occurrence is uniform enough that experiment design is premature (a scale finding, not a defeat).

### 8.2 Optimal stopping / sequential testing for admission

1. **Gap addressed:** F2's admission law operationalized: how much evidence before admitting a generator? The law says "iff recovers ALL motifs" — but motif population is unknown, so admission is a sequential decision with a stopping rule.
2. **Strongest parent:** Wald's sequential probability ratio test (1945); Bayesian optimal stopping (DeGroot, *Optimal Statistical Decisions*, 1970); modern BED-with-stopping (e.g., Foster et al., "A Unified Stochastic Gradient Approach to Designing Bayesian-Optimal Experiments", NeurIPS 2019, jointly optimizes design+stopping).
3. **Object to assimilate:** SEQUENTIAL ADMISSION RULE: continue sampling tasks iff E[value of one more sample] > its cost; admit on posterior odds threshold; formally a stopped MDP over evidence states. This converts F2's law from a binary gate into a priced, stoppable procedure — and predicts exactly when the amortisation crossing (F5) of gathering admission evidence pays.
4. **Novel after subtraction:** Sequential testing is fully developed; what is absent is the *asymmetric loss*: false admission (generator whose library misses motifs) vs false rejection, priced in downstream search cost, not statistical loss. Choosing the loss from the ledger is OCM's residue.
5. **Minimal implementation:** Track per-candidate motif-recovery evidence; admit when posterior P(recovers all) > threshold where threshold = C(pricing of downstream failure)/V ratio from the ledger; log false-admission rate vs threshold.
6. **Falsification:** Sweep the stopping threshold on replayed ecologies; verify the empirically optimal threshold matches the ledger-derived one. A systematic mismatch = the ledger mis-prices admission errors (a falsification of the C/V calibration itself, which is the point of the crossing tests in F5).

## §9 Metareasoning & value of computation

### 9.1 Rational metareasoning (Russell-Wefald VoC)

1. **Gap addressed:** V and C jointly — the *definition* of a unit's conditional future value: V(u) = expected improvement in decision quality from running u, minus its cost. This is OCM's V field's parent, and the answer to "when is serving a fragment worth it" in one formula.
2. **Strongest parent:** Russell & Wefald, "Principles of Metareasoning" (AIJ 1991); "Do the Right Thing" (1991); Hay, Russell, Tolpin, Shimony, "Selecting Computations: Theory and Applications" (UAI 2012) — sharper bounds on when to meta-reason; applied: Tolpin & Shimony, rational metareasoning for MCTS (2012).
3. **Object to assimilate:** VoC(c) = E[max_a U(a | result(c))] − max_a E[U(a)] − cost(c); run c iff VoC > 0; the single-step myopic rule is provably optimal under meta-GPI conditions (Hay et al. give the exact bounds and when myopia is safe). Mapping: computation c = serving fragment u on context Z; result = search-nodes saved; cost = marginal C.
4. **Novel after subtraction:** Parent already defines and bounds VoC, including when myopic selection is safe. Residue: (i) OCM's units are *composable and persistent* (a library amortises across future contexts — VoC is defined per-computation, not per-capability; the amortisation is the §6.1/5.1 parent's job, so the residue is the *coupling*: capital-amortised VoC = VoC + expected future VoC stream, which no parent states cleanly); (ii) VoC with the admission law (a computation that *creates* units — mining — has VoC mediated by F2). The capability-amortised VoC is OCM's honest delta.
5. **Minimal implementation:** Log per-serve-event VoC estimate and realized savings; accept/reject serves by myopic VoC>0; report calibration (estimated vs realized) — this is a direct instantiation of F1's serving result with an auditable rule.
6. **Falsification:** Myopic-VoC-gated serving vs always-serve vs bandit-serve. Terminal: net utility per C. If myopic gating underperforms always-serve on static ecologies, the VoC estimates are miscalibrated (predictable: persistent-unit value is invisible to per-serve myopia — diagnostic of the amortisation coupling, not of VoC itself).

### 9.2 Bounded optimality & rational metareasoning at design time

1. **Gap addressed:** The *normative target* for OCM as a whole: a bounded-optimal program is the best *given* the compute budget — the standard against which "library + serving policy + ledger" should be judged; also the parent of "adaptive index decisions as part of the optimal design" (§6).
2. **Strongest parent:** Russell, "Rationality and Intelligence" (IJCAI 1995); Russell & Wefald 1991; Lin? no — see Gershman, Horvitz, Tenenbaum, "Computational Rationality: A Converging Paradigm for Intelligence in Brains, Minds, and Machines" (Science 2015); strategy selection as rational metareasoning (Lieder & Griffiths, Psych. Rev. 2017).
3. **Object to assimilate:** BOUNDED OPTIMAL PROGRAM: π* = argmax E[utility | program runs within budget B]; metalevel MDP whose actions are object-level computations; OCM's whole stack (I, φ, β, C, V) is a metalevel policy — the parent says: judge it only by realized utility within B, never by component-optimality.
4. **Novel after subtraction:** Pure framing — parents own it entirely; no mechanism to import. Value: it dictates the evaluation discipline (utility at fixed budget, all arms priced) that every falsification above already follows. Residue: none mechanical; OCM's contribution claim must therefore live in the ledger/admission/coupling, not in "we select computations by value."
5. **Minimal implementation:** None beyond adopting fixed-budget net-utility as the single terminal metric (already implicit in the falsification designs above).
6. **Falsification:** N/A (it is the measurement frame). Sanity check: any OCM result reported in component-optimality terms (best library, best ranking) without budgeted net utility is parent-inferior by construction.
