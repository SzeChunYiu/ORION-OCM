# PARENT_KILL_GATE_V0 — General Epistemic Field strongest-parent attack

Status: **mandatory kill-gate before any field novelty or architecture claim.**  
Owner: #93.  
Purpose: determine whether the proposed General Epistemic Field is scientifically residual or merely a re-description/composition of mature cognitive architectures and knowledge systems.

## 1. Claim under attack

Do **not** test the weak claim that one store can hold language + science + procedures. Mature systems already do this.

The candidate residual under attack is:

```text
one typed persistent field
+ learned/executable operators
+ small domain-general executive
+ exact warrant / authority / scope
+ support alternatives and local revocation
+ context-certified abstraction/refinement
+ unresolved-alternative preservation
+ discriminating probes
+ resource-responsibility escalation
+ learned bidirectional language interface
+ sparse lifetime activation k << N
+ external non-self-certifying constitutional boundary
```

If the strongest parent product reproduces this at comparable capability/resources, terminal is `PARENT_PRODUCT_SUFFICIENT`.

## 2. Direct parent threats

### P1 — OpenCog AtomSpace / Hyperon

Ownership threat:

- typed graph/hypergraph/metagraph shared knowledge representation;
- declarative, linguistic, mathematical, procedural, attentional, goal-related and other knowledge in one space;
- data and executable programs represented together;
- querying/rewriting as cognitive computation;
- external neural nets/SAT/etc. as callable algorithms;
- language processing integrated with shared knowledge representation;
- explicit ambition for cognitive synergy and self-modification.

Required reconstruction:

- minimal executable AtomSpace/MeTTa task representing at least language + another domain;
- persistent state and procedural invocation;
- query/rewrite cost;
- current scalability/representation limitations;
- what, if anything, OCM warrant/authority/revision adds beyond Values/truth/context mechanisms.

OCM may not claim novelty for `typed hypergraph cognitive field` or `language + procedures in same graph`.

## 3. Parent federation

The decisive comparator is not one parent. Construct at least conceptually and, where feasible, executably:

```text
P* =
    typed shared store/metagraph
  + executable procedures
  + semantic/episodic/procedural memory
  + provenance/TMS-style support revision
  + active retrieval/indexes
  + language parser/realizer
  + active diagnosis/experiment selection
  + algorithm selection/metareasoning
  + external exact checkers/tools
```

The federation receives the same information, domain tools, persistent storage and verifier access as OCM.

If `P*` matches OCM’s capability and resource curve, the architecture residual collapses even if no single historical system packaged all parts together.

## 6. Candidate residuals worth testing

Only the following currently justify serious residual tests:

### R1 — epistemic authority product

Can one field preserve distinctions that common cognitive architectures usually blur:

```text
truth warrant
confidence
speaker commitment
action authority
scope
source independence
formal validity
empirical applicability
```

with exact fail-closed commitment behavior?

### R2 — future-revision-complete persistent competence

Can reusable language/science/procedural competence retain enough support structure to make later revocation exact and local without storing/replaying everything?

### R3 — context-certified representation use

Can the machine aggressively use summaries/quotients while proving when refinement is required, including future-revision behavior?

### R4 — sparse lifetime cognition

Does accumulated competence grow while query work remains tied to active `k`, after all index/consolidation costs?

### R5 — shared abstract control with domain-native semantics

Does one small executive/operator contract genuinely transfer between language clarification, scientific experiment selection and procedural diagnosis?

### R6 — language as non-authoritative interface

Can strong language fluency be obtained while semantic/warrant state remains outside the renderer, with reverse-read preventing renderer hallucination?

### R7 — governed self-extension

Can the field/operator/router evolve while the authority/check/commit boundary remains external and non-self-certifying?

## 7. Required hostile constructions

- OpenCog-like typed metagraph solves the same cross-domain task with fewer special rules.
- Soar-like semantic/procedural memory achieves the same reuse curve.
- NARS-like bounded reasoning matches uncertainty/resource behavior.
- KG + TMS + active-learning composition matches exact revision/probe behavior.
- strong parser/realizer + KG gives equivalent language↔world mapping.
- LLM + structured memory/tools matches capability and lifetime economics.
- OCM wins only because the parent is denied indexes, persistence, learning, tools or verifier access.
- OCM’s “shared identity” benchmark gives it gold cross-domain mappings that parents must infer.
- OCM’s compactness disappears after counting indexes/correspondence maps/provenance/replay state.
