# Cold-process goal-only search through OCM

A research integration of the existing goal-only bridge with the actual OCM
registry, solve/commitment gate, persisted evidence and revoke/reinstate lifecycle.
This follows the [current goal-only decision](../programme/ORDINARY_GOAL_SEARCH_NEXT.md),
not another supplied-target-proof refactoring study. No existing file or frozen
experiment is modified. It is not an installed chat/CLI feature.

## Delivered boundary

`qualify.py` launches nine sequential, fresh OS worker processes: producer;
ordinary enabled; OCM enabled; revoke; ordinary resident-disabled; OCM
resident-disabled; reinstate; ordinary restored; OCM restored. The producer
persists data and OCM state. Consumers do not import the authored fixture module.
The identical goal-only task and resident library go to the unchanged finite
solver in both routes. Six complete generated proofs are independently checked
by fresh instances of the pinned native verifier, one inside each solving worker.
The OCM route uses the real PROGRAMMATIC registry, current warrants, CHECK,
DECISION and COMMITMENT stages. Revocation and reinstatement each happen in their
own worker, and every subsequent worker replays persisted state.

On the explicitly authored fixture, abstract decision counts are **1 / 2 / 1**,
ordinary and OCM agree, and native USED records confirm cohort use / no cohort
use / restored cohort use. Both routes retain identical syntax-bank, grounding
and syntax-emission identities. The declared native prefix here is **two proofs
and four trusted assertions**, followed by the issued goal. This is NOT the
4,245-proof/100-axiom historical cohort qualification from PR #202.

The fixture's inherited name `learned-cut` does not make it learned: it is an
authored synthetic import. No training, protected target, historical scientific
run, new acquisition claim, speed comparison or whole-lifetime benefit is included.

## Run on Linux, Python 3.13

From the repository root, using a previously unused output directory:

```sh
python -B -m unittest discover -s research/goal-only-cold-native-v1 -p test_controls.py -v
python -O -B -m unittest discover -s research/goal-only-cold-native-v1 -p test_controls.py -v
python -B research/goal-only-cold-native-v1/qualify.py --out /tmp/ocm-cold-native-run
python -B research/goal-only-cold-native-v1/audit_mutants.py \
  --source /tmp/ocm-cold-native-run --out /tmp/ocm-cold-native-mutants.json
```

The 43 unit controls prohibit native entry; explicitly labelled checker doubles
exercise selected routing failures and support propagation. The separate cycle
uses the real native checker six times. Twelve mutations of COPIED completed
records must be rejected. No original evidence is rewritten.

The workflow additionally runs 75 existing runtime, output-boundary, callback-
purity, lifecycle and atomic-admission regressions. These are selected engineering
tests, not the full repository suite or historical scientific requalification.

## Source and evidence

[SOURCE_PINS.json](SOURCE_PINS.json) pins 37 bridge/vendor/runtime artifacts from
main `4853a5d0f0d3ca5170aaa2010e4919ae5b88551d` and the canonical filename/byte-hash
manifest of all 163 `src/ocm/**/*.py` files. The latter is computed with sorted
relative POSIX paths, each mapped to `{bytes, sha256}`, and encoded by
`custody.encoded`. Adding, deleting or changing one file invalidates that binding.
The archived parser is extracted and its complete original file population checked.
Local source acquisition used a full tracked archive, not a Git clone; all 8,334
tracked blob identities matched its recorded Git tree.

Worker/adapter source identities are checked before work, before native output
can reach OCM commitment, and after work. Launch records bind requests, PIDs,
return codes, stdout/stderr and observations. Native logs, full databases,
suffixes, used contracts, issued claims and OCM traces are retained. Exclusive
writes preserve failed attempts. These are reproducibility checks, not hostile-
host attestation, an OS security sandbox or a proof of all concurrent crash cases.

Local evidence, development costs and exact commands are recorded in
[evidence/LOCAL-VALIDATION.json](evidence/LOCAL-VALIDATION.json). Hosted validation
is a separate source-bound run. A passing run qualifies this integration only.
