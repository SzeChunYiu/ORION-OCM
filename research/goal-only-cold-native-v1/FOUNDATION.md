# Foundation: a generated proof, a current permission, and a durable answer

## Programme placement and parents

This contribution addresses the implementation boundary after the qualified
[goal-only bridge](../ordinary-goal-native-bridge-v1/INTERFACE.md). It does not
replace the G1–G8 programme, the foundational proposals in PRs #194/#196, or the
[joined historical cohort](../ordinary-goal-cohort-result-v1/CORE.md). Those three
lines have distinct source identities and evidence scopes.

Metamath supplies the formal proof language and conventional verification
mechanism; the existing donor `mmverify.py` and its retained licence are reused.
The [official Metamath description](https://us.metamath.org/) and
[verifier project](https://github.com/david-a-wheeler/mmverify.py) distinguish
checking a supplied formal proof from discovering one. Here the existing finite
ordinary solver discovers a proof from a permitted goal, hypotheses, typed context,
library and resource bounds; the independent checker instance validates its
complete normal expansion. The checker is independent of the search algorithm,
not an independently recruited reviewer or a separately implemented verifier.

Library construction is another obligation. [Stitch](https://arxiv.org/abs/2211.16605)
constructs reusable abstractions from program corpora and evaluates library
compression; this integration neither implements that acquisition mechanism nor
converts compression into a measured online speed or lifetime claim. A method
hand-authored for an integration fixture is not evidence of endogenous learning.

## State and assumptions

Let B denote the exact resident library bytes, C its declared cohort, Q the issued
goal/premises/context/limits, A the adapter and donor source identity, and L a lease
binding ledger head, KSO state, evidence epoch and registry revision. E denotes
the environment evidence, M the cohort permission evidence, and I the issued-task
evidence. The runtime retains B in all modes. Withdrawal changes eligibility of
C's logical actions, not B's syntax hints or the shared grounding computation.

Assume the source files, Python interpreter and operating system execute their
observed semantics; hashes identify bytes but are not authorization; the native
checker and its trace adapter are correct for their declared interface; and the
OCM store, warrant semantics and commitment gate enforce their source contracts.
This adapter does not prove those components sound for all inputs. It records
source checks at particular boundaries, not immunity to a malicious host changing
and restoring files between checks. A hard parent wait deadline bounds a worker's
lifetime, while the inherited solver uses soft work checkpoints internally. No
hard memory bound or general process-receipt theorem is claimed.

The checked task interface is narrow: three homogeneous typed parameters, empty
distinct-variable obligations, bounded syntax and proof expansion, and a finite
search bank. Unsupported syntax, actions or resource exhaustion must remain
UNKNOWN/CANNOT_CHECK rather than global non-derivability.

## Proposition 1: current checked commitment

For this adapter, a successful committed proof answer requires: (i) the expected
lease and source/library binding; (ii) live environment and task warrants; (iii)
a packet byte-identical to the one returned by the invoked solver; (iv) a complete
native check of the exact prefix followed by the exact issued claim; and (v)
unchanged eligibility and dispatcher at the final checker boundary. In enabled
and restored modes, the answer warrant also contains M.

Argument. `restore` checks the persisted method object, scope and evidence support.
`solve` refuses a stale L or a disagreement between M's liveness and requested mode.
The registered backend creates the issued packet. Its checker compares packet
bytes, rejects a non-generated terminal and calls the unchanged native bridge.
That bridge checks the ordered prefix population, unchanged trusted inventory,
issued target/hypotheses, normal proof, current native traces and USED contracts.
The worker rechecks source identities before returning that native result; the
OCM checker rechecks active warrants and dispatcher. Only PASS is returned to the
existing solve/commitment gate. The wrapper warrant is E ∧ I ∧ M when cohort
permission is enabled, and E ∧ I in resident-disabled mode.

The support distinction was found during development: checking M only inside the
callback is insufficient if the committed answer's dependency record omits M.
The successor propagates M into the actual commitment evidence, and a regression
checks the final runtime trace, not merely an adapter field. Twelve audit mutants
include deleting M from that trace despite leaving every success flag intact.
This is conservative support: enabled answers depend on M even when a future task
happens not to consume C. Finer proof-minimal support is a separate optimisation.

Revocation changes authorization, not historical mathematical truth. A proof may
remain valid from the formal axioms while a method ceases to be eligible for the
next dispatch. This implementation does not promise erasure of an answer already
spoken or automatic revision of every historical downstream object.

## Proposition 2: cold-process intervention, with fixed hints

For the recorded authored cycle, the ordinary and OCM routes consume the same Q
and B in three conditions: enabled, resident-disabled, restored. Each solving
worker is created by an explicit fresh OS process launch after the predecessor
exits. It reconstructs inputs from persisted data and does not import the fixture
constructor. Thus no live producer Python object or search cache is inherited by
the consumer. Interpreter, code, resident library and parser are intentionally
shared by identity; this is not process-level security isolation.

The read-only audit requires all nine ordered launches. It verifies lease chaining,
source generation, task and library identities, every full native proof population,
current USED membership, and exact ordinary/OCM proof and decision-count parity.
It requires unchanged bank, grounded-action and syntax-emission identities across
conditions. The native checker is freshly instantiated in each solving worker;
there is no seventh process per proof and no reused success flag as authority.

The accepted authored result is one, two, one abstract decisions, with native
cohort consumption present, absent, present. This proves the intended mechanical
intervention works on this fixture. It is not independent acquisition, generalization
on new proof families, or OCM superiority: the conventional parent matches OCM.
The task was explicitly authored to exercise the mechanism, not sampled as an
unseen scientific population. No statistical significance calculation is warranted.

## Proposition 3: bounded failure does not become a committed proof

The ordinary route retains the solver's bounded-negative or UNKNOWN terminal
without calling the native verifier when there is no generated proof. The OCM
checker returns CANNOT_CHECK in that case, so the solve gate withholds commitment.
A native refusal likewise cannot produce a committed proof. A timeout, process
failure, missing observation, altered log or incomplete launch population prevents
successful qualification. Unit controls test UNKNOWN and native refusals with
labelled doubles; the separate native cycle tests real positive checking.

These facts do not prove completeness for an unbounded theorem language. They
also do not promote a supported negative in a finite bank into impossibility, nor
make a deliberately tiny work budget evidence against a mathematical statement.

## Resource accounting and remaining completion gates

Outer worker elapsed times are disjoint launch-to-exit measurements and may be
summed for this sequential control. Nested solver/native timings are explanatory
subintervals and must not be added again. CPU totals are worker process increments;
peak resident memory is a maximum, not an additive saving. The local source archive,
software development, all earlier exploratory runs and paper/experiment design
are outside the final cycle's elapsed measurement. Development run counts are
retained separately; this is not a complete lifetime ledger. No timing ratio is
reported as a speedup, and the abstract decision-count reduction is not latency.

A formal-methods review perspective checked input, proof and support implications;
a runtime perspective checked restart, revision, registry and persistence; an
experimental-design perspective checked fixed hints, parent equality and cost
scope. These were roles applied by one author, not independent team reviews.

This supplies an executable source-bound integration prerequisite. The next
programme-level inference still requires a reviewed, prospectively allocated
historical-cohort goal-only study with proof/label/dependency exclusions enforced
before target access. Separately required are useful acquired structure, protected
transfer and composition, complete lifecycle economics, heterogeneous persistent
development, stronger equally equipped parents, and independent replication.
Those obligations are not closed by this authored fixture. Installed-product
integration, full-checkout CI, concurrency/crash qualification and expert review
are also separate from the selected passing controls reported here.
