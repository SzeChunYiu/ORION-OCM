# OCM integration note: prior-free GMI

## Purpose

This note binds the prior-free GMI formalization to the current OCM programme without laundering research evidence or treating the current KSO decomposition as a primitive.

The OCM README states that Language KSO, Method KSO, Wisdom KSO, field/subject/domain hierarchies, symbolic grammar, hypergraphs, and related structures are candidate organizations to test and replace. The formal core here makes that discipline explicit: named architecture components are implementation hypotheses. The invariant target is the obligation-relative predictive/control structure plus the resource-conditioned operational morphology.

## What changes immediately

Architecture-benefit, self-reorganization, controller-growth, routing, working-state, and decision-core studies should state the following before making a morphology claim:

1. **Obligation** — the exact task/safety/performance object being preserved.
2. **Ecology** — the worlds, perturbations, interventions, or data-generating structures over which the claim quantifies.
3. **Boundary** — what memory, clocks, tools, retrieval, external evaluators, random seeds, and side information are inside or outside the machine.
4. **Probe resolution** — which differences count as distinct operational morphologies.
5. **Resource vector** — latency, state, communication, energy/proxy cost, samples, external calls, development cost, or other claimed coordinates.
6. **Necessary outer bounds** — constraints applying to every admissible solution.
7. **Constructive inner realizations** — explicit OCM and matched alternatives with verified profiles.
8. **Fiber test** — whether an optimal profile identifies one operational morphology or several tied classes.
9. **Developmental test** — whether the declared search/update process can actually reach the claimed morphology within budget.

## OCM-specific consequence

A result such as “the KSO organization is better” is under-specified until the boundary and resource vector are fixed. The same semantic behavior can move memory into retrieval, recomputation, a clock, an external controller, or another agent. Such moves can make a local component look smaller without reducing system-level information demand.

Conversely, a named mechanism can be replaced by a different implementation without changing the obligation-level morphology if the two systems are equivalent under the registered probes and resource coordinates.

This is particularly relevant to OCM self-reorganization. A reorganization policy that searches KSO-like encodings before other operationally equivalent encodings carries an architecture/search prior. That is acceptable as an engineering heuristic, but the resulting reachability claim is search-prior-sensitive unless the development kernel is proved to descend to the operational quotient.

## Relationship to current evaluation priority

The OCM programme currently requires renewed scientific evaluation after the runtime revision. This formalism does not substitute for that evaluation. It changes the standards under which architecture-level conclusions should be interpreted:

- authored replay is engineering evidence, not morphology closure;
- historical M11/M12 terminals remain historical/reopened as declared by the repository;
- an OCM-vs-parent win on one scalar metric is not a global architecture theorem;
- a protected matched comparison can support a local profile claim only on its declared ecology/resource coordinates;
- a nontrivial morphology theorem requires the necessity/construction sandwich or an equivalently strong certificate.

## Recommended next registered experiment

A suitable OCM-specific successor is a frozen morphology-phase experiment over one bounded obligation where at least two implementations exchange memory, communication, and recomputation. Before execution:

1. derive a state/channel lower bound from the task;
2. freeze a small substrate/resource parameter family;
3. construct OCM and at least one non-KSO realization that satisfy the same interface contract;
4. predict a frontier transition as the resource weights vary;
5. test the transition without changing the morphology vocabulary after outcomes are visible.

This would move the theory from framework-level closure toward a genuine OCM physical-morphology phase law.
