# Native method serving research module

This is a research-only OCM serving adapter. It is not an installed CLI/product,
endogenous acquisition system or scientific novelty claim. Its scope is three class
atoms, empty ambient DV, one fixed finite ordinary library/bank and two externally
acquired open methods. Layered search remains the default; indexed search is optional.

## Read first

- `native_engine.py`: shared conventional engine, fresh method qualification and native
  output checking. Direct serving and OCM call these identical functions.
- `native_runtime.py`, `native_request.py`: actual PROGRAMMATIC registry → SV solve,
  exact issued packet, current warrants and active-state cleanup.
- `native_store.py`, `native_journal.py`, `native_receipt.py`: imported KSO procedures,
  separate proof/applicability evidence, durable intent/outcome, exact core-event and
  native-checker custody. Historical restore replays proofs; saved flags are not authority.
- `native_inputs.py`, `native_macros.py`, `native_packet.py`: exact external input pins,
  six atomic bijections and returned-proof provenance with normal expansion checks.
- `vendor/`, `TRANSPLANT.json`: necessary earlier mechanisms with original hashes and
  declared adaptations. The full mmverify MIT license remains in the vendor directory.

No old receipt qualifies transplanted or successor code. The measured candidate02
source remains archived unchanged; this portable integration has a distinct source
identity and does not inherit that native outcome receipt. Engineering controls replace
computation and checking with labelled doubles where they exercise OCM routing. The
pytest autouse fixture prohibits calling NativeChecker.verify, including in CI. Tiny
compiler/scheduler controls execute real pure code. The 3,159 small cases cover listed
two-rule sets/tail templates, not all possible grammars. They are not native proof results.

## Portable engineering controls

Use Python 3.11.14 and pytest 8.3.5 on Linux, with the command below from the repository
root. The explicit `native-portable-controls` job in `.github/workflows/unary-language.yml`
runs this same collection. Tests and native assays must not run on the Mac.

```sh
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 PYTHONDONTWRITEBYTECODE=1 \
PYTHONPATH=src:research/native-method-serving-v1 \
python -B -m pytest -q research/native-method-serving-v1 -m 'not native_actual_input'
```

This selects 42 portable controls and deselects three `native_actual_input` controls.
CI retains JUnit and a source-bound receipt listing selected/deselected node IDs and
native guard calls. It neither downloads a corpus nor dispatches a native assay.

## Separately declared actual-input controls

The three controls cover sealed-projection tamper, disk tamper, and six learned-template
bindings/wrong-hole refusal. They need the separately retained exact external bundle;
it is not checked into git. Explicitly select `-m native_actual_input` and supply
`--native-bundle=/path/to/bundle` only for an authorized input qualification. These are
pure input/compiler checks and retain the same native-verification prohibition.
They were not rerun for this successor integration.

Search receives the permitted parent/bank and method payloads, with no training history
or full mathematical database. Custody hashes PREFIX.mm bytes; only the independent
checker interprets that prefix. No prefix content is passed into serving search.

This module remains outside installed `src/ocm` packaging. A product/CLI would require
separately reviewed integration; this PR delivers research source and portable controls.
