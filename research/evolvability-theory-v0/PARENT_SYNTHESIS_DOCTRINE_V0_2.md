# Machine Epistemics V0.2 — Parent Research Synthesis and Absorption Doctrine

**Status:** programme doctrine for PR #150 and the #143/#145/#151 research programme.  
**Purpose:** treat existing research as accumulated scientific knowledge to reconstruct, absorb, generalize and test—not as adversaries whose only role is to be beaten.

## 1. Core principle

Machine Epistemics is not premised on inventing every cognitive mechanism from scratch.

The relevant scientific world already contains mature pieces of the problem:

- causal discovery and active diagnosis;
- TMS/ATMS, provenance and incremental databases;
- cognitive architectures;
- program/library learning;
- continual/meta-learning;
- information-gathering and experimental design;
- AutoML, program repair and evolutionary search;
- neural memory, routing and representation learning;
- open-ended self-improving agents;
- developmental and curiosity-driven learning.

These are **donors, parents and constraints on the global theory**.

The programme asks:

> What common computational principles make these apparently different mechanisms instances of one persistent developmental machine, and what new predictions follow only when they are organized together under one epistemically governed lifecycle?

Therefore:

```text
PARENT_SUFFICIENT for mechanism X
!=
X is useless to Machine Epistemics
```

It means:

```text
novelty(X) is parent-owned
+
X may be absorbed into the generalized theory/OCM
+
any residual claim must move to a higher-order synthesis or new prediction.
```

## 2. Two independent questions for every parent

Every external mechanism must answer both:

### Q-A — Scientific ownership

```text
Does the parent already explain the claimed mechanism/effect?
```

If yes, OCM does not claim invention of that mechanism.

### Q-B — Theory contribution

```text
What does this mechanism teach the generalized theory, and should OCM adopt it?
```

A parent can kill a narrow novelty claim while strengthening the final machine.

## 3. Absorption lifecycle

For each important paper/project/mechanism:

```text
DISCOVER
→ RECONSTRUCT faithfully
→ STATE assumptions/invariants
→ IDENTIFY strongest result + known failure boundary
→ MAP to Machine Epistemics objects
→ classify ADOPT / ADAPT / GENERALIZE / REJECT / OPEN
→ CHARGE imported information/implementation as prior
→ INTEGRATE only if useful
→ TEST in its native regime
→ TEST under reminted cross-domain semantics
→ SUBTRACT original parent claim
→ KEEP only emergent residual/new law
```

Definitions:

- `ADOPT`: use the parent mechanism substantially as-is; no novelty claim for it.
- `ADAPT`: alter it to satisfy OCM lifecycle/epistemic interfaces; novelty belongs only to demonstrated adaptation residual.
- `GENERALIZE`: derive a domain-neutral contract that covers the parent and additional mechanisms/domains; must yield new falsifiable consequences.
- `REJECT`: faithful testing shows it does not improve the declared frontier or violates required invariants.
- `OPEN`: evidence or faithful reconstruction is not yet sufficient.

## 4. What counts as synthesis novelty

Simply connecting known components is systems integration. That can be useful engineering but is not by itself a foundational scientific contribution.

The synthesis becomes scientific only when it yields at least one of:

### S1 — Unifying formal object

A compact formalism explains several previously separate mechanisms without erasing their semantic distinctions.

Example target:

```text
M_t = (F_t, O_t, Π_t, C)
```

with parent mechanisms appearing as special cases/views/operators rather than independent ad-hoc subsystems.

### S2 — New relationship/law

The synthesis exposes a measurable relationship not contained in one component alone.

Current candidate:

```text
developmental evolvability
requires the joint regime of κ locality, Ω self-identifiability and χ repair searchability
```

rather than modularity, self-modeling or search alone.

### S3 — New cross-domain invariance

The same learned computational contract survives a change in validation semantics.

Examples:

```text
DISTINGUISH:
language clarification
≈ scientific experiment
≈ coding diagnostic
≈ mathematical proof/counterexample probe
```

The mapping itself cannot contain the target solution.

### S4 — Emergent system prediction

Combining mechanisms predicts a lifecycle/scaling phenomenon that the isolated components do not establish.

Candidate:

```text
as verified developmental experience accumulates,
future related acquisition and self-repair become cheaper
because reusable structure improves locality, identifiability and searchability.
```

### S5 — Principled boundary / impossibility result

The unified theory predicts when explicit structured cognition should lose to global/statistical adaptation—for example dense coupling, low diagnostic information, large repair entropy or excessive maintenance.

A negative phase boundary can be a major theoretical result.

## 5. Parent product, not straw-parent competition

The strongest comparator may be a **composition** of mature mechanisms.

For example:

```text
active diagnosis
+ probabilistic self-model
+ TMS dependency maintenance
+ library learning
+ learned router
+ AutoML/program repair
+ persistent memory
```

may be a stronger explanation than any isolated parent.

OCM only earns a residual after this parent product receives materially matched:

```text
information
tools/checkers
persistent memory
candidate language
adaptation permissions
resource budget
```

If the parent product reproduces the whole signature, terminal is `PARENT_PRODUCT_SUFFICIENT` and the generalized theory should absorb that explanation.

## 6. Research inheritance is cumulative

The programme should maintain a cumulative graph:

```text
paper/project result
→ mechanism abstraction
→ assumptions / failure boundary
→ OCM/general-theory mapping
→ integrated experiment
→ cross-domain pressure
→ surviving law or negative boundary
```

A result should not disappear merely because it was parent-sufficient.

For every negative/subtraction record, ask:

```text
WHAT DID THIS RESULT TEACH THE GENERAL THEORY?
WHAT SHOULD OCM ADOPT, SIMPLIFY OR DELETE?
WHAT NEW PREDICTION FOLLOWS AFTER ABSORPTION?
```

## 7. Information accounting for imported research

Absorbed parent knowledge is prior information.

Record at minimum:

```text
source identity/version
mechanism description
implementation/code imported
hand translation/generalization
hyperparameters/configuration
parent training data when relevant
OCM mapping supplied by researchers
```

Do not call an imported mechanism autonomously discovered by OCM.

Later OCM may rediscover/reconstruct a mechanism independently, but that requires a separate protected origin/provenance study.

## 8. Developmental use

Issue #151 should use external research similarly to education:

- early OCM may be given established operators or instructional structure as declared priors;
- later experiments test whether it learns when/how to use, combine, scope, revise and eventually rediscover/generalize them;
- protected tests distinguish taught competence from independently acquired competence.

The goal is not an artificially isolated machine that ignores human scientific knowledge.

The stronger goal is:

> a machine capable of incorporating accumulated human computational knowledge into one persistent cognitive organization, then using experience to reorganize/generalize that knowledge further.

## 9. Publication/novelty wording

Do not write:

> Unlike prior work, OCM can self-model / store dependencies / learn abstractions / use active probes.

when parents already do those things.

Prefer:

> We synthesize established mechanisms under a common persistent epistemic lifecycle and test a new prediction about their joint developmental dynamics.

Then name exactly which components are parent-owned and which relationship/prediction is new.

## 12. North star

The programme is successful even if many individual mechanisms are fully parent-owned.

The strongest possible contribution is not a bag of mechanisms nobody else has seen.

It is:

> **a compact generalized theory that correctly explains which mechanisms are needed, how they relate, when they should be used, how one persistent machine can learn and reorganize them across domains, and what measurable developmental laws and failure boundaries follow from the synthesis.**
