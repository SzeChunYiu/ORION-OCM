## Registered mechanism

Terms are closed JSON arrays: `sort`, de Bruijn `var`, numeric `const`, `app`,
`pi`, and `lam`. The small universe grammar and constant registry are explicit.
No source text, tactics, imports, callbacks, learned weights or target-name routing
are candidate inputs. The fixed target is separately hashed `Target.lean`.

The engine validates closed types, introduces leading Pi binders, indexes known
terms by normalized type and constructs applications in successive depth layers.
Substitution is capture-avoiding; every proposed application is type checked.
The complete returned term is checked again by the symbolic engine and independently
by Lean. Proof-body constant use and annotation-only use are reported separately.

Default operational bounds are depth 5, 5,000 terms, 20,000 applications,
32 introductions, 4,096 nodes and 20,000 normalization steps. These define exposed
engineering controls, not optimized scientific parameters. Exhaustion certifies only
the registered finite application fragment. It cannot prove the theorem false.
Operational exhaustion is `CANNOT_CHECK`.

There is no arbitrary internal lambda/witness synthesis, induction, general
higher-order unification, learned method library or evidence-revision eligibility
mechanism in this tranche. Their qualification remains outstanding.

## Learner and checker separation

The worker receives four reviewed Python files, task JSON, a copied Python standard
library and individually inventoried loader dependencies. It receives no fixture
builder, historical Composition proof, repository, model package or host network.
An import/dispatch audit is sealed before search; the parent validates its module
inventory and recomputes constant occurrence metadata from the returned AST.

Bubblewrap supplies separate user/PID/network namespaces, read-only mounts and root,
dropped capabilities, bounded process output, timeout and process-group cleanup.
The checker separately receives a pinned Lean toolchain and fresh staging directory.
The Python audit hook is a guard for this reviewed program, not an arbitrary-code
sandbox or proof against operating-system vulnerabilities.

The trusted renderer preserves complete explicit application spines. It first
infers a transparent closed helper, then checks that helper against the independently
fixed theorem. Only unused-variable and proposition-definition style linters are
disabled. Kernel checks and the strict final axiom audit remain enabled.

Lean identity, all fixed sources and generated candidate data are checked. Foundation,
Target and Candidate are compiled freshly. A process exit of zero alone is insufficient:
the final expected theorem must report only permitted axioms and produce a fresh
`.olean` artifact. The allowlist is `propext`, `Classical.choice`, `Quot.sound`;
the actual dependency list is recorded. An empty list is an observed result, not
an additional hard guard in this version.
Type mismatch is `REJECTED`; missing tools, incomplete processes, source drift,
unexpected diagnostics and unqualified checks are `CANNOT_CHECK`.

## Commissioning matrix

| Assignment | Required observation |

| Original, fresh-process restart | Exact-target kernel acceptance; same candidate and work counters |
| Equality signature only | Accepted proof without either supplied Foundation proof lemma |

| Ill-typed closed candidate | Actual candidate type mismatch rejection |
| Missing checker | Missing registered runtime refusal before process launch |
| Corrupted staged target | Source identity refusal before process launch |
| Raw source, admitted proof, unknown constant | Constructor/constant refusal before staging |

Negative controls must reach their intended failure stage. An unrelated error is a
failed control even if it also returns `CANNOT_CHECK`. Unit/process controls additionally
exercise harmless renaming, premise order, forbidden imports/dispatch, input schema,
root/network boundaries, output limits, timeout cleanup and custody changes.

All fourteen matrix assignments are retained. The driver snapshots top-level sources,
copies and binds the runtime manifest, verifies full copied runtime inventories before
and after, and checks source/manifest custody around each case. A changed source or
runtime cannot inherit an earlier receipt. Archive seals bind preserved raw files;
compiled artifacts are represented by original hashes when omitted from Git.
