## Mechanism established

The source environment is exported as native kernel data. Preparation uses an
independently registered target expression and ordered universes, allowed roots,
excluded declarations and independently registered primitive/axiom identities.
Dependency walking covers declaration types and bodies, opaque definitions,
inductive families, recursors, projections and implicit literal requirements.
The permitted environment is replayed from empty kernel state and checked against
the registered identities. Emitted tables omit unreachable private expressions.

A separate fresh checker receives only the permitted packet, target, registration,
primitive packet and declaration-free candidate expression packet. It inserts a
checker-owned theorem with the registered type through Lean's checked declaration
API. No source elaboration, tactics, instance search or neural proposer runs there.
Axiom closure is checked after kernel acceptance. A preparation receipt cannot be
replaced by a candidate's self-authorized, internally consistent environment.

Positive controls cover composition, polymorphism, definitions, opaque bodies,
mutual/nested inductive families, recursors, projections, literals and quotient
primitives. Registered refusals cover changed targets/universes, unauthorized
axioms or primitive identities, excluded aliases, malformed/missing families,
unsafe/partial declarations and invalid candidates. A shared stress candidate
passes the baseline and produces a deterministic kernel resource refusal under
its separately registered constrained setting.

## Parent absorption and corrections

This is engineering built on Lean4.33.1, pinned lean4export
`15f6055e299ad5b89345e533cc2192f4cc00f659`, and Comparator
`3927ad383f208ae977c340a91c48ac9b497d2097`. Original sources and Apache-2.0 licenses
are retained. These mechanisms receive parent attribution, not OCM novelty credit.

The exporter interns expressions using kernel-term alpha equality, which ignores
binder names and annotations. An initial stricter comparison incorrectly refused
valid exports. The corrected replay comparison follows that parent normalization
for expression fields while retaining all other declaration metadata and ordered
universe identities. This is not equivalence of source-level binder interfaces.
The inserted checker theorem still receives a strict target/proof identity check.

A separate checked-export adapter reads the replayed kernel environment; the raw
parent exporter remains intact. Development failures and the exact adapter change
are retained. The final47 were frozen before execution: a normalization-registration
mutation remains a separate native development control, and one ill-typed candidate's
expected reason was prospectively tightened to `declaration type mismatch`.
No failed final row was removed or reclassified after the run.

## Isolation, cost and evidence scope

The generic executable links no fixture modules or objects. Its seven ELF mounts
contain the checker and six measured library objects, without source code or fixture
caches. Preparation also receives the registered source export. The separate checker
receives only the issued permitted/target/registration/primitive packets and candidate;
custody sources and the full export stay outside its guest mounts. Two registered
traced operations, prepare and check, passed with complete cleanup. Static closure
and these observed operations do not establish universal filesystem behavior or
whole-host security. Host Python, its standard library and the OS remain trusted.

Complete commissioning cost, including final hashing/sealing, was **30.446151392 s**
wall, **16.237970 s** child user CPU and **3.334927 s** child system CPU.
`RUSAGE_CHILDREN` reported **22,436 KiB maximum RSS**; this is not an aggregate
simultaneous process peak. Acquisition, compilation, development and the separate
profile work are outside this timing and remain separately recorded or unmeasured.
Nested driver timings must not be added to the outer envelope.

The package occupies 125,285,768 bytes across 50 retained files, mostly the native
executable. ELF payloads remain in the external qualified runtime; the repository
retains their exact inventory and evidence rather than treating omitted payloads
as reproduced binaries. Native rebuild and runtime requalification remain necessary
when moving execution to a different environment.

Current host authentication rehashes the full retained preparation inventory,
including the evaluator-only source export. Its audit work can scale with source
size even though that source is not mounted in the native checker. No local-work
or warm-serving speedup follows from this qualification.
