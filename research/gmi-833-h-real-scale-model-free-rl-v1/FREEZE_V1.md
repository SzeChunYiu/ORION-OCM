### The ecology, registered before it is built

`F_ML` (`SIGMA_HMLR`). The tokenised source is read as an **experience
table**. For every token `w` and every split position `k` with
`2 <= k <= len(w) - 1`, the table records one experience

```
context           q     = w[:k]     the descriptor the agent is in
action            a     = w[k]      the action the token records there
received outcome  rho(a) = 1 iff a is in V,    V = {a, e, i, o, u}
```

`V` is the five-letter subset of the source's own character inventory
registered here, before any count. The experience-table size is

```
T = sum over tokens of max(0, len(w) - 2)
```

computed by the executor from the bound bytes: a token shorter than three
letters contributes no experience. (The descriptor closure of `D` restricted to
the positions that record an action.)

A task is a **stored experience**. Its **state** is the registered projection

```
sigma(q) = (q[:1], q[-1:])          the first and the last letter of the context
```

so the table partitions into accumulated-feedback cells. For a stream `J` of
positions the accumulated store is

```
N_J(c) = the number of experiences of J whose state is c
P_J(c) = the exact sum of their received outcomes        (the accumulated mass)
```

and the **protected decision** is the boolean threshold on accumulated outcome
feedback

```
y_J(q) = 1      iff   2 * P_J(sigma(q)) >= N_J(sigma(q))
```

with the **registered fallback**: when `N_J(sigma(q)) = 0`, the stream's
majority constant `maj_J = 1 iff 2 * sum_c P_J(c) >= |J|` is read out instead.
The executor asserts `maj_J = 0` for every registered stream before any
enumeration, which fixes the fallback at `0`.

This is the row's mechanism stated as a protected interface: a query is
decided by **accumulated outcome-feedback mass experienced at the query's
state** — a stored value updated by experienced reward frequency — not by any
single stored item and not by any single dimension of the query.

Slices, fixed here before any fit: the experience list is partitioned by the
7:1 rule registered in `FREEZE_V1_SLICE_ADDENDUM.md`, giving

```
n_fit = (T * 7) // 8     >= 100,000
n_held = T - n_fit       >= 20,000
```

which clears the `R11` real-scale bar (n_fit ≥ 100k / n_held ≥ 20k on a
sha256-bound external REAL source, exact arithmetic, independent oracle).

## 5. Grammar

`G_ML`: a family-blind grammar derived ONLY from the sha-bound bytes of `D`.
The experience table `F_ML` (contexts, actions, received outcomes), the
registered state projection, the cell-accumulation table, the vocabulary index
over stored contexts, and a charged-cost model over the table lookup and the
accumulated propensities. No family-level macro, no hand-encoded
reinforcement-learning routine, no value-iteration or policy-gradient routine,
and no reference to any external implementation. Section `R03` asserts the
grammar contains no reinforcement-learning macro, and `R04` recovers the
family from the grammar alone. The generator receives no family name and no
row name; structural class names are attached only after the winner rule runs,
by a classifier that reads the arm name and nothing else.

## 6. Arithmetic

Exact integer arithmetic for every reported quantity: every claimed number is
an exact integer decision count (prototype agreement, sign-decision errors,
null errors, ladder errors, charged-cost units, crossover index) or an exact
comparison written as an integer cross-multiplication (`2 * P >= N`,
`10 * P >= j * N`). No float enters any comparison, count, loss, or claim.
There is no real-valued fitting routine whose output requires a
rationalisation operator, so this package carries no arithmetic addendum: the
exact-integer form is complete in this freeze and the slice addenda.

## 7. Budget

Registered table, node and index budgets for the family-blind search, stated
before any fit, identical for every arm: the experience table, the vocabulary
index over stored contexts, and the cell-accumulation table are all bounded
and fixed in the executor. Resource crossover (`R07`) varies the store budget
and asserts the held-out error count is monotone non-increasing in it.

## 8. Predictions, frozen before any outcome

Held-out frozen predictions are written to the frozen-prediction record
(`R08`) before the oracle is run, exactly as in
`gmi-833-h-real-scale-classical-v1`: the fit is completed on `n_fit`, the
prediction for each held-out query is emitted to the frozen record, and only
then is the independent oracle (Section `R09`) run and compared.

## 9. Falsifiers

A held-out exact prototype agreement below the registered baseline; an exact
sign-decision error count above the registered bound; a null that performs
comparably to the family on the same slice rule; a matched negative control
under which any arm of `R` clears the registered margin; or any cross-scope
gate composition — any one falsifies the claim ceiling.

## 10. Controls

Matched negative control (`R05`): under a received outcome built from a
registered seed and from the experience's own position in the table and from
nothing else — so that **no cell's accumulated mass reflects the outcomes its
own experiences received** — no arm of the registered language may clear the
registered margin, while the raw sibling arms are left untouched by the swap.
The screen asserts `CLEAN` only when the no-alarm case also fires (the
checker's own controls are asserted to fire).
