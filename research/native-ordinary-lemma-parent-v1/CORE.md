# Ordinary learned-theorem parent

**Decision, 8 September 2026:** compare a learned executable proof recipe with
the same checked result installed as an ordinary derived theorem. Give the
ordinary parent its full qualified applicability. This is a prospective design;
no new learning, proof search, corpus access or native qualification was run.

[CONTRACT.md](CONTRACT.md) defines the comparison, costs and interpretation.
[SOURCE-READS.json](SOURCE-READS.json) binds the inspected source and excerpts.
[DOMINANCE.md](DOMINANCE.md) proves the conditional tree-cost comparison, including
zero-premise actions. It narrows the empirical question to implementation and costs.

The current recipe interface permits six atomic bijections. An ordinary theorem
can have a broader substitution interface. Restricting the conventional parent
to those six cases would hide a potentially useful conventional mechanism.

Adding theorem labels also changes the native checker environment. A fresh,
versioned library must check their proofs; the frozen serving receipt cannot
authorize that successor. Typed extraction qualification comes first.

No speedup, learning benefit, lifetime advantage or novelty follows from this
source review. Ordinary theorem reuse may prove to be the best initial design.
