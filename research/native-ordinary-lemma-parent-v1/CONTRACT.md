## The question

Does a reusable recipe improve future solving beyond installing its independently
proved sequent as an ordinary theorem? Both forms must receive the same experience,
admission evidence, current eligibility and available mathematical library.
This isolates representation and execution; it does not yet test an OCM-specific
learning or revision policy. A separate matched host comparison remains necessary.

## Mechanical projection and current authority

1. Start with the exact candidate emitted by the registered learner. Preserve
   method identity, discovery history, correctness warrant, applicability and scope.
   Do not author a more convenient theorem after observing a target.
2. Project the actual admitted assertion into its label, ordered floating and
   essential hypotheses, distinct-variable constraints and conclusion. Bind the
   canonical method ID to that complete assertion contract and its checked proof.
   Treat source spans as provenance, not a replacement for the assertion contract.
3. Append the exact declarations and proved `$p` assertions to a successor native
   library. Add no new `$a` assertions. Check the full expected theorem population,
   exact trusted axiom identities and proof dependencies against that successor.
4. Bind the parent index, checker bytes, context, projection and source version
   together. Existing `PREFIX.mm`, `PARENT.json` and population checks cannot be
   silently relaxed. A previous native receipt is provenance only.
5. Restart the consumer from the sealed projection after producer exit. The parent
   receives all admitted reusable information that the recipe consumer receives.
   Neither arm receives a protected target theorem or its excluded proof closure.
6. Derive service eligibility from the same current proof/applicability/scope policy.
   Removal of a method disables all its derived-theorem/action aliases as well as
   its recipe. Preserve independent correctness warrant when only discovery
   provenance is withdrawn. Do not equate library residency with permitted use.

## Two complementary comparisons

**Primary conventional parent:** ordinary theorem reuse with its full independently
qualified substitution domain over the registered bank. Composite terms and repeated
bindings may be valid even when the recipe currently supports only atomic bijections.
Do not disable that capability merely to equalize the recipe implementation.
Respect exact types, grammar, syntax proofs, mandatory variables and DV constraints.
Unsupported substitutions receive an explicit boundary result; no hidden fallback.

**Representation diagnostic:** additionally compare equal qualified substitutions,
ordered premise ports, target obligations and available actions. This narrower
comparison isolates encoding/dispatch cost. Label it as a restricted diagnostic,
and never use it alone to call the ordinary parent the strongest available parent.

An ordinary theorem may expose only its premise/conclusion boundary to search.
The present recipe also demands bank membership for its internal conclusions.
Record this difference: it is an implementation restriction with possible changes
to the finite action space. Equal theorem meanings do not imply equal search spaces.

Use the same search objective and cutoffs where comparable. Preserve ordered repeated
premises. Record any extra resource needed for broader parent grounding separately.
Keep deterministic tie order visible; equal optimal cost does not imply equal action
attempts or identical proofs. Do not retune target-specific ordering after a run.

## Costs and qualification controls

Charge acquisition, admission, projection, cold compilation, storage, current-warrant
checks, search, proof construction, native checking and revision. Separate shared
costs and costs unique to each representation. Report them before amortization.
Warm calls alone cannot establish lifetime benefit.

Retain action counts, substitution attempts, candidate counts, ordered premise work,
intermediate bank requirements, bytes resident/materialized, calls and measured
wall/CPU/RSS. Mark unmeasured quantities explicitly. Native abbreviated proof length
and search application cost are distinct quantities.

Also produce a validated normalization that expands only the added learned theorem
labels into their bound original-library proof recipes. Preserve original parent
theorems as labels; this is not expansion to axioms. Account for floating syntax
substitution and repeated essential ports. Bound and charge normalization separately;
compare reconstructed targets and native validity before interpreting token counts.
Never infer proof identity merely from matching theorem conclusions or tree costs.

Before a task comparison, use authored interface controls for changed statement,
wrong type, reordered/repeated premise ports, stale library/eligibility, changed
projection and removed method aliases. Verify that the unchanged valid case passes.
Wrong inputs must fail at the claimed boundary. These controls must not inspect
protected tasks or choose a candidate for later apparent success.

Freeze a separate actual execution protocol once typed reconstruction and the
ordinary-theorem consumer are qualified. Register task allocation, parents, accepted
substitutions, cost windows, refusal terminals and allowed failure repairs beforehand.
Do not rerun the historical native controls under this source-review document.

## Interpretation and next decision

If both forms yield the same useful capability, report ordinary theorem reuse as
parent sufficient for that capability and choose by measured total cost. If the
ordinary parent is stronger, adopt its mechanism. If a recipe helps, identify whether
the cause is search-space restriction, indexing, proof construction or a transferable
method policy, then transplant that mechanism into the matched conventional host.

A scientific contribution requires a supported mechanism and a meaningful residual
after those comparisons. Neither a renamed theorem nor a shorter abstract proof
establishes cognitive compression, generalization, OCM novelty or LLM-level ability.
