# AJ5 — G0 as compiled presentation, not operational bottom

## Scope

This tranche consumes AJ1–AJ4 and the exact merged `G0-reg-v1` parent object. The parent file is pinned by Git blob `6c80e7b1ee0cceedb5dc48eaf28bd3011750d80a`; semantic drift fails closed.

The result is a **presentation/compilation theorem at registered bounded scope**:

`operational roles + registered natural-register carrier -> lower micro-processes -> G0 instruction presentation -> executable G0 realization`.

It does not claim that the lower micro-operation list is an absolute ontology.

## Primitive classification

### READ — DERIVED

`INPUT_TAKE ; REGISTER_WRITE ; CONTROL_ROUTE`.

The input channel and mutable register are lower process/interface roles. `READ` is their named G0 macro.

### EMIT — DERIVED

`REGISTER_READ ; OUTPUT_APPEND ; CONTROL_ROUTE`.

### INC — DERIVED, relative to the registered natural carrier

`REGISTER_READ ; NATURAL_SUCCESSOR ; REGISTER_WRITE ; CONTROL_ROUTE`.

The G0 instruction is derived. The existence/cost of exact natural successor is a substrate/representation premise and is **not** promoted to a law of physics.

### DECJZ — DERIVED, relative to the registered natural order/predecessor

`REGISTER_READ ; ZERO_TEST ; CONDITIONAL_ROUTE ; [POSITIVE_PREDECESSOR ; REGISTER_WRITE]`.

The nonzero write path has five lower micro-operations; the zero path has three.

### HALT — PRESENTATION_ONLY

`HALT` names the terminal/no-successor control convention. A terminal outcome can be represented without a dedicated syntax token in other presentations.

Thus none of the five current G0 instruction names is established as an ontologically irreducible intelligence primitive.

## Semantic-preservation microscope

The checker imports the exact parent G0 implementation and exhausts all `11^2 = 121` two-label, one-register programs constructed from the five current instruction classes. Each is run on four input cases under a parent step budget of eight, for 484 parent-vs-lower executions.

Protected comparisons are:

- terminal outcome;
- emitted I/O trace;
- final registered values;
- parent instruction-step count used only to state the compilation bound.

There are zero semantic disagreements.

The lower runtime uses at most five registered micro-operations per executed G0 step. Static expansion is at most five lower operations per G0 instruction. No new persistent register is introduced; the interpreter uses constant scratch temporary/predicate state.

The precision/resource caveat is binding: the compiler inherits the parent's unit-cost exact-natural-register convention. It does **not** prove constant physical cost for arbitrarily large integers and does not hide bit complexity inside the theorem.

## Materially different lower presentation

The same five instruction behaviours are independently presented as a finite declarative transition relation over:

- all 11 instruction forms at the two-label scope;
- register values `{0,1,2}`;
- input tails `epsilon`, `[0]`, `[1]`.

This gives 99 relation rows. The sequential micro-process presentation and the relational presentation agree on all 99 rows.

This is a materially different semantics style—sequential operational decomposition versus declarative relation table—at a finite registered slice. It is not a theorem that every future formalism has identical cost geometry.

## Invariance and non-invariance

Preserved through the registered compiler:

- protected I/O traces;
- terminal outcomes;
- final registered values at bounded execution scope.

Not asserted invariant:

- surface code length;
- grammar mutation/search distance;
- raw lower-level step counts without an explicit compiler map.

This deliberately preserves the earlier #875/#896 structural-bias results: semantic preservation does not erase presentation/search bias.
