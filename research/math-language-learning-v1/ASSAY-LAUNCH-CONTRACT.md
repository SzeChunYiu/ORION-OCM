# Fixed unary assay launch contract

This is the fixed execution entry for the integrated unary assay apparatus.
The six [prospective policies](../../docs/plans/unary-adaptive-parent-v2-1/CORE.md)
and the existing [coordinator semantics](ASSAY-COORDINATOR-CONTRACT.md) remain unchanged.
Engineering fixtures contain authored inputs only. No registered master was drawn here.

## Entry and source authority

`unary_assay_launch_profile.prepare` makes a create-only, independently inventoried
project copy, assembled standard library and empty writable work directory.
It consumes the exact reviewed runtime snapshot plus its separate aa-exec mapping correction.
The immutable PREPARED file binds the plan, complete source map, fixed runtime/profile,
external review, limits and measured cold preparation. Preparation does not issue the clock.

`unary_assay_launch.launch` consumes that exact binding. It verifies current/copied sources,
runtime material, interpreter and CPU choice, then writes the original durable STARTED.
The clock value and issuance attempt are retained before writing; post-write faults remain
ISSUANCE_UNCERTAIN. It never treats them as an unstarted run or retries issuance.

The fixed executable CLI accepts only PREPARED path and digest.
Review evidence is externally supplied authority; a JSON flag is not an independent review.
The common source envelope includes the new entry, helpers and ten resource driver files.
Conventional per-operation source checks retain their narrower existing closure.

## Original deadline and containment

The optional `external_started` binding flows through resource_boot, build_profile and
resource_runner. Omitting it preserves the older call interfaces and behavior.
The strict clock reader checks consumed bytes, exact schema, boot, original duration,
immutable file identity and repeated observations. Both expected and unexpected validation
exceptions produce refused observations with their actual causes.

The fixed registered duration is 1,200 seconds from the original STARTED. Each ordinary
child receives the remaining original deadline; no A/B/C or restart creates a new clock.
The existing resource controller monitors that same clock independently of the guest.
Its sampled enforcement may overshoot; final custody can change the terminal while
preserving observed return code, first stop, primary outcome and cleanup.

The namespace uses exactly the pinned Python 3.11.14 with -I -S -B; these flags alone
are not host isolation. Existing bwrap/AppArmor/cgroup enforcement provides the tested boundary.
The bootstrap selects the original lowest allowed CPU and verifies singleton affinity.
Each actual method child records entry/final CPU and thread affinity separately.

Guest sources and Git-independent Python package layout are read-only.
Only the authored writable work area and namespace temporary paths are writable.
No network, user-site packages, cached bytecode, unspecified executable or executable
native-library mapping from writable files is part of the fixed route.
Ordinary read-only data mappings may occur before a dynamic-library load is refused.
Only declared Python, system loader/libraries and policy aa-exec are mounted for execution.
Copied aa-exec is supplied as profile.aa_exec at reserved /policy-aa-exec;
bwrap remains a supervisor executable.

The assembled standard library preserves all 734 bound source files (12,185,437 bytes),
adds the required empty lib-dynload landmark and retains consumed/copy inventory lineage.
Source files/directories are fsynced before their recorded preparation succeeds.
The original 744-file runtime snapshot and mapping correction remain unchanged.

## Outcomes and cost scope

The bootstrap calls the integrated coordinator and unchanged retained analyzer in the
guest, under the same original deadline. It preserves the coordinator call/abort record
and separately measures evaluation recheck work.
BOOTSTRAP_COMPLETED/LAUNCH_COMPLETED describe operational completion, not a positive study.

One authored episode can establish its checked causal apparatus control while the
whole four-episode analysis remains CANNOT_CHECK. PARENT_SUFFICIENT is a valid result.
No transfer, utility advantage, broad mathematical generality or novelty follows from fixtures.

The [phase cost protocol](ASSAY-COST-RECEIPT.md) binds independent PREPARATION/LAUNCH
observations to current sources, commands, raw GNU time output and persisted products.
GNU time phase wall is measured at 0.01-second resolution and checked conservatively
against its enclosing monotonic span. It is not equated to nested high-resolution spans.
Cgroup aggregate CPU, outside own CPU and waited-child CPU remain separate.
Unknown overlap and unobserved helper/observer work keep full lifetime economics
ECONOMICS_CANNOT_CHECK. The supplement never reruns or promotes semantic analysis.
Earliest crossing remains UNAVAILABLE; measured endpoints retain their narrower meaning.
