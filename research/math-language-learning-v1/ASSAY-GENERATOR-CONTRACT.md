# Prospective generator mechanics
This package implements only the data mechanics in the unchanged v2.1 policy:
[GENERATOR](../../docs/plans/unary-adaptive-parent-v2-1/GENERATOR.md) and
[EXECUTION](../../docs/plans/unary-adaptive-parent-v2-1/EXECUTION.md).
There is no scientific CLI, service/controller, containment or analysis implementation here.

## File plan and API
- unary_assay_stream: fixed production master/episodes/splits/counts, exact SHA choices,
  ordered expression pools and single candidate construction with complete field records.
  Generic hash choices use non-study tags in authored tests; candidate tests inject choices.
- unary_assay_identity: syntactic gates and exact alpha/premise-order syntax identity;
  semantic_key calls the released finite-world implementation with the real work accumulator.
- unary_assay_generate: generate_episode with fixed production dimensions, required durable
  sink, caller's original absolute deadline and explicit work/observation dictionaries.
  Its private authored driver accepts injected candidates/small limits for controls only.
- unary_assay_present: final renaming/canonical text and ordered presentation rows;
  pure removal/restoration variants with original-to-derived premise positions.
- Focused tests use authored candidates only, retained external basetemp and source snapshots.

## Retention and authority
Generation is evaluator work. Returned records include private identity keys and are never
passed directly to a worker; later orchestration projects only the permitted ASTs and row IDs.
Every attempted candidate retains input fields and exact task bytes; identity fields remain
null if their gate was not reached. Rejected candidates never enter accepted-key sets.
The sink must durably append before acceptance changes the in-memory state. A sink failure
propagates with reached observations; the later external controller owns independent retention.
The helper cannot qualify a supplied sink's fsync, clock, source or launch authority.
Deadline expiry forbids new draw/identity dispatch. Mandatory failure retention can overrun,
and its actual time is observed rather than represented as work completed before the deadline.
Unfilled slots retain original episode/split/slot IDs; no replacement seed or hidden retry.
The next episode is a separate fixed coordinator decision under the same original deadline.

## Presentation and support scope
Parser output must already equal the validated paired formal digest; unused registry entries
are refused by the unchanged validator. No name restoration or semantic/alpha substitution.
The caller supplies an already authenticated actual OCM B formal cover for used removal.
An explicit None cover means caller-established checked no-use, never missing/failed evidence.
Missing/failed B authority is INTERVENTION_REFERENCE_UNAVAILABLE in the later coordinator.
Pure variant output is a candidate transformation, not evidence that a recipe executed.
Every removal recomputes used names from remaining premises AND query and validates afresh.
Restoration is the original task; its future solve must rematch/check, not resurrect an answer.

Logical counters describe actual key, syntax, semantic and transformation calls/visits.
They are not complete Python/OS/CPU accounting. Sink timing and encompassing return work
are retained separately; row work snapshots precede their own durable append.
All study-master generation is forbidden during engineering qualification.
