# Unary coordinator and retained analysis contract

This is authored execution apparatus around the integrated unary generator and service.
It has no CLI, STARTED issuer, resource-controller authority or scientific launch seal.
The six [v2.1 policies](../../docs/plans/unary-adaptive-parent-v2-1/CORE.md) remain unchanged.
A caller must supply the original absolute deadline; these helpers never create a new one.

## Fixed responsibilities

- `unary_assay_coordinator.run(root, deadline=..., profile=...)` fixes four episodes and
  the existing registered generator. It is callable only through a later qualified entry.
- `run_authored(root, inputs, ...)` is an explicit engineering-only partition seam.
  It never changes or samples the registered master. Tests prohibit registered draws.
- `unary_assay_schedule` implements the fixed A ordering, rotated B/C arms and independent
  evidence-role chains. No request data chooses callbacks, retries, policy or code.
- `unary_assay_phase.Session` dispatches every actual child using both
  `timeout=remaining(original_deadline)` and `deadline=original_deadline`.
  Source/profile preflight and existing child cleanup remain the reviewed launcher’s work.
- `unary_assay_ledger` writes bounded canonical individual records, fsyncs file/directory,
  links their exact digests, and records expected/attempted/completed/unavailable/N/A slots.
  The final coordinator record is create-only; unfinished slots are retained.
- Store copies have independent regular bytes, exact root/descendant modes and complete
  before/after/copied inventories. Symlinks, hardlinks, overlaps and changed inputs refuse.
  Each B/C branch starts from its exact original A. Each role starts a separate A copy;
  each subsequent mutation/solve consumes a copied, retained predecessor state.
- `unary_assay_auth` verifies promised process/input/raw/result/row identities and cold
  replays actual issuer/core stores. Actual receipt/head/use matching and the independent
  semantic checker authenticate accepted results; a JSON CHECKED flag is insufficient.
- `unary_assay_obligations` checks actual required calls and legal N/A cases. N/A role
  reference requires authenticated complete B/C no-use; exact-only mutations remain N/A.
  It binds copy source/target, pre-dispatch inventory and initial use count to original A
  or the immediately preceding role state, independently of each copy's internal equality.
- `unary_assay_recheck` derives B presentations, C support removals and the fixed role
  reference again from retained generation and authenticated OCM B formal use.
- `unary_assay_controls` applies the registered precedence, distinct semantic-row/same-rule
  causal criterion, knockout and role obligations. Formal/text/restoration repeats do not
  enlarge the independent denominator.
- `unary_assay_analysis.analyze(root, expected_sources=..., work=...)` reads retained
  records and rechecks actual state/answers/uses. Its required caller-owned work dictionary
  retains known costs when analysis refuses. It performs no new query solve or mining.

## Data and authority

Learner A receives training/development ASTs and the existing bound selection contract.
Evaluator generation keys and final tasks do not enter those requests.
Both adaptive A processes physically mine/select/persist; all three library identities
must agree before any final arm use. Empty pool/library still runs the fixed fallbacks.

B uses the existing paired text/AST service and one warm EnginePool per fresh process.
Text parsing occurs in that child, with exact paired formal digest validation.
C uses the same authenticated OCM formal cover for all arms; it preserves original indices,
removal-to-derived mappings, duplicate variants and structural N/A restoration calls.
An absent B reference is unavailable, never checked no-use.

Mutation and subsequent solve use different actual processes. Role chains do not inherit
another role’s withdrawal. Exact has no learned-role mutation but executes the two solves.
Knockout remains disabled. Discovery attribution, utility eligibility and correctness are
different records. OCM DEAD warrant liveness and the conventional REVOKED label are kept
distinct from the mutation command’s REVOKED state and from UNKNOWN.

Every retained checked receipt is authenticated even when a later operational row failure
made its row CANNOT_CHECK. Such reached use is reconciled with the journal but earns no
causal success credit. A checked partial observation must match the actual committed USE;
it is not reconstructed from the task or a similar successful row. Every row claiming
CHECKED must contain a structured checked result; missing promised positive data is a
custody failure, while an invalid accepted answer/use is a semantic control failure.

## Failures and scope

Ordinary process refusal does not promise an optional result file. Missing, changed or
malformed artifacts that were promised by the retained custody bindings globally refuse.
Negative observed child exits are classified before reading optional store outputs.
Semantic and environmental failures are both retained; a secondary source failure cannot
overwrite an observed semantic/control violation. Known facts/work survive a later refusal.
Failure causes retain their actual episode and optional call slot. The global strongest
terminal remains separate from each episode's outcome; skipped episodes stay unavailable.
A failed later phase does not relabel an already completed generation as failed generation.

A stops at its first failed operation but the other adaptive A is attempted once.
Incomplete A skips B/C/roles. Incomplete B or C retains other arms’ fixed attempts, then skips
dependent phases. A failed role chain stops that chain only, subject to global controls/time.
No retry, seed replacement, alternate reference or new experiment clock is supplied.

The independent resource/controller and external minimal-failure recorder are later work.
This internal caller cannot claim containment or guarantee retention after a filesystem
failure that prevents its own records. Sampled deadline checks do not imply zero overshoot.

## Accounting

Actual process returns, child CPU, row spans, writes, replay work, copies, source scans and
coordinator/analysis spans remain separate. Repeated cold audit work belongs to evaluation
and is not charged as conventional public-operation overhead.
Retained per-preparation semantic/binding counters are reused without cross-reset deltas.
Logical counters do not measure all Python allocation/hash/serialization costs; encompassing
wall/CPU observations pay for actual work rather than equating sparse data with sparse execution.

The economic helper reports actual complete A+B endpoint comparisons. Frontloaded B overhead
produces only explicitly allocated prefix arithmetic, not observed lifecycle prefixes.
A favorable measured endpoint is OBSERVED_AT_HORIZON; the earliest/intermediate crossing is
UNAVAILABLE. An unfavorable endpoint cannot establish that no earlier crossing occurred.
C/role costs remain separate; knockout’s reused A is a counterfactual allocation and is
never added as another physical acquisition. Absent observations are unavailable.
Complete outer-lifetime closure is not supplied by this tranche, so economics remains
ECONOMICS_CANNOT_CHECK even when endpoint arithmetic is available.

Authored capacity and causal-loop controls are engineering evidence. They do not establish
scientific learning utility, lower total cost, novel cognition, learned grammar, broad
language competence or a corpus-proof result.
