## Execution and counters
One runtime/EnginePool lives for the batch. Each task gets a fresh preparation; expression
mask caches persist only for identical predicate registries within that child.
The exact arm calls existing prepare/complete and the counted independent answer checker.
It does no rule acquisition, adaptive lookup, method restoration, revision or journal writes.
Conventional/OCM routes use their existing qualified proposal, warrant and journal semantics.
Exact implementation/import identities are checked at shared launch/child boundaries.
Conventional public operations retain their own narrow source closure.

Per-row semantic and prepared-binding totals belong to that row's preparation.
They are summed across rows, never subtracted across reset boundaries.
Matching/index/answer-check counters retain separate scopes. Query certificate counters
and the enclosing engine totals overlap and must not be added as independent work.
Each row retains the actual store work before,after and delta, including unknown metrics.
Integer logical store counters and finite measured *_wall_s spans aggregate separately.
An unclassified metric remains in those raw maps and causes explicit aggregation refusal.
Unknown partial matcher counters stay null, with a partial-attempt count.
A parse failure has no prior engine totals attached.
Parser instrumentation records attempts, serialized input bytes and elapsed time; it does
not claim every token operation, validation, Python allocation or hashing operation is counted.

## Failure and cost
The service stops after the first unavailable row and retains original unreached indices.
A checked UNKNOWN or INCONSISTENT mathematical answer remains CHECKED.
A normally returned partial batch is an outcome with CANNOT_CHECK, even when the child
protocol itself completes. PROCESS/child completion is not acceptance of all task answers.
Backend/journal failures retain known reached result/observations before aggregation.
Observation failure marks totals incomplete, preserves unclassified/raw work and stops.
Presented child batches now retain individual rows under fixed rows/00000.json paths.
The compact outcome carries exact path/byte/hash/index/request/PID references; the active
summary points there. Exceptions before an outcome owns rows retain full active observations.
The existing 1 MiB plain-data bound is unchanged; the authored 64-call envelope is checked.

The launcher checks expiry before binding, immediately before Popen and after child wait;
wait time is recomputed after dispatch and postflight expiry also refuses.
Sampled checks can overshoot. They are not the later independent resource supervisor.
No retries, replacement rows or fresh scientific clock are introduced.
Row wall/CPU spans cover input handling and actual call/observation work. Service wall includes
metadata and rows; adaptive persistence is reported separately by the inherited arm.
Launcher outer_wall_s now includes source/profile preflight and child dispatch/wait, but
excludes initial request/profile encoding and final source/readback/PROCESS serialization.
Child process_wall_s excludes final result serialization/fsync. Parent wait covers that child
work. These nested spans must not be summed as independent costs; full controller return
accounting and containment qualification remain later work. -I/-S is not host isolation.
