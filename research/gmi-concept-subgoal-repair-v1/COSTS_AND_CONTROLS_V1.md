# Costs, supplied interfaces and finite falsifiers

All prices are finite nonnegative rationals. The prefix model separately charges
primitive reconstruction, skill invocation, and every delivered symbol. The
executor emits the actual primitive string and verifies exact target equality.
Library derivation/compilation/checking/indexing, installation, retention and
planner computation are setup resources; a fixed installed library is a given
input to the service theorem, not free physical capital.

The finite table-reuse executor has supplied rows and an occurrence-to-row map.
A charged materialize operation returns the complete row; installing it makes
an immutable artifact. Recall checks the stored row, and every arm separately
pays one route operation per request and every output-bit delivery. Prices for
materialize, install and recall are the explicit C,S,U contract. These are
abstract complete operations, not Python instruction timings. Supplied row
acquisition, map validation, policy synthesis and fixed code/controller storage
are reported as setup obligations; no finite scalar claim hides them as free.
The receipt reports row storage and operation counts. Different acquisition or
recognition implementations need their own measured or justified prices.

The minimum over static subsets is checked against an independent event executor
for every subset, including the empty set. Controller decisions cannot read a
future random workload unless that workload model is explicitly supplied.
All enumerated row/price controls use a given finite stream; the two-continuation
counterexample prevents transporting that result to unknown future demand.

Meaningful controls include overlapping skills, an expensive available skill,
zero-cost calls, common output delivery costs, and full complete-parse enumeration.
Concept controls include C<=U, a strict break-even tie, nonpositive class gains,
hard-capacity coupling, identical past with different futures, and distinct
current versus post-update response rows. Raw finite source scripts are run in
private temporary directories only; there are no native VM imports or campaigns.

Exact operation counts are part of the receipt: prefix DP considers n primitive
choices and at most n times library-size match tests. A chosen parse takes at
most n steps. A direct full-response partition compares finite rows; the checker
reports its input size without calling this oracle acquisition free. Complete
parse/subset enumeration is only the bounded independent falsification oracle,
not a proposed scalable development algorithm.
