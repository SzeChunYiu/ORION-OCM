# ORION–OCM source-bound learning integration

This continuation combines the existing ORION-V2 method-learning theory with the
newer local OCM runtime. It is an additive engineering review tool. It preserves
all earlier runtime source, receipts, negative results and reopening decisions.
It does not install a new learner or confer adoption authority.

## What the existing machine can learn

The pre-existing space is a persistent substrate of knowledge, procedures,
evidence, dependencies and revisable organization. New learning changes its
contents and usable methods. The current decomposition remains a hypothesis.
Speech is one interface into this substrate.

The local runtime already learns attributed knowledge and checked arithmetic
methods through conversation. It can search a finite program grammar, learn
recurring fragments from distinct checked solutions, retain a generator across
restart, and refuse reuse when essential support is revoked. Its exact polynomial
checker licenses more than agreement on a handful of examples. These capabilities
remain restricted to the registered primitives, specifications and budgets.

## The concrete integration gap addressed here

`src/ocm/selfmodel/intake.py` is a useful historical record of theory intake, but
its counters and textual references do not verify the absorption contract in
ORION-V2's `ME_FOUNDATION_V1.md`. That contract requires the exact source,
terminal, scope, parent ownership, runtime checks and reopening conditions.

This package adds the first executable packet for the existing method contract:

| Row | V2 obligation | Actual OCM consumer | Check in this packet |
|---|---|---|---|
| M1 | Finite grammar and fair primitive fallback | `learning/methods.py` | Guided search reaches each tested primitive-solvable target within twice its primitive rank |
| M2 | Polynomial identity and sample/proof separation | `learning/methods.py` | Independent numeric/coefficient paths; samples that agree while polynomials differ |
| M3 | Fragment learning and evidence lifecycle | `learning/methods.py` | Existing two-training/two-holdout generator, restart and support revocation |
| M4 | Finite deterministic identification | `science/finite_identification.py` | V2/runtime query and survivor agreement, identification bound, revocation reopening |

`MANIFEST_V1.json` preserves each complete source theorem section, its parent and
scope status, all runtime source/resource files and exact Git blob/SHA-256 pins.
The checker resolves actual Git objects and compares working bytes before and
after execution. Checked source/data are copied into new private trees before
import, preventing existing bytecode caches from substituting for the verified
source. The host interpreter and standard library remain trusted. It does not
infer validity from a well-formed digest string.

The output distinguishes source binding from finite engineering checks and from
independent semantic validation. Host-declared revocation or code drift reopens
eligibility; an unknown revocation cannot silently disappear. A new result is
written exclusively to a new path. Past reports are never regenerated in place.

This is a trusted-host review tool, not a sandbox, authenticated custody service,
proof assistant or theorem parser. The source-to-consumer mapping is registered
by the reviewers. Matching bytes does not establish its semantic correctness;
the explicit finite checks exercise only the named cases. The source's
`PROVED_SCOPE_LIMITED` and `PARENT_SUFFICIENT` labels are preserved as source
claims, not independently conferred by this tool. M5 statistics is not absorbed
by this packet. Its scope and independent validation remain separate.

## Replay

From the OCM checkout, with the matching V2 repository available:

```bash
python research/theory-runtime-integration-v1/test_bindings.py
python research/theory-runtime-integration-v1/check.py --theory ../ORION-V2
```

Set `OCM_THEORY_ROOT` for the binding controls if V2 is stored elsewhere. Pass
`--out NEW_PATH` to retain a fresh replay, or `--revoke-row M3` to exercise a
host-declared invalidation. Exit 0 means the registered engineering checks passed;
exit 1 means rejection/check failure; exit 2 means missing evidence or revalidation.
Neither success nor exit code grants adoption, scientific validation or novelty.

The checks live outside the sealed runtime source inventory and are bound by
their own package inventory in the new replay. This package is not covered by a
historical M0–M12 receipt or an existing CI result. Existing runtime receipt
verification remains a separate required check. No old receipt is extended by
implication to cover this new tool.

## Machine epistemics can evolve, with distinct evidence requirements

The continuing loop is runtime failure or learning experience → precise V2
question/counterexample → scoped revised theory or parent reduction → source-bound
OCM engineering checks → fresh protected comparison → external adoption → monitored
retention, reopening and recovery. Changing representations, acquisition policies,
search or uncertainty procedures can be a legitimate learned improvement. A
candidate's claim that it improved does not establish that improvement or entitle
it to weaken the evaluator. This packet implements only the engineering connection.

## Relationship to the linked Anthropic result

The existing [comparison](../../docs/ANTHROPIC_FORMALIZATION_COMPARISON_V1.md)
remains the design reference. Anthropic describes formalizing an already-known
proof using persistent theorem dependencies and reuse. This supports the relevance
of durable mathematical workspaces; it does not establish OCM novelty or learning
of general epistemic procedures. [Primary research account](https://www.anthropic.com/research/formalizing-fermats-last-theorem).

For mathematics, distinguish local lemma acceptance, complete dependency closure,
whole-proof kernel replay, correspondence to the intended theorem, and independent
novelty review. Then progress from known proof reconstruction to unseen compositions,
learned reuse with revocation, and a prospectively identified open target. The
finite `2r` search-slot bound is not a guarantee of solving unrestricted mathematics.

Finishing this packet does not mean every programme issue is solved. It supplies
a concrete, repeatable integration result while keeping the unfinished obligations
visible. Publication and merge of the newer local OCM work are not completed here.
