## Defects under attack

1. R6 V1 calls iteration over a hand-written finite registry "fair enumeration"; that is finite coverage, not a theorem about dovetailing an enumerable program space.
2. "Prior-free" needs two distinct impossibility statements:
   - any finite-time search of an infinite candidate space visits only finitely many candidates;
   - any concrete language/encoding/scheduler induces generic description/order bias even if it contains no architecture-family ontology.
3. Fair candidate enumeration does not imply fair **successful discovery** when execution/evaluation may diverge or the target property is undecidable.
4. The reusable-abstraction inequality requires a complete case split: with nonnegative one-time cost D, eventual crossover exists only when per-use cost c < baseline cost L.
5. The hidden ID/NOT example establishes a finite evidence-conditioned separator, not a universal theorem that learning must emerge.
6. The V1 reflective Lean theorem is ordinary function composition. It does not prove encoded program self-modification, evaluator self-application, safe adoption, or arbitrary meta-level collapse.
7. Code-as-data, a universal/interpreting evaluator, writable descriptions, and adoption semantics are substrate assumptions that must be disclosed.
8. Search-order / representation changes can preserve eventual expressibility while radically changing finite discovery time.

## Frozen successor distinctions

### Candidate-space fairness
A scheduler over an enumerable candidate language is fair when every candidate index receives execution/evaluation steps unboundedly often (or is eventually completed if its run terminates). A finite registry loop is only a finite calibration.

### Certification boundary
Eventual discovery is claimed only for candidates whose construction is enumerable and whose required success witness is reached by the registered semidecision/verifier route. No decision procedure for arbitrary unbounded semantics is claimed.

### Generic prior boundary
Architecture-family names/macros remain forbidden. Nevertheless instruction set, encoding, enumeration order, scheduler, resource account and verifier are disclosed generic priors.

### Abstraction crossover
For D>=0 and n>=0:
- if c < L, reuse is cheaper exactly when D < n*(L-c);
- if c = L, reuse is never strictly cheaper;
- if c > L, reuse is never strictly cheaper.
Integer threshold statements must respect strict inequality/rounding.

### Reflective boundary
Finite description transformation is first-order only on a substrate that:
- represents program/search/update descriptions as data;
- admits processes that transform those descriptions;
- has a declared evaluator/interpreter/adoption path.
Composition of ordinary functions alone is insufficient evidence.

## Frozen successor targets

- non-tautological finite dovetail scheduler calibration with starvation hostile;
- analytic finite-time impossibility boundary for infinite spaces;
- two encodings/orders with same finite candidate set but different discovery times;
- DELAY1 persistent-state calibration retained with finite scope;
- corrected abstraction crossover/no-crossover cases;
- evidence-conditioned ID/NOT finite calibration retained and narrowed;
- search-order cue finite calibration retained and narrowed;
- encoded-description modifier fixture separating description transformation from function composition;
- explicit prior disclosure ledger;
- explicit UNKNOWN/CANNOT_CHECK outcomes for uncertifiable/unbounded semantics;
- all R6 rows reconciled honestly.
