# G3.3 representation-improvement v1

**Status:** prospectively frozen successor to bounded G2/G3.1 polynomial positives.  
**Owners:** #165 G3.3.  
**Claim ceiling:** representation language selection under a registered exact-identity requirement in one polynomial domain.

## Starting evidence

G2.4 / G3.1 are positive at one bounded exact scope (`#192` / `#193`). Those results used the incumbent coefficient identity `methods.normal_form`. G3.3 asks whether a *different representation* of the same polynomial objects can be learned from valid evidence, save later search/checking work, and still preserve **lifecycle** identity.

## Registered candidate language (before protected outcomes)

Frozen object `REGISTERED_LANGUAGE` in `experiment.py`, fingerprint via `content_hash`. Do not edit it to rescue v1.

| Id | Kind | Key |
|---|---|---|
| `A_COEFFICIENT_TUPLE` | incumbent exact identity | `methods.normal_form` |
| `B_EVAL_VECTOR` | evaluation vector | `(p(0), p(1), p(2))` |
| `C_DEGREE_LEADING` | misleading | `(degree, leading coefficient)` |
| `D_MONOMIAL_SUPPORT` | optional bitmap | nonzero monomial bits `0..63` |

Four-point evaluation `{0,1,2,3}` is injective on the entire length-≤7 grammar generated by `{inc,dec,double,square}`, so it cannot witness “fit train, disagree later” inside this bound. The frozen B point set is therefore **`{0,1,2}`**.

Language-level disagreement (not salt-tuned):

- B is injective on the complete **min-length ≤ 2** grammar (fits short programs that A also indexes exactly).
- B already collides for some min-length 3 programs, e.g. `('dec','square')` vs `('dec','square','square')`.
- Registered witness programs, both length 4:

```text
('dec', 'double', 'double', 'square')
('dec', 'double', 'square', 'square')
```

Same B-vector, different full coefficients. The admitted probe `evaluate-at-x=4` distinguishes them (`144` vs `1296`). The length-3 pair above is distinguished at the same probe (`9` vs `81`).

C already collapses distinct length-1 identities (`inc` vs `double`).

## Frozen partition

Task identity is the exact coefficient tuple. Population: all programs through primitive length 6, first min-length program per identity.

| Stratum | Min length | Salt | N |
|---|---|---|---|
| train | 4 | `orion-ocm-g3-repr-training-v1` | 48 |

Test identities are fixed by mathematics + salt only. Selection does not read them.

## Selection rule (frozen before test)

On the **validation-bound grammar catalog** (all identities of min-length ≤ 5):

1. A candidate is **identity-safe** only if it is injective on that whole catalog. Sample non-collision among the 32 validation tasks is not enough.
2. Among identity-safe candidates, minimize

```text
index_key_computations + validation_exact_identity_checks
```

3. The incumbent wins remaining ties.

If only A is identity-safe, the legal terminals are `PARENT_SUFFICIENT` or, if another candidate were eligible but more expensive, `REPRESENTATION_PRIOR_DOMINATES`. Do not weaken identity to rescue B.

Lookup always exact-verifies `normal_form`. A collision class is scanned; the wrong identity is never returned.

## Distinguishing-operator invalidation / lifecycle

Admitting `EVAL_AT_HELD_OUT_POINT` at `x=4` splits the registered B-class. B is invalidated / reopened. Current-answer equality under the frozen three-point B-key may still hold; those states must **not** remain identified. That is lifecycle equivalence, not current-answer equivalence.

## Persistent causal arms

Ordinary parent: atomic JSON of the selected representation id; reload before test.

OCM: admit the selected representation as a `representation` atom (plus a live probe operator), persist, reconstruct a fresh runtime, then serve. Revoking training evidence must load no representation and fall back to A, matching incumbent search task-by-task.

## Discovery charge

Building A, B, C, D indexes on the validation-bound catalog, plus all validation lookups, is charged even if A is selected.

## Successor v2 (kept beside v1)

If v1 is parent/prior because identity-safe selection keeps A, v2 uses a **different** mechanism: sequential cheap filter then exact identity. Collisions do not disqualify. Selection minimizes validation `exact_identity_checks`. v2 does not overwrite the v1 terminal.
