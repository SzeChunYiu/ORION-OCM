### The ecology, registered before it is built

`F19` (`SIGMA_H19R`). Tokenise `D` into its 104,334 whitespace-separated
tokens. The ecology is the **descriptor closure**: for every token `w`, all
prefixes of `w` of length ≥ 2. The exact total is

```
T = sum(len(w) - 1 for w in words) = 776,142 descriptors
```

A task is a query descriptor. The family is **particle / population
inference**: the quantity that decides the answer for a query is not one
stored item but the **consensus over a population of many weak samples**. The
population attached to a query `q` is its **particle population**: the
distinct one-letter extensions of `q` over the full source,

```
pop(q) = { q + c : q + c is a descriptor of the source }        (the particles)
```

a set whose members each carry only a weak, noisy vote. The stored context of
a query `q` is the part of that population the stored table holds, with each
particle recorded at its stored occurrence count:

```
n(q)    = the number of stored child descriptors of q (|pop(q) ∩ store|)
m(q)    = the stored occurrence count of a particle p in the stored table
votes   = a particle p votes 1 iff its SOURCE occurrence count >= VOTE_K
```

The protected interface is held-out exact prototype-agreement and held-out
exact sign-decision error count, over the exact decisions

```
y(q) = 1 iff the STRICT plurality of pop(q) votes 1        (ties -> 0)
```

evaluated only on the queries whose population has at least two particles
(`|pop(q)| >= 2` — a plurality needs a population to be a plurality over). The
label is the **consensus of the population**: a query is positive exactly when
the population of particles attached to it is split with a strict majority of
its members voting positive. This is the property a particle/population method
computes as the mode of its particle cloud, and the property no single stored
item carries.

Slices, fixed here before any outcome of this package: the descriptor list is
presented under the parents' target-independent Knuth permutation and
partitioned 7:1, giving

```
n_fit = (T * 7) // 8 = 679,124  >= 100k
n_held = T - n_fit = 97,018    >= 20k
```

which clears the R11 real-scale bar (n_fit ≥ 100k / n_held ≥ 20k on a
sha256-bound external REAL source, exact arithmetic, independent oracle).

## 5. Grammar

`G_PP`: a family-blind grammar derived ONLY from the sha-bound bytes of `D`.
Descriptor closure over the token vocabulary (prefixes of length ≥ 2), the
child-extension relation over the closure (the particle population and its
stored part), the stored-context table (membership counts and trie fan-out),
and a charged-cost model over stored-table size and scan cost. No family-level
macro, no hand-encoded plural-vote routine, no reference to any external
implementation. Section R03 asserts the grammar contains no particle-filter or
population-method macro, and R04 recovers the family from the grammar alone.

## 6. Arithmetic

Exact integer arithmetic for every reported quantity: every claimed number is
an exact integer decision count (prototype agreement, sign-decision errors,
null errors, ladder errors, charged-cost units, crossover index). No float
enters any comparison, count, loss, or claim. There is no real-valued fitting
routine whose output requires a rationalisation operator, so this package
carries no arithmetic addendum: the exact-integer form is complete in this
freeze and the slice addenda.

## 7. Budget

Registered node and index budgets for the family-blind search, stated before
any fit, identical for every arm: the descriptor-closure vocabulary index, the
child-extension table, the stored-context table, and the scan window are all
bounded and fixed in the executor. Resource crossover (`R07`) varies these
budgets and asserts the held-out error is monotone non-increasing in them.

## 8. Predictions, frozen before any outcome

Held-out frozen predictions are written to the frozen-prediction record
(`R08`) before the oracle is run, exactly as in
`gmi-833-h-real-scale-classical-v1`: the fit is completed on `n_fit`, the
prediction for each held-out query is emitted to the frozen record, and only
then is the independent oracle (Section R09) run and compared.

## 9. Falsifiers

A held-out exact prototype-agreement below the registered baseline, an exact
sign-decision error count above the registered bound, a null that performs
comparably to the family on the same slice rule, a winning readout whose
structural class is not the population-plurality class, or any cross-scope gate
composition — any one falsifies the claim ceiling.
