## Use the actual donor mechanism

The [REFACTOR source](https://github.com/jinpz/refactor/blob/7327ca79f59929d8f8e43b79daeade3a9a6d5aad/theorem_refactor.py#L165)
recursively matches assertion labels and children. At a pattern `$e` or `$f` leaf,
it accepts the corresponding target subtree as an argument. `additional_check`
checks repeated mandatory-variable expressions. This is different from comparing
all assertion labels in an entire target subtree with a flattened pattern whose
argument leaves have been deleted. [Appendices A.2–A.3](https://arxiv.org/html/2402.17032)
also describe contextual arguments that can themselves be proof subtrees.

At the [bound repository source](BINDINGS.json), `dag.py:Node.steps` includes
all target descendants; `lemma_steps` removes only the pattern's named cut leaves.
`match_getsteps` therefore misses a valid structural instance whenever a boundary
argument expands into additional assertion steps. This is a source-derived scope
gap, not an executed counterexample on any held-out proof. A semantic-label spine
alone is also insufficient: it checks neither typed substitution nor the cut's
boundary obligations. Do not promote the recorded `inundif` spine occurrence to
an actual replacement. Native validity of the original proof is a separate fact.

## Describe the search policy accurately

[Mooney 1989, sections 4–5](https://www.ijcai.org/Proceedings/89-1/Papers/116.pdf)
compares rule-use and search policies; its strict limited-use condition permits a
learned rule only when it solves the current problem without chaining. The paper
also studies relaxed chaining and breadth-first search. It does not prescribe
an arbitrary universal two-decision threshold or a count of at most one learned
label in a completed derivation.

In the bound `search_arms.py`, `mooney_once` is applied after search and records a
boolean. It does not constrain search. Call this an observed-use diagnostic unless
an explicit search-state constraint is implemented and measured. Retain the reported
absence of learned labels in successful derivations within that experiment's scope.

## Keep evaluation information separate

[Kaliszyk and Urban, section 6](https://arxiv.org/html/1310.2797) distinguish
chronological learning from selecting lemmas using the future proof graph. Use
training-only selection for the scientific comparison. An official proof can test
refactoring; giving its intermediate states to a solver tests an oracle-assisted
condition and must be labeled accordingly. Both parents receive the same inputs.
