## Question

After demonstrations are first-class capital

```text
(count, bytes, later-task inequality)
```

does later related-task acquisition consume strictly fewer demonstrations than
reset, or do examples remain unrecouped library capital?

Charged example coordinates:

- **count** — number of demonstration programs stored / consumed;
- **bytes** — canonical JSON of `{fingerprint, program, coefficients}`;
- **later-task inequality** — additional demonstrations consumed while
  acquiring later identities, K_t vs K_0.

State written is persist bytes of that demonstration corpus (ordinary JSON and
an OCM `Channel.DEMONSTRATION` snapshot). Later incremental persist is a
separate later-task coordinate.

Environment interactions, IO/tool calls, and human instructional burden have
no channel (`CANNOT_CHECK`). Training solutions are machine-solved identities,
not human teaching.

## Mechanism change (parent, not salts)

v3 salts, partitions, admitted rewrite `double square`, and later-task search
vectors are **inputs**. Salts are not retuned. Later-task search is **cited,
not rerun**. The G2 9,010,526-attempt tournament is **cited, not rerun**.

The new parent **charges demonstrations** instead of treating them as free
mining residue:

1. Reconstruct the v3 training stratum and serialize each solved identity as a
   demonstration record (count + bytes).
2. Admit those records on `Channel.DEMONSTRATION` (not `PROOF` / `OBSERVATION`
   stand-ins). Persist ordinary JSON and an OCM snapshot; charge those bytes
   as state written.
3. At later-task time, try **exact fingerprint lookup** in the demonstration
   library before search. A hit would consume 0 additional demonstrations. A
   miss does not mint a new teaching example: later acquisition remains search
   (0 additional demonstrations), matching K_0.
4. A **teach-every-later-task** parent (K_0 later examples = `later_n`, or
   rewrite-shortened operator-word encodings as later teaching bytes) is
   measured and **rejected**. K_0 actually searches. Switching the later-task
   channel to teaching would fake-earn H1/002.

If lookup hits and later-task (count, bytes) are both strictly smaller, the
terminal is `H1_EXAMPLES_EARNED_AT_SCOPE`. Otherwise examples stay library
capital.

## Arms

1. `K_0` — primitive search; no demonstration library; later additional
   examples = 0.
2. `DEMO_CHARGED` — training demonstrations stored (count + bytes), admitted on
   `Channel.DEMONSTRATION`, lookup then search; later additional examples = 0
   on a miss.
3. `ORDINARY_JSON` — same corpus as ordinary atomic JSON.
4. `OCM_REVOKED` — demonstration evidence revoked; lookup index empty.
5. `TEACH_LATER` — **rejected**. Would charge K_0 later tasks as `later_n`
   teaching examples or as rewrite-shortened encodings.

Ordinary JSON and OCM demonstration persist receive the identical corpus.
Lookup hits, if any, are therefore `PARENT_SUFFICIENT` versus a persistent
demonstration library. `PARENT_SUFFICIENT` is not programme failure.
